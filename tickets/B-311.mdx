**Brief:** the owner, 2026-11-21:
- "Baton should handle work performed outside of baton gracefully: If it is possible to
  determine that a ticket has been completed in a separate session, baton should update its board
  accordingly … This should be performed by the sync github action code, not the baton server".
- "baton *must* work well in a setup where only a portion of the organization is using baton".
- "the codegen leg is not the only leg which may be completed outside baton".
- On weak evidence, a reconciliation course Baton manages, "configurable / overrideable like
  other courses".

After two adversarial reviews, the owner chose:
- hand acts as separate fact legs;
- mentions filtered, rather than an explicit trailer;
- a hand merge closing only where the course allows.

The case that started it: B-166 was delivered on 2026-11-02 by PRs #158, #159, #163 and #164,
never claimed or closed, and cost a runner's implement leg on 2026-11-21.

## Plan

### Core (`src/core/`)

1. **`arrives` in the course file.** Accept `arrives: {fact, next?}` on a leg in `validateCourse`
   (`src/core/course.ts`: the leg-field allowlist ≈67, and the "`call` and `arrives` are not
   built" refusal ≈376). The leg has exactly one outcome, is never `kind: person`, and its `next`
   names legs of the course. Raise the standard courses' `min_runner_version`, since older
   runners and servers refuse the field.
2. **Applying `std:arrival@1`.** `src/core/questions.ts` ≈195 records every type but
   `std:decision@1` as `arrival-unapplied` today. Build the apply path R-BTN-39 states: the
   policy admits the writer, a fact leg leaves Baton's station, `reached` is its outcome, no
   claim is active, nothing holds the ticket. Defer while claimed or held. Apply once per
   attestation `ref`, queuing `next`, and log `fact-arrival`. A hand arrival counts as a run of
   its leg (R-BTN-63).
3. **`std:evidence@1` and the reconciliation move.** A new numbered migration (append-only) for
   `ticket_evidence` and `reconcile_holds` (§13). Keep each admitted evidence once per `ref`.
   Then apply R-BTN-39's move in the transaction that accepts the evidence, or that ends the
   claim or hold. Enter: record the position, place the ticket at the reconciliation course's
   start, log `reconcile-entered`. Leave at `returned`: mark the evidence weighed, restore the
   recorded position, log `reconcile-returned`. At an end, the ticket is done. An unregistered
   course raises `baton.reconcile-missing` (a new `baton.*` condition, notify).
4. **The claim answer** for a reconciliation leg carries `evidence: [{ref, kind}]`.

### Sync (`src/defaults/`)

5. **Facts.** Extend `PrFact` (`src/defaults/course-pr.ts` ≈15) with the merge commit and the
   title and body (read, never posted). Read PRs for every course's live tickets (R-BTN-96 as
   amended). Note: `BATON_PR_AUTHOR` (`cli.ts` ≈1186) narrows the PR list to one author, which
   defeats this; it must not apply to the evidence read.
6. **Arrivals.** For each ticket whose fact leg leaves Baton's station (`ctx.positions`, which
   `StationCtx` does not carry today: pass it), post an `std:arrival@1` as `sync` with the ref
   and `next` from R-BTN-203's table and the leg. `pr-verdict` ignores `runner_pushers` logins
   and verdicts a claim wrote; on `create-pr` it counts only on a head the gate passed.
   `pr-pushed` comes after the latest changes verdict and changes more than the merged-in base.
   `pr-merged` means every PR of the ticket merged by no `merge` leg.
7. **Evidence.** Post `merged-early` for a `pr-merged` fact no fact leg can take. Post `mention`
   for pushers' merged PRs and the home's first-parent commits in the window (the last accepted
   head to the observation's head) that name the id as a whole word, with every exclusion
   R-BTN-203 lists. Skip both with `reconcile_course: null`.
8. **Settings.** `reconcile_course` (R-BTN-51's list) validated with the other settings.

### Courses

9. **Fact legs** in `create-pr`, `review-pr` and `create-spec` (`src/defaults/courses.ts` and the
   course files), as `docs/standard-courses.mdx`'s table lists, with the course versions raised
   (R-BTN-22).
10. **The standard course `reconcile`** under `src/defaults/courses/reconcile/`:
    - stations `weighing`, `delivered-claimed`, `returned` (no end) and `delivered` (the end);
    - the agent leg `weigh`, read-only, answering `delivered`, `partial` or `unrelated`, and
      checking each named commit or PR is on the default branch as B-257's `delivered` does;
    - the person leg `confirm`;
    - `baton repo init --course reconcile` scaffolds it;
    - add it to `test/unit/standard-courses.test.ts`'s list.

### Checks and tests

11. **`baton ticket check`** reports, never as a finding, each ticket done on the board whose
    file is live.
12. **Tests.**
    - S-BTN-309's cases, in one test file naming the row.
    - A `baton test-course` run for `reconcile`.
    - B-166's shape as a fixture: four merged PRs naming it in titles, none in `prs:`, so it gets
      `mention` evidence, enters `reconcile`, and with `unrelated` returns to `filed`.
    - A `create-pr` ticket at `pr-open` whose PR is merged by hand gets `merged-early`, not
      closure.
    - The same ticket at `reviewed`, with a person's approval and then a hand merge, ends at
      `merged`.

### Trust

New inputs, each read by the sync and judged by Baton:
- **The forge's PR states, merges, verdicts and pushes** move a ticket only through a fact leg
  its own course file places, and only under a policy whose `attestations` admit `sync` for
  `std:arrival@1` (`cooperative` does, `protected` does not, R-BTN-188). Runners' verdicts never
  count.
- **PR titles and bodies, and commit messages**, are read as text to find an id and never
  posted. A `mention` is only evidence: its worst effect is a reconciliation (a `weigh` run and
  a person's `confirm`), bounded by the exclusions and the three-id cap.
- **`std:evidence@1`** is admitted for `sync` under both presets.
- **`reconcile_course`** is the repository's own file.

Closing on evidence takes a person's `confirm`, unless the repository's own course says otherwise.

### Invariants

- **The sync finds, the core places (R-BTN-35, R-BTN-39, R-BTN-50).** The sync never sets a
  position. Baton applies arrivals along edges and makes the reconciliation move itself,
  restoring only a position it recorded.
- **A claimed or held ticket is untouched.** Arrivals and moves wait for the claim or hold to
  end; archive and `status: done` close as before.
- **A partial reading is never posted (R-BTN-96).**
- **Filter fields only (R-BTN-33).** Evidence is a `ref` and a `kind`; no title or message is
  stored.
- **Migrations are append-only.**
