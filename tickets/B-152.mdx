This ticket moves a credential, so the move itself is an operator's: an agent writes the code and
the runbook, a human moves the key. The brief above quotes the owner in an unsigned commit, which
is a claim until Baton marks briefs (B-127): before the build starts, the owner confirms the move.

### What to build

1. **The kind.** `dispatch` entries queued in the transaction that records a want, an unblocked
   trigger or a mirror's lag, where the repository has a dispatch target; coalesced to one per
   repository per 30 seconds plus a trailing one (the alarm), a newer entry replacing one not yet
   claimed per `(repository, workflow)`; confirmed by a board post (a mirror's acknowledgement)
   observed after it; `baton.outbox-late` 2 minutes after queueing.
2. **The courier.** `baton owner courier add <key> --delivers dispatch`; `baton courier start`
   with `--github-app-key` and the forge tokens, minting installation tokens on its own host and
   dispatching only a signed entry's workflow; a `std:effect@1` on delivery (R-BTN-191).
3. **The ring.** `GET /v1/courier/push`, authenticated as the courier's key, rung `outbox` when an
   entry of a class it delivers is queued.
4. **What leaves the Worker.** `BATON_GITHUB_APP_KEY`, the GitLab trigger tokens and the Gitea bot
   tokens; `BATON_FORGE_SECRETS` keeps only webhook secrets. The Worker makes no outbound call
   that acts. `baton.forge-secret-missing` is raised for a dispatch target with no dispatch
   courier.
5. **The runbook** for moving the key, and R3-1208's checklist brought in line.

### Tests
