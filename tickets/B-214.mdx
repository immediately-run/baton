B-191, answered by the owner on 2026-11-09, makes them read-only. The mockup's Instance view (`root.txt`: "anthropic
· 5h window — 62% used · resets 19:40 UTC — ● OK"; "real-iphone — No device attached to any
alive worker — ▲ Unavailable") is `/instances`; its Limits → Probes line is on `/resources`.

### What to build

1. **`/repositories`** (`src/dashboard/screens/tenant/Registry.tsx`): from `GET
   /v1/admin/repositories?retired=1` as B-202 extends it — a `<table>` with id, forge path
   (linking the forge by `web_base`), forge, default branch, weight, `tiers`, head (sha, age),
   mode, courses, `sync_keys` and `ci_identity`, retired rows marked by `retired_at`,
   `seed_owners` marked and explained (R-BTN-58); what the root `/` does not show (the full row,
   retired repositories). The commands `baton admin repo add
   <forge path> --owner-key <pub> […]`, `… repo set <id> […]`, `… repo retire <id>` and `… repo
   resync <repository> --force [<sha>]` as text; no control (Decision 1a; the session's forced
   resync lives on each repository's Sync screen, B-201).
2. **`/instances`**: the mockup's table from `admin.instance.list` — instance, resource, what it
   serves, state mark and word (available, unavailable until), the newest reading's summary
   (its `detail` through `View` where the resource's `detail_schema` carries a view, else the
   first fields as text), source and age, `stale` marked — each row expanding to every reading
   by source with `detail` pretty-printed. `baton admin reading set <instance> […]` as text.
3. **`/resources`**: each resource with scope, `detail_schema` pretty-printed and its instances
   linking `/instances`; the probe keys as a `<table>` (fingerprint, label, added at). `baton
   admin resource add <name> […]`, `… instance add <name> […]`, `… probe add --key <pub> --label
   <l>` as text.
4. **`/capacities`**: a `<table>` of capability, capacity, seats held, the holding claims
   (ticket and runner linking their pages). `baton admin capacity set <capability> <n>` as text.
5. **Phone.** Tables collapse to cards at 375 px.

### What not to do

- No control (Decision 1a); no owner-scoped data; no reading or state computed in the client.
- No key or secret management: `admin keys set` and the GitHub App flows stay the CLI's.

### Trust

- **Every value** is the reads' text through `Text` or `View`; answered to an administrator's
  session only; the forge link from `web_base`. Nothing is written.

### Invariants

- **Administrators only** (R-BTN-57, R-BTN-155); **read-only** (§11.4, Decision 1a).
- **Readings are statements** (R-BTN-76); **text, never markup** (§12.3).

### Tests

Under `test/ui/` with fixtures: the registry marks `seed_owners` and retired rows and draws no
control; `/instances` marks a stale reading and expands by source; `/resources` lists the probe;
`/capacities` links the holders; an owner's session has no tenant entry (B-206's router test
extended); every command line matches R-BTN-127's tree; a hostile instance name is text.

### Exit criteria

- [ ] The four screens built, read-only, usable on a local Baton for an administrator's session.
- [ ] The tests pass; `npm test`, `npm run typecheck`, `npm run check:wiki` and
      `npm run check:tickets` are green.
