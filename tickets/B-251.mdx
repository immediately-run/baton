**Brief:** `baton request` files a request ticket as one commit pushed to `main` through its own `transact` (`src/defaults/request.ts`), which reads neither `TICKET_TRAILERS` nor `TICKET_REQUIRE_TRAILERS=1` — after B-16 (#249), the one ticket-filing commit left un-attributable. Found by both blind reviewers of #249's round 1 (a should-fix there, out of B-16's named scope).
**Spec:** none; repository tooling (B-16's precedent).
**Depends on:** none.
**Used by:** none.

### What to build

1. The request's filing commit (the `transact` in `src/defaults/request.ts`, `fileRequest`) appends the value of `TICKET_TRAILERS`, after a blank line, to its commit message — reusing `ticketCommitMessage` from `src/defaults/tickets.ts` (B-16), never a second builder.
2. With `TICKET_REQUIRE_TRAILERS=1`, the command refuses when `TICKET_TRAILERS` is empty, before anything is pushed.
3. The README's documentation of the two variables names `baton request` among the commands that read them.

### Trust

No new input: `TICKET_TRAILERS` and `TICKET_REQUIRE_TRAILERS` are B-16's inputs, read where the request's filing commit is built; no field, file, commit trailer or request is added.

### Invariants

- None by id — repository tooling with no spec rule of its own (B-16's precedent, **Spec:** none).
- Kept anyway: the refusal fires before the push, so nothing un-attributable lands; and the request's message and output shape are otherwise unchanged.

### Tests

- The filing commit through `fileRequest`: with trailers appended after a blank line, without them, and refused under `TICKET_REQUIRE_TRAILERS=1` with nothing pushed — mirroring `test/unit/tickets-commands.test.ts`'s B-16 cases.

### Exit criteria

- [ ] `baton request`'s filing commit carries the trailers it was given, and refuses an empty one under `TICKET_REQUIRE_TRAILERS=1` before pushing
- [ ] merged
