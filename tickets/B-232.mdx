**Brief:** see the description.

**Where.** `src/runner/runner.ts`: `verifyBySource` returns `the executor could not start the
ticket source's session (…)` as a version-check reason; the caller treats every reason as a moved
ticket (`released:stale-board`). Its other failure paths (a wrapper call that writes no outcome,
a session that dies) may have the same shape.

**Spec:** §4.5 (R-BTN-74, B-183's version check), §6.5's release reasons, R-BTN-34.

### What to build

- Tell the version check's verdicts (the ticket moved, or did not) from its failures to run (the
  executor or the source could not answer). A failure ends the claim `cannot-finish:transient`
  with the executor's error, never `released:stale-board`.
- After a few consecutive executor failures (say 3), the runner stops claiming and retries the
  executor on a backoff, logging each attempt, and resumes claiming when a session starts — so a
  broken executor costs no claims beyond the first few.
- The same for a leg session the executor cannot start, if it is not already so.

**Done when** a runner whose executor refuses every session ends at most a few claims, each as
`cannot-finish:transient` naming the executor's error, and then waits without claiming until a
session starts.
