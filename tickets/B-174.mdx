**Spec:** R-BTN-131 (the request command, in the standard courses' table), R-BTN-180 (*Who may
land*, the request bullet), R-BTN-74 (a refused push reported in git's own words), R-BTN-188
(`refs.default_branch`, `refs.other`), R-BTN-92 (forges), S-BTN-175. Source:
`docs/review/security-review-2026-11-02.mdx`, finding C2. PR #165 tried a one-sentence fix, and its
review round one found it underspecified (branch, credential, `git` forge, refusal kinds; a
`request/<ID>` branch outside `branch_pattern` is refused again under `protected`'s
`refs.other`), so the fix moved here.

### Decided (the owner)

2026-11-02, choosing among this ticket's options: "I accept your recommendations" — option (a),
decide by the forge's answer and ask Baton nothing. The spec states it (R-BTN-131's request
command, R-BTN-180's bullet), PR `claude/baton-spec-review-2fwiga`.

### What to build

1. In each forge adapter (R-BTN-92), a matcher that recognises the forge's protected-branch
   refusal of a push (GitHub's and GitLab's hook-declined messages; Gitea's), and a call that
   opens a PR with the caller's forge credential.
2. `baton ticket request`: on that refusal, push the same commit to the course's
   `branch_pattern` with the id as `{ticket}` and `request` for the rest, open a PR from it,
   print the URL; on a `git` forge, or with no forge credential, print the branch and exit
   non-zero; any other refusal reported in git's own words, nothing opened; a moved head
   retried as now.
3. The three S-BTN-175 cases §15 now states: a protected default branch, a `git` forge, a
   refusal that is not protection.
