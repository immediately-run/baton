**Brief:** the owner, 2026-11-28 (in a Claude Code session): "The plan is to drop git forge sync which become unnecessary once we have the git proxy in place. This should be included in 0.1", and, asked who ships the proxy, "Baton ships it". The design is B-401's; the plan is [Baton 0.1](../docs/plans/baton-0-1.mdx), phase B.

**Spec:** the proxy's subsection of [BATON_SPEC §3](../spec/BATON_SPEC/03-repositories-and-forges.md), as B-401 writes it; [R-BTN-144](../spec/BATON_SPEC/08-runners.md#sec-8-4) (a leg's credentials); [R-BTN-107](../spec/BATON_SPEC/08-runners.md#sec-8-3) (the executor and its brief).

**Depends on:** B-401.

**Related:** B-131 (per-claim forge credentials: this ticket builds them), B-265 (the executor brief carries the claim's scope), B-269 (REST, never GraphQL), FLDH-60 and FLDH-61 (Fieldhouse's forge gate, which rebuilds on this).

### What to build

1. **The service.** `baton proxy` (in the published package): one process per host, holding the deployment's forge credential, serving git smart HTTP and the forge's REST API to legs on the host. It refuses GraphQL, any repository outside a grant, and any ref outside a grant's branches; pushes to the default branch are refused for leg grants.
2. **Grants per claim.** The runner, at a claim's start, asks the proxy for a token scoped to the claim's repositories (the home and its `repos:` with reach, R-BTN-140) and the ticket's branches (`branch_pattern`), valid for the claim's lease and revoked at its end. The executor hands the leg only that token and the proxy's URL; `GH_TOKEN` and every other forge credential leave the leg's and the runner's environment (R-BTN-144).
3. **What it remembers.** Every branch head it relays under a grant, with the claim and ticket, kept as long as the ticket is live: B-403 reads it.
4. **The standard courses' stubs** reach the forge through the proxy URL the executor gives them; the builtin executor and Fieldhouse's E2B executor both pass it.
5. **`baton doctor`'s proxy check** where B-370 has landed: the proxy answers, holds a credential the forge accepts, and refuses a request outside a grant.

### Exit criteria

- A test drives a leg through the proxy against a fake forge (B-343's): its push to its ticket's branch succeeds, a push to the default branch or another ticket's branch is refused, and its token stops working when the claim ends.
- No forge credential is in a leg's environment under the builtin executor (a test reads it).
- `npm test` and `npm run typecheck` green; each behaviour named in a scenario.

### Trust

The proxy is a new holder of the most powerful credential in a deployment; it runs no repository code, and every request it serves is checked against a grant Baton's record backs. A compromised leg reaches only its own claim's branches.

### Invariants

- No leg and no runner holds a forge credential.
- A grant never outlives its claim.
