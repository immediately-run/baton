**Brief:** the owner, 2026-10-27: "I'm debating whether it's a mistake to allow unprivileged runner
virtual machine instances write access to the home repository. Maybe they should only be able to
read tickets and propose changes to tickets if necessary in PRs." After discussion the owner
chose this option, (a) in the security model, over a provenance quarantine as a bridge: "I would
go straight to a instead of doing c first", with ticket PRs merged only on an owner's approval so
that (a) keeps what the quarantine would have given.

**Spec:** R-BTN-66 (pushers are legitimate), R-BTN-105 (a sync reads the default branch's
commit), R-BTN-139 (PRs and words that count), R-BTN-74 (verdicts), R-BTN-131 (the standard
courses' `merge` leg); `docs/security-model.mdx` (reaches 1, 3, 5 and 6; hardening options 8 and
the home-write section).
**Depends on:** R3-1266 (Baton claims its own tickets, so no claim or status write needs a push
to main) and B-128 (the reviewer identity that merges code).

### Why

Every VM shares `immediately-run-worker`, which has `write` on each home's default branch. A
compromised runner can therefore change what every runner executes (`.baton/`), how work is
scheduled (goals, `EXPEDITE`), the record, and the tickets other agents read, including those the
owner's privileged sessions read (reach 3, rated critical). The line that matters is not home
versus code repository but the default branch versus agent branches: Baton's sync reads only the
default branch, so a change that has not reached it is not claimable and not in force.

### What to build

1. **The worker writes only agent refs.** On every home and output repository, a branch ruleset
   lets the worker identities (implementer and reviewer, B-128) create and update only refs
   matching the courses' `branch_pattern` (`claude/{ticket}-*` today, or a dedicated `agent/**`),
   and never the default branch. No bypass for either identity.
2. **Main changes only by merge.** The default branch requires a pull request:
   - code is merged by the reviewer identity after an approval of the latest push by someone
     other than the pusher (B-128);
   - **`tickets/**` and goal files are merged only on an owner's approval**: CODEOWNERS naming
     the owners, and the ruleset requiring code-owner review. A model never approves a ticket's
     text, since its danger is its meaning.
   - `.baton/**`, `.github/workflows/**` and agent configuration (`.claude/**` (hooks, settings, skills, memory), every `CLAUDE.md` and `AGENTS.md`, and plugin manifests) need an owner's approval too (security model A or B; B-127 signs what A cannot
     cover on public repositories). Agent configuration is what privileged sessions execute
     (OWASP ASI05).
   - **Everything a privileged session reads as authority** needs an owner's approval too
     (the owner, 2026-10-27; security model, *Authority and data*): the context corpus
     (`docs/context/**`, docs' `content/context/**`, Fieldhouse's `docs/context/**`),
     `lessons.mdx`, the owner tier of agent memory wherever it lives, and the specs' decision
     sections. Content never crosses upward without a gate.
   - **The fleet tier of memory is the exception that proves the rule.** Runners write it
     without approval, at a path outside every owner-gated one (proposed: `hq`'s
     `memory/fleet/**`), and no privileged session's configuration loads it; a lesson reaches
     the owner tier only as a PR the owner merges.
3. **Agent-filed tickets are PRs.** `bug-report`, `draft-ticket` and `epic` (children) open a PR
   adding the ticket instead of pushing it; the ticket becomes claimable when an owner merges it.
   **Decide:** whether a deterministic check may auto-merge a ticket PR that changes only status
   fields in frontmatter and no body or brief (proposed: yes, once the owner queue shows the need).
4. **No course writes main directly.** Marker courses that commit their record to the ticket file
   on main (B-100) move their record to Baton (B-120's direction) or to the PR branch (B-101);
   `baton tickets` commands (B-112) write through Baton, not git, once R3-1266 lands.
5. **The interim is a decision** (recorded in the security model): until this lands, VM runners
   hold `write` on main and the exposure is accepted.

**After the adversarial review** (2026-10-27, `docs/security-model.mdx` *Review*):

- **Tags too** (finding 15): a tag ruleset forbids the worker identities to create or update
  tags, and any `on: push: tags` workflow sits behind it.
- **"Not in force" means Baton's board** (finding 8): a review or fix leg that checks out the PR
  branch loads that branch's agent configuration, nested `CLAUDE.md` and test code, so the PR
  branch is in force there (B-128 item 6, B-132).
- **This contradicts Fieldhouse's Axiom 4** ("never by an approval queue") and Axiom 1 for
  tickets (finding 8). The implementing PR amends the axioms in FIELDHOUSE_SPEC first, citing the
  owner's choice of option (a), and estimates the owner queue (agent-filed tickets, memory
  promotions, corpus changes) against Axiom 0.
- **"Owner's approval" means the human-only identity** (B-136), not the account the owner's agent
  sessions use.

**After the merge-runner design** (the owner, 2026-10-28; B-140):

- **This ticket is now B-140's three rules**: runners propose, the merge runner lands; no runner
  change to Baton's state lands without a human; tickets are proposals. The default branch accepts
  only the merge runner's identity (a GitHub branch ruleset, public or private; GitLab and Gitea
  protected branches; a `pre-receive` hook on plain git). Protected paths are enforced by the
  merge runner's own path check, the same on every forge, so push rulesets and CODEOWNERS become
  optional extra layers. What stays here: agent-filed tickets as PRs, no course committing to the
  default branch, the tag ruleset, the owner-gated authority paths, and the Axiom 4 amendment.

### Tests

- A drill on a scratch repository, scripted: the worker's push to main is refused; its push to an
  agent ref succeeds; a ticket PR approved by the reviewer identity cannot merge, and one approved
  by an owner can; a workflow change from the worker cannot merge without an owner; nor can a
  change to the context corpus, `lessons.mdx` or owner-tier memory, while a fleet-tier memory
  write lands without approval.
- A scenario (the next free S-BTN number): a ticket added on an agent branch never appears on the
  board; merged, it does.

### Exit criteria

- [ ] the rulesets applied to `fieldhouse`, `docs` and `baton`, each recorded with its JSON in
      the repository
- [ ] the drill script passes
- [ ] the standard courses file tickets by PR; no course commits to a default branch
