**Brief:** continues B-3 (split 2026-10-20).
**Spec:** `spec/BATON_SPEC.md` §5.5 R-BTN-112 (declarative views, Baton's renderers), R-BTN-110 (each `std:` schema with a view); §12.6 R-BTN-157 (a `link_hosts` link is https with no userinfo); §3.1 R-BTN-92's link rule and §12.3 (untrusted text); §15 S-BTN-76; G-BTN-100.
**Depends on:** B-3 (`x-baton-view` is accepted and bounded in a schema; the `std:` library).

### Requires

- none.

### What to build

1. **Renderers** in the shared library: `plain` (the CLI, a `forge-check` summary and a handler course's text), `html` (a handler course's mail: every value escaped, inline styles only, no script, image or remote resource) and `ui` (the dashboard, through `textContent`). A view's `title`/`summary` templates replace `{<JSON Pointer>}` only; `fields` with `as` in `text`, `number`, `time`, `gauge`, `status`, `table` (≤ 50 rows) and `link` — shown as a link only under R-BTN-92's link rule for the ticket's repositories or the instance's `link_hosts` (an administrator's setting, default empty).
2. **Fallback**: a value's own view, else the nearest up its base chain, else a generic two-level rendering, truncated.
3. **The `std:` library's views**, and core events rendered by core's own templates with one slot for the course's view.
4. Courses never ship rendering code.

### Tests

- S-BTN-76 (hostile values in templates and table cells, a link to a host neither in `link_hosts` nor `web_base`) through all three renderers.
