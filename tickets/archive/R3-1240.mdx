### Requires

- none — the harness runs administrator and owner keys locally.

### Why

Setting up a Baton must take a deploy, one secret and a few commands (owner, 2026-10-14), and
every limit agents must not change lives in Baton's SQLite, set by owner or administrator
keys. Tier: critical — who may grant what.

### What to build

1. Administrators from `BATON_ADMIN_KEYS` (`--admin-keys` locally): register, change and
   retire repositories (`weight`, `tiers`, `cut_over`), probes, `human-operator` grants;
   revoke any key; one-time login links and `__Host-` sessions that end when the key leaves
   the secret.
2. Owners per repository: grants with expanded capabilities and `max_tier`, unique names
   (`conflict`), owners (never the last); owner bars (`course` — a course id or `*` —, `legs` only
   under a named course, `applies`, times, `release_holders`, `reason`) and their lifting;
   required bars (`{course | *, leg | *, except?, tag_prefix}`, a named `leg` only under a
   named course, following `renamed_from`; a course file lacking a named `leg` is held, a
   missing `except` entry dropped), `retry`,
   `transcript_repos`.
3. One role per key: a key in two roles is refused.
4. `baton admin …` and `baton owner …` (`grant`, `bar`, `bar lift`, `settings`) on one set
   of validated functions in `src/core/admin.ts`.

### Architecture — the decisions, named

- **A bar change is an `admin` event and dispatches the repository's sync**; the alarm
  releases tagged holders at a bar's start when it says so.
- **Do not**: read any of these settings from a board post; let an owner grant
  `human-operator`; offer a management path but the CLI (the dashboard shows them read-only).

### Tests

- Integration: S-BTN-32, S-BTN-39 (the settings half), both hosts.
- S-BTN-30's administrator clause (an admin request signed by a key not in `BATON_ADMIN_KEYS`
  is refused `unauthenticated`): the `it.todo` R3-1239 left in baton's
  `test/integration/S-BTN-30.signed-requests.test.ts`; admin and owner requests go through the
  same `verifyRequest` and nonce cache (R3-1239, baton#24). Granted keys carry `created_by`
  `owner:`/`admin:`, which the interim `BATON_KEYS` seed (`created_by = 'seed'`) never revokes.
- `test/unit/admin.test.ts`: every refusal of R-BTN-57/58 by code; a bar on `chore` never
  bars a `roadmap-pr` leg, a `*` bar bars both.
