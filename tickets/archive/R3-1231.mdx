### Requires

- none — the integration harness runs two fixture repositories with fake OIDC tokens.

### Why

Baton must serve several repositories, each with its own board, courses and settings, and
order what each sync *saw* in PRs, which no commit orders (R-BTN-62). Today there is one board
and one head. Tier: critical — the compare-and-set and the sync principal change.

### What to build

1. Migration: `repositories` (with `weight`, `tiers`, `retry`, `required_bars`,
   `transcript_repos`, `cutover_at`), `courses` (with `course_json`, `min_worker_version`,
   `branch_pattern`, `report_horizon_h`), `worker_courses`, per-repository `board_head`
   (`observation`, `last_handed_out`), `held_snapshots` keyed by repository with its
   observation, `events.repository_id`; qualified ticket ids. *(`closed_tickets` moved to
   R3-1232, 2026-10-15.)*
2. `POST /v1/sync/observation`: the head, the next observation number and the owner bars in
   force; `POST /v1/sync/board` accepted or refused whole: new head, refresh, held force post,
   `stale-observation`. *(§7.1's normative tickets schema and the held post's station refresh
   moved to R3-1232, 2026-10-15: they need the stations it ingests.)*
3. Course-file validation (R-BTN-69) on every registry post: a failing file keeps the
   previous and is listed under **Needs you**.
4. OIDC bound per repository (R-BTN-15); rule 9 against `min_worker_version`, at claims only.
5. *(Added 2026-10-15.)* Tiers per repository (R-BTN-66, rule 5) and `GET /v1/runner/branch-holder`
   (§6.3, R-BTN-51).

### Architecture — the decisions, named

- **One function validates a course file**, `validateCourse(json)` in `src/core/course.ts`,
  returning every violation (unreachable station, no route to an end, a cycle without
  `max_runs`, an unknown name); the sync's test kit (R3-1248) imports the same module.
- **The counter is per repository and strictly increasing**: Baton records the last number
  handed out; a post qualifies only when its number is greater than the last accepted one.
- **No reference repository** and no fleet data; tiers are a repository setting; ticket
  tiers arrive by name and are stored as positions.
- **Do not**: read a course file's names for meaning; accept part of a post; let a sync token
  of one repository read or write another's board or events.

### Tests

- `test/unit/course.test.ts`: `validateCourse` over the real `roadmap-pr` file (from the
