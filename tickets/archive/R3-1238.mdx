### Requires

- none — both hosts run under the repository's own test runner; no account or deploy.

### Why

The owner wants Baton to run both as a Cloudflare Worker and locally (2026-10-14). Its
coupling is narrow — `src/baton.ts:5` is the only `cloudflare:workers` import, and
`Claims`, `Cutover`, `Mirror` and `WorkerApi` receive `ctx.storage` and use only
`sql.exec`, `.toArray()` and `transactionSync` — so the split is cheap now and expensive
after R3-1231, R3-1232 and R3-1235 add most of the remaining server code. Tier: judgement —
module structure, one repo, no behaviour change.

### What to build

1. `src/core/`: everything that decides — claims, cutover, mirror, worker API, sync
   handling, matching — taking `Store`, `Scheduler`, `Clock`, `AdminKeys`, `HookRunner` and
   `Dispatch` in a constructor; `src/core/ports.ts` declares the interfaces.
2. `src/cloudflare/`: the `Baton` Durable Object and `worker.ts`, wiring `ctx.storage`, the
   alarm and `fetch` into the ports.
3. `src/local/`: `node:sqlite` `DatabaseSync` as `Store`, a single promise queue so requests
   run one at a time, released only while a request awaits its signature check or a hook call and
   serialising the alarm too (BATON_SPEC §3, R-BTN-55), a 60-second timer as `Scheduler`, `node:http` serving the same routes;
   `AdminKeys` reads `--admin-keys <file>` (R-BTN-57); the local `HookRunner` (a `workerd`
   child process) is R3-1236's — until it lands, tests inject a fake runner.
4. `npm run start:local -- --db <path> --port <n>` and a `README.md` section.
5. The Vitest config runs `test/integration/` as two projects, `cloudflare` and `local`.

### Architecture — the decisions, named

- **Synchronous storage on both hosts**: `Store.exec` and `Store.transaction` are
  synchronous, as the Durable Object's are; `node:sqlite` matches, so the atomicity the spec
  relies on (§3: one request at a time, transactional writes) holds without new locks.
- **The queue is the local host's only concurrency control**: every request, alarm tick and
  dispatch goes through it, as the Durable Object serialises them.
- **A check, not a convention**: `test/unit/boundary-host.test.ts` fails if any file under
  `src/core/` imports `cloudflare:workers` or reads `ctx`.
- **Migrations are shared**: `src/migrations/` runs through `Store` on both hosts.
- **Do not**: change any rule, response or refusal; add a second storage engine; let the local
  host read `.dev.vars` secrets; run a hook outside a sandbox (R-BTN-59).
