### Requires

- none — the test kit runs the local host against a checkout.

### Why

A minimal core exists so projects — and agents — can change their courses without changing
Baton (owner, 2026-10-14). That needs claims to survive a course change, a way to test a
change before it merges, and a way to see whether it helped. Tier: judgement.

### What to build

1. Course changes under claims: `renamed_from` carries a claim's station or leg over; a claim
   whose station or leg is gone gets `station: unknown` and ends `released:course-changed`.
2. `baton test-course <root> <course>`: starts a local Baton, posts the proposed `.baton/`,
   replays every live ticket, fails when one's path shrinks without its evidence changing,
   when a station or leg is removed without raising `min_worker_version`, or when legs and
   `legs/` scripts do not pair one to one; runs the generic scenarios against the course.
3. `GET /v1/repositories/{repository}/stats` for keys granted on the repository.
4. The `Min-Worker-Version` trailer check in docs' CI (`check-baton.mjs`).

### Architecture — the decisions, named

- **The test kit is the local host**, not a second implementation; it imports R3-1231's
  `validateCourse`.
- **Stats are aggregates and ids**: no profile, report or advice text.
- **Do not**: let a course change release a claim before it reaches a boundary; read stats
  for a repository the key has no grant on.
