### Requires

- none — the Worker runs locally under Cloudflare's Vitest pool; deploying it is R3-1207
  and R3-1208.

### Why

Step 1 of the rollout (§13) is a read-only view: the board, the providers and the ready queue
on a dashboard, with no workers and no claims. It is also where the service, its schema and
the integration harness every later item extends are born. Tier: critical — it verifies
OIDC and Access tokens.

### What to build

1. `infra/baton/`: its own `package.json` (wrangler, `@cloudflare/vitest-plugin` — the
   renamed `@cloudflare/vitest-pool-workers`, which is deprecated —
   vitest, typescript), `wrangler.toml` (route `workitems.immediately.run/*`, Durable Object
   class `Baton`, SQLite storage), `src/worker.ts`, `src/baton.ts` (the Durable Object).
2. Migrations `src/migrations/0001_init.sql` with every §4 table, applied in order before the
   object serves.
3. `GET /v1/sync/head`, `POST /v1/sync/board` (§7.1 CAS), `GET /v1/ui/state`.
4. The dashboard at `/`: Ready and Providers views (§14), polling `/v1/ui/state` every 10 s.
5. The integration harness `infra/baton/test/integration/` (R-BTN-29) and S-BTN-13.
6. Root `package.json`: `"test:baton": "npm --prefix infra/baton test"`.

### Architecture — the decisions, named

- **One fixed object.** `worker.ts` authenticates, then forwards to
  `env.BATON.idFromName('baton')`; all SQL lives in `baton.ts`. The object takes a clock in
  its constructor (`this.now`), production `() => Date.now()`, tests a fake (R-BTN-32).
- **Sync auth (R-BTN-15).** Verify the GitHub OIDC JWT with `jose` against
  `https://token.actions.githubusercontent.com/.well-known/jwks`; require `aud`
  `workitems.immediately.run`, `repository` `immediately-run/docs`, `ref`
  `refs/heads/main`, `job_workflow_ref` `immediately-run/docs/.github/workflows/baton-sync.yml@refs/heads/main`
  for `/v1/sync/board` and `/v1/sync/head`. The JWKS URL and the accepted workflow refs are
  `wrangler.toml` vars; the test environment overrides them with a local key (§13a).
- **Owner auth (R-BTN-16).** Verify `Cf-Access-Jwt-Assertion` against the team's certs
  (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD` vars), allow only `OWNER_EMAILS`; every response
  carries the R-BTN-16 headers; state-changing `/v1/ui/*` needs JSON and a same `Origin`
  (none exist yet but the middleware ships now).
- **Filter fields only, as tables (R-BTN-33/35).** The accepted snapshot is materialized into
  `work_items` and `work_item_requires` (§4): upsert rows whose `row_hash` changed, delete
  rows for items no longer live; no JSON copy of the board is stored (`board_snapshots` keeps
  sha, parent and counts only). The table is a cache of git and never edited otherwise. The
  payload and the table carry no body, note or exit-criteria text; the Ready view links each
  title to `https://github.com/immediately-run/docs/blob/main/<path>`.
- **Requires as stored (§4, §7.2 rules 4 and 6, as amended by docs#204).** `work_item_requires`
  holds the clause **expanded** through `capabilitiesOf` from `lib/vocabulary.mjs` — a role
  becomes its capabilities, a legacy name stays itself, `none` and no clause store no row —
  so it compares directly with the expanded `worker_capabilities`. No role name is stored,
  `human-operator` included: `work_items.operator_only` is 1 when the item has the `OP` tag
  or a `human-operator` name in its clause, and rule 6 reads that column. `reviewer_agents`
  carries the optional `models` column (§4, §7.4).
- **CAS (R-BTN-11).** `POST /v1/sync/board` accepts `parent_sha === board_head.sha`, or
  `parent_sha: null` when no head exists; else `head-moved`. `force: true` stores a held
  snapshot and a `snapshot-rejected` event; auto-accept at 24 h is the alarm's job, added in
  R3-1212 — this item stores the held snapshot only.
- **The dashboard** is static HTML + one ES module in `src/ui/`, rendering with
  `textContent` only (§10.4). Ready lists each item's `requires`, tier and rank reason;
  Providers lists accounts, peak now and next change from `peak_schedules`.
- **Shared code.** `src/` imports `../../scripts/lib/baton.mjs`; wrangler bundles it.
- **Do not:** call `Date.now()` outside the clock; trust any header but the verified JWTs;
  render with `innerHTML`; let the test key's verification path exist outside the test
  bindings (§13a); add worker endpoints (R3-1211).

### Tests

- `infra/baton/test/unit/auth.test.ts`: a token for another repo, ref or workflow is refused
  (G-BTN-11); an Access JWT for another email or `aud` is refused; a POST without the same
  `Origin` is refused (G-BTN-12).
- `infra/baton/test/unit/sync.test.ts`: first snapshot with `parent_sha: null`; a stale
  `parent_sha` gets `head-moved`; `force` is held (G-BTN-7).
- `infra/baton/test/unit/workItems.test.ts`: a snapshot changing one item rewrites one row;
  a clause naming `agent-venue` lands in `work_item_requires` as its four capabilities and a
  legacy name (`mcp-chrome`) as itself; `none` and no clause store no row and set
  `requires_clause`; an `OP`-tagged item and a `human-operator` clause each set
  `operator_only = 1` with no `human-operator` row;
  a removed item's row is deleted; no column holds body text (G-BTN-39's server half).
- `infra/baton/test/integration/S-BTN-13.board-ordering.test.ts`: the harness's bare repo
  gets two pushes; their syncs post out of order; the head never moves backwards; a rewritten
  history is held. Board states come from running the real `scripts/factory-state.mjs` on the
  bare repo's fixture items.
