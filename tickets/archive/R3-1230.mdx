### Why

The owner renamed Baton's unit from "work item" to "ticket" (2026-10-14): "work item" is the
docs roadmap's word. Every later item of the amendment writes against the new names, so the
rename lands first and alone, where a reviewer can check it changes nothing else. Tier:
judgement — two repos and a schema migration.

### What to build

1. baton `src/migrations/0005_tickets.sql`: `work_items` → `tickets`, `work_item_claims` →
   `claims`, `item_overrides` → `ticket_overrides`, `work_item_requires` → `ticket_requires`;
   every `work_item_id` column → `ticket_id`; `board_snapshots.item_count` → `ticket_count`;
   indexes renamed to match (`one_active_claim_per_ticket`, `tickets_ready`).
2. API: `GET /v1/worker/tickets/{ticket}/holder` replaces `/v1/worker/items/{item}/holder`;
   every request and response field `work_item_id` becomes `ticket_id`; error code
   `no-eligible-ticket` replaces `no-eligible-item`.
3. docs: `scripts/baton-worker.mjs` (the holder call at line 302, the code list at 189 and the
   comment at 27), `scripts/claim.sh` (its self-test stubs at 1381–1399),
   `scripts/lib/batonClient.mjs`, `scripts/lib/batonSync.mjs`, `scripts/lib/baton.mjs`,
   `scripts/baton-mirror.mjs` and their tests; then `npm run vendor` in baton.

### Architecture — the decisions, named

- **SQLite renames in place**: `ALTER TABLE … RENAME TO` and `ALTER TABLE … RENAME COLUMN`;
  indexes are dropped and re-created under their new names in the same migration. Rows are
  never copied.
- **Append-only**: `0001`–`0004` stay as they are (baton `CLAUDE.md`); the object's
  migration runner applies `0005` like any other.
- **No aliases**: the old path and field names are not kept, because nothing is deployed
  (R3-1208 is unrun) and no client outside these two repos exists.
- **Vendored modules change in docs first** (`scripts/lib/baton.mjs`, `scripts/lib/batonSync.mjs`),
  then `npm run vendor` updates `src/shared/` and `manifest.json` (R-BTN-37).
- **Qualified ids are not this item**: `docs:R3-1205` arrives with R3-1231; here a ticket id
  is still the bare `R3-…`.
- **Do not**: change any query's logic, any refusal, or any test's expectation other than a
  name; rename `isEligible`'s `item` parameter (internal); edit archived roadmap items.
