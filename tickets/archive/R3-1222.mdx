**Spec:** `docs/content/specs/BATON_SPEC.mdx` §2 (`repos` is a filter field), §7.1 (docs@a6bc7c28)
**Depends on:** R3-1207

### Requires

- none — unit tests, `check:requires` and `npm run verify`.

### Why

R3-1207's `repoName` turns each `repos:` entry into the repository name Baton filters on. Round
three of its review found two defects, left for this item because the sync stays off until
R3-1208 sets `BATON_ENABLED`, so neither can touch a live board before this lands:

- the `kind (name)` form takes the bracket for **any** `word (word)` entry, so a `repo (note)`
  entry — `deploy (provisioning)`, `site-main (follow-up)` — posts the wrong repository; the
  board's only bracketed shape is `app (<name>)`;
- an unreadable entry throws in the sync, which runs only after merge, so one bad `repos:`
  line on `main` would halt every sync until fixed. Nothing checks `repos:` on the PR that
  adds it (archived items carry such shapes: R3-70's `app repo (file-commander)`).

Tier: judgement — one rule, applied in two places (the sync and the board check), across two
repositories.

### What to build

1. `repoName` (docs `scripts/baton-sync.mjs`, or moved to a pure `scripts/lib/repoName.mjs` that
   both callers import): accept a bare name, `app (<name>)`, `owner/<name>` and a GitHub URL;
   throw on everything else, a bracket after any other word included.
2. `check-roadmap-requires.mjs` (`check:requires`, in verify): every **live** item's `repos:`
   entries pass `repoName`, or the check fails naming the item and the entry — so the refusal
   happens on the PR's own tree, never on the sync after merge.
3. baton: `test/fixtures/roadmap/R3-9003.mdx` uses the real shape (`app (deploy)`), the
   `fixtureRepo.mjs` comment says so, `npm run fixtures` regenerates `boards.json`, and
   `npm run vendor` if a vendored module changed.
4. docs `scripts/baton-sync.test.mjs`: drop the stale `claimOrder` comment and assertion under
   the payload test (round 3's 3-r3-3).

### Architecture — the decisions, named

- One function, two callers: the board check and the sync must accept exactly the same set.
- **Do not:** guess a name from an unknown shape; skip archived items' `repos:` (they are not
  live and are never posted) — the check covers live items only.

### Tests

- `scripts/baton-sync.test.mjs`: `app (devtools)` → `devtools`; `deploy (provisioning)`,
  `site-main (follow-up)` and `app repo (file-commander)` throw.
- `check-roadmap-requires.mjs --self-test`: a fixture item with `repos: [x (y)]` fails the check
  naming it; one with `repos: [app (devtools)]` passes.
- Scenarios: S-BTN-13 (baton) re-run with the regenerated fixtures; none new.
