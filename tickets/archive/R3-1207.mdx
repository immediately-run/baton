**Brief:** [the Baton project](../projects/baton.mdx).
**Spec:** `docs/content/specs/BATON_SPEC.mdx` §3 (deploy), §7.1, §10.3 R-BTN-15, §13a (where it runs) (docs@2dbf1424)
**Depends on:** R3-1205, R3-1206

### Requires

- none — the workflows are tested by running their scripts against the harness's bare repo;
  the first real deploy needs secrets the owner sets in R3-1208.

### Why

The read-only view needs real board snapshots and a deployed Worker, and `test:baton` must
run where every other check runs. Tier: critical — the workflows mint OIDC tokens and use a
deploy secret.

### What to build

1. `.github/workflows/baton-deploy.yml`: on push to `main` touching `infra/baton/**` or
   `scripts/lib/baton.mjs`, run `npm ci --prefix infra/baton`, `npm run test:baton`, then
   `wrangler deploy` (production) and `wrangler deploy --env staging`.
2. `.github/workflows/baton-sync.yml` and `scripts/baton-sync.mjs` (§7.1).
3. `scripts/baton-sync.mjs --compare`: prints, per tier, the dashboard's Ready order beside
   `claimOrder(state, {tier})`, and exits 1 on a difference.
4. `test:baton` in `verify`, scoped to changes under `infra/baton/`, `scripts/lib/baton.mjs`,
   `scripts/lib/vocabulary.mjs`.

### Architecture — the decisions, named

- **Sync triggers (§7.1):** `push` to `main` with the `paths:` list in §7.1, `workflow_dispatch`,
  and `schedule: '*/15 * * * *'`; `concurrency: baton-sync` with `cancel-in-progress: false`.
  `actions/checkout` with `fetch-depth: 0`. `permissions: id-token: write, contents: read`.
- **`baton-sync.mjs`** (Node, exported functions + `main()`): `decide(headSha, newSha, isAncestor)`
  returns `'confirm-only' | 'advance' | 'force'` (§7.1 step 3); `buildPayload()` runs
  `factory-state.mjs`, adds each state item's `repos` from its file's `repos:` frontmatter
  (factory-state's items do not carry it, and `work_items.repos` is a §2 filter field — found
  in baton#1's review), posts `ready` as `rankReady(state)`'s ids, reads the three data files
  and the reviewer catalog —
  `reviews_on`, `bills` and the optional `models` (§7.4, as amended by docs#204), taken from
  `scripts/data/reviewer-matrix.json`'s `agents` until R3-1215 adds the frontmatter keys, and
  from the frontmatter after, failing loudly on a seated agent missing `reviews_on` or
  `bills` — and computes confirmations (§6.7: `git merge-base --is-ancestor` plus status not
  `in-progress`); `post()` retries once on `head-moved` after re-reading the head, and on `unavailable` (503,
  a key-set outage, BATON_SPEC §11) after a short backoff, failing the run if it persists. The OIDC
  token comes from `ACTIONS_ID_TOKEN_REQUEST_URL` with audience `workitems.immediately.run`.
- **Deploy secret:** `CLOUDFLARE_API_TOKEN` (Workers Scripts edit on one account), set by the
  owner in R3-1208; the workflow fails loudly naming the secret when it is absent.
- **Do not:** use the triggering commit instead of `origin/main` (§7.1 step 2); store any
  Baton secret in the repo; let a failed sync retry in a loop (one retry, then fail the run).
