Run `npm run spec:impact` on [R-BTN-10](../../spec/BATON_SPEC/09-claims.md#sec-9-6) and [S-BTN-18](../../spec/BATON_SPEC/15-verification.md#scenarios) before the code changes.

**Depends on:** none.

### What happened

On 2026-11-25 two tickets, B-127 (claim 106, `suspended:adjudicated`, 2026-11-07) and B-176 (claim 240, `suspended:reviewed`, 2026-11-17), stayed `unconfirmed` in `GET /v1/repositories/baton/tickets?state=unconfirmed` long after git closed both as done and archived them (2026-11-12 and 2026-11-18). See `docs/interventions.mdx`, 2026-11-24 20:00.

- **Nothing could confirm them.** Each parked end named evidence. #415's observation lists only ends whose ticket is live and not in `closed_tickets`, so the sync never attested them. R-BTN-10 says nothing about a suspended end whose ticket closed after it; only a `done` end is confirmed by closure.
- **The administrator could not resolve them either.** The ticket listing keeps a claim on a dropped ticket as a row of its own (`src/core/tickets.ts`, "A claim on a ticket git has dropped stays"), so the Unconfirmed tab shows them. But Confirm and Release live on the ticket's page (`src/dashboard/screens/tickets/TicketControls.tsx`), and `GET /v1/repositories/{repo}/tickets/{id}` answers `404 … is not on the board` for a closed ticket, so the page says "No such ticket". The owner confirmed both from the browser console with `POST /v1/ui/claims/{id}/confirm`.

### What to build

1. **Spec, then server: a closure settles the ends still waiting on it.** Amend R-BTN-10 so that an unconfirmed suspended end whose ticket git has since closed (any `closed_as`) or dropped is settled by the first accepted snapshot that shows the closure. Whether it is *confirmed* or *released* is the spec PR's question for the owner. Confirmed reads as "the work stood", released as "the position no longer matters"; either way it must stop holding and stop being listed. Implement it in `judge` (`src/core/claims.ts`), log the event the spec names, and keep S-BTN-243's read budget.
2. **Dashboard: an unconfirmed end is resolvable wherever it is listed.** A row of the Unconfirmed tab whose ticket is not on the board (no title, no position) offers `claim.confirm` and `claim.release` itself, or links to a page that does. It must never be a link to "No such ticket". Read `docs/context/ux.mdx` first.

### Trust

No new authority: `claim.confirm` and `claim.release` stay an administrator's session actions (R-BTN-155), and the settling in item 1 runs only on an accepted snapshot.

### Invariants

- A suspended end of a live ticket is confirmed exactly as today: by its attested evidence, or by any accepted snapshot when it named none.
- A `done` end is confirmed exactly as today.

### Tests

- A scenario (take a number with `baton tickets next scenario`): a suspension that named a URL, then git closes the ticket as done. The next accepted snapshot settles the end as the spec says, and the ticket leaves `?state=unconfirmed`. The same with the ticket dropped instead of closed.
- A dashboard test: an Unconfirmed row for a dropped ticket offers both actions, and each calls its route with the claim's id.

### Exit criteria

- R-BTN-10 says what settles a suspended end whose ticket closed, and the code does it.
- No unconfirmed end on a closed or dropped ticket is listed without a way to resolve it.
- `npm test` is green.
