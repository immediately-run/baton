**What:** `src/core/baton.ts` holds the composition root and also the router, every route's
authorisation, the board post and the dashboard read model. Make it wiring only.

From the architecture review of 2026-11-19 (`docs/review/architecture-review-2026-11-19.mdx`, on the branch `review/architecture-2026-11-19` until it lands).

### What to build

Three move-only changes, each its own commit:

1. `src/core/sync.ts`: the board post and its helpers.
2. `src/core/views.ts`: the dashboard read model.
3. `src/core/routes/`: one file per principal family (runner, owner, admin, sync, public), each
   a function `(core, req, url, principal) => Response | null`.

The preambles the routes repeat become helpers: `liveRepoParam`, `ticketOf`, `requireGrant`
(the same grant check is written eight times today), `runnerSecret`.

This is a stepping stone to B-25 (the action registry), not a replacement: the route files are
what B-25 later generates.

**Done when:** `baton.ts` is under about 500 lines; no test changes beyond imports; each "one
check for every route naming a repository" is one function.

### Trust

No new input, and no check moves relative to the SQL it guards: each route keeps its principal
check and its `src/core/validate.ts` calls ahead of any write. The review of the change reads
each moved route for a dropped check; a retired repository answering on a route
(`registry.get` where `registry.live` was meant) is the mistake this file already made once.
