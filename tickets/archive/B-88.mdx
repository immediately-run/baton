**Brief:** the gap-analysis run (finding 6): the server accepts a sync key's signature
(R-BTN-93 — proven by posting a board hand-signed through `syncMain` with the signing auth
injected), but `baton repo sync` produces only a CI identity token. A repository without
Actions, or bootstrapping its first board, cannot post one at all.
**Spec:** §7.1 (the board post), R-BTN-93 (a sync key signs as workers do), `src/runner/api.ts`
(`BatonApi` already signs), `src/defaults/cli.ts` (`syncMain`'s bearer-only auth).

### Why

The server side and the client library are both done; only the command's wiring is missing.
The hand-driven script that proved the server is the ticket's map.

### What to build

1. `baton repo sync --sync-key FILE`: `syncMain` builds its `BatonApi` with
   `envAuth`-style SSH signing (the runner's helper, imported) instead of the bearer when
   the flag is present; `BATON_SYNC_KEY` serves as the environment form.
2. The runbook's step 4 notes the flag as the no-CI path, and the sync workflow stays as it
   is (OIDC in Actions).
3. The admin runbook/README mention registering the key with `repo add --sync-key` beside
   the CI identity.

### Tests

- Unit: `parseSyncArgs` accepts the flag; `syncMain` signs the observation/head/board calls
  when it is set (a recording transport asserts the `Signature-Input` header).
- Integration: a signed sync post lands the board on the local host (the scenario the
  hand-driven script performed, made permanent).

### Exit criteria

- [x] a repository with a registered sync key posts its board from a laptop, one flag —
  S-BTN-156 (`test/integration/S-BTN-156.sync-key.test.ts`, "a registered sync key posts the
  board from a laptop, one flag, no CI and no bearer"): an ssh-keygen ed25519 key, registered
  through `Registry.addSyncKey`, posts the board with no CI token and no `BATON_SYNC_TOKEN` in
  the environment, and each of the three calls carries a `Signature-Input` naming that key's
  fingerprint; `test/unit/defaults-cli.test.ts` asserts the same at the CLI's seam.
