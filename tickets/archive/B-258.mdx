**What:** a person's `confirmed` answer at B-257's `delivered` station also archives the ticket file (owner ruling, 2026-11-17). Today Baton holds the ticket at the `confirmed` end, but the file keeps its status until someone runs `baton tickets done`, so git and Baton disagree until a person remembers.

- Add a runner leg after `confirm` (`archive`) that runs the same steps as `baton tickets done <id>` — status `done`, the file moved to `tickets/archive/`, relative links rewritten (#265) — in one commit, naming the delivered commit(s) from the end record as the ticket's evidence.
- The leg runs only after the person's `confirmed` answer, never from the agent's `delivered` word alone.
- The owner answers `confirm` (owner ruling, 2026-11-17: `asks: owner` stays).

**Done when:** a scenario where the owner answers `confirmed` ends with the ticket archived in git and closed in Baton, with no further person step; a `filed` answer archives nothing.

### Trust

No new input: the leg acts on Baton's record of the person's answer and the end's evidence, both already stored.

### Invariants

- A ticket is closed only by a person's confirmation or a merged PR, never by a leg's word alone (B-257).
- The archive commit is the same one `baton tickets done` writes.
