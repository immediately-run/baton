### Why

The owner moved the host to `baton.immediately.run` on 2026-10-14 when "work item" became
"ticket". The old name is configured in both repos: `wrangler.toml` lines 5, 23, 27, 43, 50, 53
(routes, `PUBLIC_ORIGIN`, `OIDC_AUDIENCE`, both environments) and docs
`scripts/lib/batonClient.mjs:5-6` (`BATON_URL`, `AUDIENCE`), `scripts/baton-worker.mjs:47`,
comments in `scripts/baton-sync.mjs:13-14` and `scripts/lib/vocabulary.mjs:43`. Tier: critical
— the OIDC audience is half of the sync principal's check (R-BTN-15).

### What to build

1. baton: production route `baton.immediately.run/*`, `PUBLIC_ORIGIN = "https://baton.immediately.run"`,
   staging route and origin `baton-staging.immediately.run`, `OIDC_AUDIENCE = "baton.immediately.run"`
   in both environments.
2. docs: `BATON_URL` default and `AUDIENCE` in `scripts/lib/batonClient.mjs`, the default in
   `scripts/baton-worker.mjs`, and the comments that name the host.

### Architecture — the decisions, named

- **One home per literal.** docs reads the host only from `scripts/lib/batonClient.mjs`
  (`BATON_URL`, `AUDIENCE`); `scripts/baton-worker.mjs:47` imports `BATON_URL` instead of
  spelling its own default. The baton Worker reads it only from `wrangler.toml` vars.
- **No transition period.** The Worker accepts exactly one audience. Nothing is deployed, so
  accepting both names would be a permanent widening for no caller.
- **Merge order:** both PRs may merge in either order; neither is live until R3-1208.
- **Do not**: rename the Worker (`baton`, `baton-staging`) or the Durable Object class; touch
  archived items' text (history); add a redirect from the old host.
