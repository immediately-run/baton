**What:** build R-BTN-149's retention (02-deployments.md:247-250), which the spec requires and nothing implements (no `DELETE FROM events` in src).

- In the alarm, batched (e.g. 1,000 rows per tick): repository `events` older than 90 days below every live mirror's `mirror_acked_seq`; `board_snapshots` older than 90 days (never the head's); runner dependents (capabilities, tags, courses, reports) unseen 30 days. Keep `workers` rows (R-BTN-3).
- Then claims, claim_legs and activities only for tickets with `closed_tickets.purged_at` set — open tickets still read them (R-BTN-106 chain rule, R-BTN-24 resume, R-BTN-81 history, the end-observation check). Delete events → claim_legs/activities → claims.

**Target:** every events- and claims-proportional read stays bounded as time passes.

**Why:** on 2026-11-14 production exceeded Cloudflare's free-tier Durable Objects limit of
5,000,000 `rows_read`/day at 21:41Z; every runner call returned 500 until the 00:00Z reset.
Measured on a production-sized local state (180 tickets, 600 claims, ~3k events) with
workerd's `SqlStorageCursor.rowsRead`: `GET /v1/ui/state` ≈ 14.4k rows per 10 s poll
(≈ 3·events + 2–5k), recommendations ≈ 3.7k, claim ≈ 3.8–4k, alarm ≈ 0.8–1.3k per minute,
`POST /v1/sync/board` 4–5k rows over ~2.5k statements. This ticket is one of B-235–B-243,
the owner's 2026-11-15 plan to bound what each read costs.

**Done when:** the named calls' rows_read, measured the same way in a test (cloudflare host),
is at or below the target, `EXPLAIN QUERY PLAN` shows the intended index where one is named,
and behaviour is unchanged (the existing scenarios pass).

### Trust

No new input: indexes, tables and queries over data Baton already stores; no field, file, commit trailer or request is added.

### Invariants

- R-BTN-149's retention is what is built, nothing wider.
- R-BTN-3: runner rows are never deleted, only their dependents.
- R-BTN-106, R-BTN-24, R-BTN-81: claims, legs and activities are deleted only for purged tickets.
- Events below a live mirror's `mirror_acked_seq` only, so no mirror loses an event it has not acknowledged.
