### Requires

- none — the mirror script runs against the harness's bare repo.

### Why

After cutover every git reader — `check:claims`, `factory-state.mjs`, `reconcile-merged-items.mjs`,
`claimedAt()`, the process dashboard's timelines — still needs claims in git, in today's
shapes and with the right times. Tier: critical — it writes `docs/main`.

### What to build

1. `scripts/baton-mirror.mjs`: reads `GET /v1/sync/events?after=<cursor>`, writes one commit
   per transition with today's subjects and notes, `GIT_AUTHOR_DATE` = the event's time; the
   claim note is `(claim <nonce>)` with **no session** (R-BTN-36), and the export names
   workers only by claim id.
2. Preconditions (R-BTN-17), at-least-once replay, push-conflict retry.
3. Foreign-claim handling (§12), held notes (§6.10), `EXPEDITE` from overrides, the
   `content/plans/baton/claim-events.mdx` export.
4. `.github/workflows/baton-mirror.yml`: `workflow_dispatch` plus a 15-minute schedule, OIDC
   audience `workitems.immediately.run`.
5. Baton dispatches the workflow after each claim, release or reap, with the Actions-write
   token (§10.3).

### Architecture — the decisions, named

- **Reuse the transforms.** Status and note edits go through the same awk transforms
  `claim.sh` uses (`transform_claim`, `transform_set`), called as `claim.sh --transform-only`
  (a new flag that prints the rewritten file to stdout), so there is one writer of those
  shapes.
- **The cursor** is stored in the export file's front matter; it advances only after a push
  lands.
- **Notes** pass `check-note-mdx`; free text goes in code spans (§10.4).
- **Do not:** write a status whose precondition fails; batch several items in one commit
  (`claimedAt` and `itemTimelines` read per-item subjects); change the subject shapes.

### Tests

- `scripts/baton-mirror.test.mjs`: precondition table; replay is a no-op; author date equals
  the event's time; G-BTN-41 — no mirrored note, subject or export line contains a session
  name, worker id or hostname, and `holderOf` returns nothing for a mirrored claim.
- Integration: `S-BTN-14.mirror-preconditions`; G-BTN-8, G-BTN-9 (`check:claims`,
  `factory-state.mjs`, `claimedAt`, `itemTimelines` read the mirror's commits as they read
  `claim.sh`'s).
