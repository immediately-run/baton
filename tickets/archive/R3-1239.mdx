### Requires

- none — test keys of every type are generated in the harness.

### Why

Bearer tokens work for anyone who holds them until revoked; the owner chose SSH keypairs
(2026-10-14). The revision of the same day withdrew commit and marker signing: Baton does not
fortify git's security model. Tier: critical — authentication.

### What to build

1. `credentials` keyed by fingerprint with one registered name per worker key (unique; a
   cloud environment's containers share it), subjects and repositories for probes.
2. Verification of SSHSIG signatures over the RFC 9421 base for `ssh-ed25519`,
   `ecdsa-sha2-nistp256` and their `sk-` forms (FIDO flags and counter), with `@authority`,
   `content-digest` (the empty string's for no body), `created` within 5 minutes and a nonce
   cache by fingerprint for every signer, administrators and owners included.
3. The Worker rejects unsigned, malformed, stale or foreign-`@authority` requests before the
   Durable Object; key and nonce checks run inside it.
4. The sidecar and CLIs sign through `ssh-agent` or a key file.

### Architecture — the decisions, named

- **One verifier**, `verifyRequest(req, lookupKey)` in `src/core/auth.ts`, used for every
  principal; the namespace is always `baton-request`.
- **Do not**: verify signatures on commits or markers; accept a signature in another
  namespace; store a private key.

### Tests

- Integration: S-BTN-30 on both hosts, with keys of all four types.
- `test/unit/auth.test.ts`: a replay to another `@authority`, a body-less request's digest,
  a git-namespace signature presented as a request.

### Exit criteria

- [x] S-BTN-30 passes on both hosts
- [x] `git grep -n "verify-commit\|baton-marker" src/` returns nothing
- [x] `npm run typecheck` green
