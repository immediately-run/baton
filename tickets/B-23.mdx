**Brief:** the owner, 2026-10-17: a Git-like CLI with every leg command under `baton leg`, and `baton leg log` showing a leg's logs. Each leg run's output is saved now, and the old command names go outright. B-22 specified it (baton#46).
**Spec:** `spec/BATON_SPEC.md` §11.3 (R-BTN-127), §8.5 (R-BTN-128), §8.4 (R-BTN-144: the one list of
what is masked), §14's rows; history, Migrations: renamed CLI commands.

### Why

R-BTN-127 and R-BTN-128 are specified. This ticket builds them, and moves every caller of the old names in the same release.

### What to build

1. **The tree.** Rebuild `cli/baton.mjs` as R-BTN-127's tree:
   - each command signs as its actions' `callers`, in order, trying the first role the user
     holds a key for (`-i`, else `~/.config/baton/keys.json` for the origin called); no key for
     any of them exits 2 naming the first role (R-BTN-127, G-BTN-117, adv-4 m12);
   - each old name exits 2 with its "renamed:" line, kept until no caller uses it (history, Migrations);
   - an ambiguous ticket id lists its matches;
   - the leg default is running, then queued, then most recent;
   - the channel verbs work only inside a leg;
   - `help` covers every level, with nearest-name suggestions;
   - every read takes `--json`;
   - R-BTN-127's rows that later tickets fill in: `decision list` on the conditions route and
     `owner resolve` (B-56), `leg raise` (B-55), `leg await` (B-59).
2. **The leg log.** In `src/runner`: read the pipes of a `process`-mode leg, mask R-BTN-144's
   closed credential set on the byte stream before framing, and write create-only chunks
   `<dir>/<n>.jsonl` (1 s or 256 KB) then `end.json` to the `dir` the claim or `advance` reply
   named, with bounded retries and buffer, `gap` frames and the 50 MB cap. One small writer
   interface with three implementations — `s3:` (AWS default credential chain,
   `AWS_ENDPOINT_URL_S3` for R2 or MinIO, `If-None-Match: *`), `gs:` (Application Default
   Credentials, `ifGenerationMatch=0`) and `file:` (`O_EXCL`) — the local one driving the
   scenarios. Only when the owners set `leg_log_root`.
3. **The server.**
   - the `leg_log_root` setting and its validation (`file:` only on the local host);
   - `claim_legs.leg_log_dir`, and `leg_log: {dir}` in the claim and `advance` replies;
   - `GET …/tickets/{ticket}/legs/{leg}/runs` with `log_dir`;
   - `POST /v1/owner/{repository}/tickets/{ticket}/release`.
4. **`baton leg log`.**
   - finished runs read from the directory with the user's own credentials, chunks in order;
   - `-f`, polling for the next chunk until `end.json`;
   - `--transcripts`;
   - session and attached runs as links;
   - the failure messages;
   - escapes and C0/C1 controls stripped on every printed path.
5. **The callers, in the same release.**
   - this repository's `README.md`, `scripts/`, tests and the runner's usage text;
   - the docs repository: `content/specs/BATON_DOCS_DEPLOYMENT.mdx` (docs' CI, `npx baton repo sync`, `baton course test`), `BATON_ROADMAP_PR_COURSE.mdx`, its skills and workflows that call `baton run`, `baton sync` or `baton test-course`.

### Do not

- Keep an alias for any old name.
- Store a log's bytes, or hold, mint or sign a bucket credential, in Baton.

### Tests

- S-BTN-97, S-BTN-98 and S-BTN-99 as integration scenarios on both hosts; G-BTN-117 to G-BTN-119.
- Unit (`test/unit/cli.test.ts`): a command whose actions' `callers` are `[owner, admin]` signs
  with the owner key when both are held, with the administrator key when only it is, and exits 2
  naming `owner` when neither is.
- `npm test`, `npm run typecheck` and `npm run check:spec` green, and docs' `npm run verify` green.

### Exit criteria

- [ ] the scenarios above pass on both hosts, with the first-held-role signing
- [ ] no caller in either repository uses an old name
- [ ] merged under the review gate
