**Brief:** the owner, 2026-10-17: every leg command under `baton leg`, and `baton leg log` showing a
leg's logs, each leg run's output saved. B-22 specified it (baton#46).

**Spec:** [R-BTN-128](../spec/BATON_SPEC/08-runners.md#sec-8-5) ([§8.5](../spec/BATON_SPEC/08-runners.md#sec-8-5), a leg run's output; its
design is part 10 of [the checks-and-executors proposal](../spec/proposals/checks-and-executors.md)
since the cut of 2026-11-19), [R-BTN-144](../spec/BATON_SPEC/08-runners.md#sec-8-4) ([§8.4](../spec/BATON_SPEC/08-runners.md#sec-8-4), the one
list of what is masked), [R-BTN-107](../spec/BATON_SPEC/08-runners.md#sec-8-3) ([§8.3](../spec/BATON_SPEC/08-runners.md#sec-8-3), which
executors stream a leg's output), [R-BTN-63](../spec/BATON_SPEC/05-courses.md#sec-5-3) (the run id
the directory is keyed by), [R-BTN-66](../spec/BATON_SPEC/01-what-baton-is.md#sec-1) (the owners'
settings), [§13](../spec/BATON_SPEC/13-data-model.md#sec-13) (`leg_log_root`,
`claim_legs.leg_log_dir`), [§14](../spec/BATON_SPEC/14-api.md#sec-14) (`GET …/legs/{leg}/runs` with
`log_dir`), [§15](../spec/BATON_SPEC/15-verification.md#sec-15) ([S-BTN-98](../spec/BATON_SPEC/15-verification.md#scenarios), [S-BTN-99](../spec/BATON_SPEC/15-verification.md#scenarios), [G-BTN-118](../spec/BATON_SPEC/15-verification.md#gates),
[G-BTN-119](../spec/BATON_SPEC/15-verification.md#gates)).

**Depends on:** B-22 (the specification, done). **B-299**: the reference runner masks only R-BTN-144's
classes 5 to 7 today (`src/runner/mask.ts`), so the runner's secret and the contents of its key
file (classes 1 and 2) can reach a leg's output; that output stays in the runner's own log now,
and this ticket would copy it to a bucket every owner and every reader of the bucket can see.
B-299's rows 2 and 5 (in review in [baton#339](https://github.com/immediately-run/baton/pull/339))
strip the runner's Baton credentials from the leg's environment and mask classes 1 and 2; this
ticket starts after they land. Classes 3 and 4 stay B-46's and B-131's, as R-BTN-144 says.

**Used by:** B-192 (adds a session caller to `legs/{leg}/runs`), B-197 and B-210 (draw its rows).

### Why

Today a leg's output reaches only the runner's own log, on whatever machine ran it. An owner
watching a leg, or reading why one failed, has to reach that machine. R-BTN-128's design keeps
Baton out of the bytes: the runner writes to storage its owners control, with credentials Baton
never sees, and the CLI reads it there.

### What to build

1. **The spec, first, in the same PR.** Move R-BTN-128 from part 10 of the checks-and-executors
   proposal back into §8.5 as built text, and strike the part from the proposal. Correct the
   proposal's "Built: … the masking of a leg's output (R-BTN-144)": after B-299, classes 1, 2 and
   5 to 7 are built, 3 and 4 not. S-BTN-98, S-BTN-99, G-BTN-118 and G-BTN-119 are already rows of
   §15; take `*no test*` off what this PR tests. Run `spec:impact` on R-BTN-128 and put the
   checklist in the PR body. The PR is a spec PR under the babysit skill's *Spec PRs*.
2. **The server.**
   - the owners' `leg_log_root` setting (R-BTN-66) and its validation in `src/core/validate.ts`:
     `s3://` and `gs://` with the bucket pattern and R-BTN-20's path rule, `file://` only on the
     local host, anything else `invalid-params`;
   - on each `advance` reply that starts a run while a root is set, `leg_log: {dir}` with `dir`
     `<root>/<tenant host>/<repository id>/<local ticket id>/<leg>/<run_id>/`, recorded as
     `claim_legs.leg_log_dir` (the column exists); nothing else about the log is stored;
   - `log_dir` on each row of the built `GET …/tickets/{ticket}/legs/{leg}/runs` (B-190).
3. **The runner** (`src/runner`). Only for a run whose `advance` reply named a directory, whose
   executor streams the leg's output (`builtin`; the `session` and `attached` executors stream
   none, R-BTN-107), and whose leg is not `"stream": false`:
   - frame the masked stream (the masker that already runs before bytes leave the runner, with
     B-299's classes) as R-BTN-128's JSON-lines frames, ≤ 8 KB each, cut between code points;
   - write create-only chunks `<dir>/<n>.jsonl` (1 s after a chunk's first frame or at 256 KB),
     then `end.json` last; bounded retries and buffer, `gap` frames and the 50 MB cap; a final
     failure records `leg-log-write-failed` and never delays or fails the end;
   - one small writer interface with three implementations: `s3:` (the AWS default credential
     chain, `AWS_ENDPOINT_URL_S3` for R2 or MinIO, `If-None-Match: *`), `gs:` (Application
     Default Credentials, `ifGenerationMatch=0`) and `file:` (`O_CREAT | O_EXCL`), the local one
     driving the scenarios.
4. **`baton leg log <ticket> [<leg>] [--run <n>] [-f] [--transcripts] [--json]`**, a verb beside
   the built `leg replay` and `leg raise` in `cli/baton.mjs`: the runs route, then the directory
   with the user's own credentials, chunks in order, `[gap]` for a missing `seq`; `-f` polling
   (1 s backing off to 10 s) until `end.json` or 30 s past the run's end; session and attached
   runs as their links and transcript pointers, `--transcripts` printing the transcripts; the
   run record and why when there is nothing to print; "cannot read `<dir>`" and exit 1 on a read
   failure; terminal escapes and C0/C1 controls (but newline and tab) stripped from every
   printed path and frame. `--json` prints frames as JSON lines. It signs as the current CLI
   signs, with the key `-i` names.

### Do not

- Store a log's bytes, or hold, mint or sign a bucket credential, in Baton (G-BTN-118).
- Ship before B-299's classes 1 and 2 are masked.
- Build the command tree, the old-name refusals or `baton leg stop`: the tree is B-157's (after
  B-25's registry), and the stop is R-BTN-119's, which B-299 assigns to B-9.

### Tests

- S-BTN-98 as an integration scenario on both hosts with the `file:` writer, and G-BTN-118: a
  run's output lands as create-only chunks and `end.json` in the named directory, a credential
  of every built class masked; nothing is written with no root, for a `stream: false` leg, or for
  a non-streaming executor; a failing writer never delays the end.
- S-BTN-99's leg-log clauses and G-BTN-119: `baton leg log -f` follows chunks to the end record,
  marking a gap; another repository's owner is `forbidden`. Its `leg stop` clause stays for the
  ticket that builds the stop.
- Unit: the `s3:` and `gs:` writers send the create-only precondition and read their credentials
  from the environment only; the root's validation; escape stripping.
- `npm test`, `npm run typecheck`, `npm run check:spec`, `npm run check:wiki` and
  `npm run check:tickets` green.

### Trust

- **`leg_log_root`** is an owner's setting, validated before it is stored; Baton turns it into a
  directory name and nothing more. Who may write or read the bucket is its owners' (IAM, a
  lifecycle rule), never Baton's.
- **The directory** in the `advance` reply is Baton's; the runner writes only there, with
  credentials from its own environment. Under `builtin` a leg runs as the runner's user and can
  reach the same storage, so a leg log is a diagnostic, not evidence (R-BTN-128).
- **What `baton leg log` prints** is written by a leg, which is repository code and possibly an
  injected agent (reaches 1 and 3): untrusted text, with terminal escapes and controls stripped
  before it reaches the reader's terminal.
- **The runs route** gives `log_dir` only to the repository's owners and administrators
  (G-BTN-119).

### Invariants

- **Baton never holds a log byte or a bucket credential** (G-BTN-118).
- **Masked before it leaves the runner** (R-BTN-144): the writer sees only the masker's output.
- **Create-only**: no chunk or end record is ever rewritten.
- **A log never delays or fails a leg's end.**
- **One clock**: the server reads time only through `this.now` (R-BTN-32).
