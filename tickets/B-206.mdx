**Brief:** the owner, 2026-11-09 (B-191): "sign in, pick a repository, and every screen after
that is one entity". The mockup's shell — the sidebar (Baton, the origin, the entries with their
counts, "Live · updated 7 s ago · Polls every 10 s") and the page header — is this ticket's
layout.

**Spec:** [BATON_SPEC §11.4](../spec/BATON_SPEC/11-people.md#sec-11-4) ([R-BTN-155](../spec/BATON_SPEC/11-people.md#sec-11-4):
sign-in by a confirmed code, per role; sessions; `ui.logout`), [§12.4](../spec/BATON_SPEC/12-security.md#sec-12-4)
([R-BTN-16](../spec/BATON_SPEC/12-security.md#sec-12-4): the pending and session cookies),
[§12.3](../spec/BATON_SPEC/12-security.md#sec-12-3) (text nodes; the `ui` renderer for a viewed
value, as B-191 amends it), [§5.5](../spec/BATON_SPEC/05-courses.md#sec-5-5) ([R-BTN-112](../spec/BATON_SPEC/05-courses.md#sec-5-5):
`renderUi` builds a node tree from a value and its schema's view), [§14](../spec/BATON_SPEC/14-api.md#sec-14)
(`POST /v1/login`, `POST /v1/ui/logout`, `repo.schemas`). Context: the brief's constraints.

**Depends on:** B-193 (the toolchain and serving), B-192 (session reads), B-204 (`repo.list`
carries the session's role, which the sidebar needs), B-217 (`repo.schemas` for `View`), B-76
(owner sessions: the sign-in has two roles). B-46's surfaces item names "the sign-in code flow,
logout and revoke"; the logout route is built here and B-46's item cites this ticket.

**Used by:** B-221, and through it every screen ticket.

### What to build

1. **Layout** (`src/dashboard/app/`): the mockup's frame — a sidebar (brand and origin; the
   current repository's screens with counts from `repo.list`; the tenant screens for an
   administrator's session, by `repo.list.session.role`; the freshness line, filled by B-221)
   and a main column with a page header. The sidebar's and strip's counts come from `repo.list`
   only (B-208); no screen supplies a count.
2. **`Text`** (`src/dashboard/lib/Text.tsx`): renders one value as a text child after string
   coercion; the only way a string from a read reaches the DOM besides `View`.
3. **`View`** (`src/dashboard/lib/View.tsx`): takes a value and a schema id; fetches the schema
   once per id through `repo.schemas` (B-217; cached for the session, per repository) and calls
   `src/shared/view.mjs`'s `renderUi(value, schemaId, resolve)`, which returns a node tree of
   `{tag, cls, text, children}`; `View` maps that tree to React elements with text children only
   — no `innerHTML`, no ref'd container. A schema the read does not know, or one with no view,
   falls back to pretty-printed JSON as text (§12.3).
4. **Sign-in.** `/login?as=administrator|owner` heads itself by role and runs R-BTN-155's steps:
   `POST /v1/login {role}`, show the eight-character code with the one CLI line that binds it
   (`baton admin open` or `baton owner open`), poll `{poll: true}` every two seconds, and on
   the session cookie go to `/`. On any screen whose read answers `unauthenticated`, the shell
   draws the same sign-in in place with two buttons — administrator sign-in and owner sign-in
   — keeps the URL it is on and continues there once signed in; no return URL is carried in a
   query (an open-redirect surface).
5. **`POST /v1/ui/logout`** (`ui.logout`): §14 lists it and no code serves it; build it — a
   session's own, ends the session row and clears the cookie, `{ok: true}` — and draw it in
   the sidebar's footer, back to the sign-in.
6. **Tests** under `test/ui/`: the sign-in page runs the code flow and lands on `/`; an
   `unauthenticated` answer draws the two-button sign-in and keeps the URL; `Text` and `View`
   render a hostile string as text; `View` maps a fixture node tree and falls back to JSON for
   an unknown schema; logout ends the session (a scenario on both hosts for the route).

### What not to do

- No router, polling, refusal screen, theme or drawer: B-221. No entity screen.
- No permission logic: the sidebar shows tenant entries by `repo.list.session.role`;
  everything else is drawn or refused by the server's answer.
- No return URL parameter; no `innerHTML` path in `View`.

### Trust

- **The pending and session cookies** are the only credentials; the shell holds no key and
  reads no secret (R-BTN-155).
- **Everything drawn** from a read is untrusted text through `Text` or `View` (§12.3); a schema
  is data the renderer interprets.
- **Logout** — a session's own action through `authorize`.

### Invariants

- **R-BTN-155**: sign-in by a confirmed code; the role is the session's.
- **Text, never markup** (§12.3): `Text` and `View` are the only paths from a read to the DOM,
  and `View` writes text children only.
- **Course-agnostic**; **one count source** (`repo.list`).
