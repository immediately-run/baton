**Brief:** [SELF-HOSTING](https://immediately.run/present/github/immediately-run/baton/main/bundle/docs/plans/self-hosting.mdx). The owner, 2026-10-16: no access to docs should
be needed to understand how Baton works or what is being developed.
**Spec:** BATON_SPEC R-BTN-37, §3, §6.4.

### Why

After R3-1267 the tickets and the spec are in the baton repository, but parts of how work gets
done there still point at docs:
- CLAUDE.md says the spec and items are in docs.
- `npm run vendor` copies `src/shared/` from `../docs`.
- The way an agent works a ticket (`next-roadmap-item`, `claim.sh`) exists only in docs.
- The deploy runbook is in docs and full of this deployment's values.

### What to build

1. **Agent workflow, without an entry-point skill** (owner, 2026-10-16: `baton runner start` claims
   tickets and runs each leg through the course's leg scripts, R3-1245, so no `/next-ticket` is
   needed):
   - **`AGENTS.md`**, with CLAUDE.md pointing to it: how to work a `B-n` or moved `R3-NNNN`
     ticket by hand while git is the lock (`npm run ticket`, until R3-1266), and how `baton runner start`
     drives the legs once Baton claims this repository's tickets. It needs no docs checkout and
     no `claim.sh`.
   - **The `pr` course's legs** in `.baton/courses/pr/legs/` (written by R3-1249's
     `baton repo init`): each leg's instructions for the agent session it launches — implement,
     review ending with a verdict line, fix, merge — beside its script, since a leg script is a
     launcher and what the leg does is its instructions' text. Review findings are recorded
     under `docs/review/`.
2. **CLAUDE.md, README, CHANGELOG.**
   - No rule or link needs docs.
   - The vendoring rule is replaced by item 3.
   - The changelog's preamble describes the baton repository only.
3. **Shared modules.**
   - `baton.mjs`, `vocabulary.mjs`, `sessionUsage.mjs` and `batonSync.mjs` become sources in
     baton, under `src/shared/` with no manifest pin to docs.
   - Docs consumes them instead: vendored from baton at a pinned commit, or from the published
     CLI package.
   - R-BTN-37's direction is amended in the spec (now in baton) and in docs' deployment spec.
   - Docs' R3-1237 is updated to match.
4. **Deploy guide.**
   - `docs/DEPLOY.md` in baton covers deploying any Baton to Cloudflare from the command line,
     generalised from `content/plans/baton/DEPLOY-RUNBOOK.mdx`, with placeholders for the
     zone, hostnames, the Access team and owners.
   - Docs keeps a short page with this deployment's values that points to it.
5. **Check.** Add a CI step in baton that fails on any `../docs`, `immediately-run/docs` or
   `content/` reference outside a marked history note, so nothing re-introduces the
   dependency.

### Do not

- Remove docs' own copies before docs consumes the baton-side sources: docs' sync and claim
  path must keep working through the switch.

### Tests

- A fresh clone of immediately-run/baton alone: `npm ci && npm test && npm run typecheck` pass,
  and an agent session following `AGENTS.md` claims and finishes a ticket on staging.
- The CI reference check fails on a planted `../docs` path.
- In docs: `npm run verify` and the Baton sync stay green on the baton-sourced modules.

### Exit criteria

- [ ] AGENTS.md and the `pr` course's leg instructions merged; a ticket worked end to end from a baton-only clone
- [ ] `src/shared/` sourced in baton; docs consumes it; R-BTN-37 amended
- [ ] `docs/DEPLOY.md` merged; the reference check is green in CI
