**What:** `stubSource` and `testsStubSource` in `src/defaults/cli.ts` emit about 515 lines of
JavaScript from template literals. No compiler or test reads that code as code, and `gitRun` and
`newestWrite` are defined again inside it.

From the architecture review of 2026-11-19 (`docs/review/architecture-review-2026-11-19.mdx`, on the branch `review/architecture-2026-11-19` until it lands).

### What to build

1. `src/defaults/stub-runtime.ts` exports `makeLeg(config)`: a real, type-checked module.
2. The generated entry is imports and a config literal.
3. In the same change, split `defaults/cli.ts` into its four parts: sync, facts, stubs, init.
4. `baton repo init --check` reports stubs that differ from their pinned source.

**Done when:** generated stubs behave identically on the existing tests, and the templates total
under 40 lines.

### Trust

A leg stub runs in the repository's checkout with the runner's credentials, and anyone who can
push can edit it. That does not change. What changes is that the logic is in a pinned module the
package ships, so `init --check` can say when a repository's stub has drifted from its source.

### Invariants

- Course code never core: the runtime is under `src/defaults/`, and core imports nothing from
  it.
- `baton repo init` from the published package works with no checkout and no esbuild, and pins
  the commit the package was built from.
- Verification at the boundary: the stub still checks what the agent wrote before it reports.
