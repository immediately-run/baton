**Brief:** continues B-3 (split 2026-10-20).
**Spec:** `spec/BATON_SPEC.md` §2m.2 R-BTN-109 (the sync checks pointers; a sync-posted arrival is checked when the snapshot is accepted), R-BTN-85 (`output-invalid`), R-BTN-82 (an invalid output is never resolved as an input; its consumer waits on `input-missing`); §13a S-BTN-66's third move; G-BTN-92's pointer clause.
**Depends on:** B-3 (the validator and the entry rule) and B-39 (outputs recorded and resolved as inputs, `input-missing`).

### Requires

- none.

### What to build

1. **The sync validates pointers.** For an output given by `uri`, the sync (`baton repo sync`) fetches it from git or the forge as the station function already reads git, validates it with `src/shared/schema.mjs`, and posts each output's verdict with the ticket. Baton never fetches.
2. **An invalid one** is logged as a discrepancy, sub `output-invalid` (R-BTN-85), is never resolved as an input, so its consumer waits on `input-missing`, and is listed under **Needs you**.
3. **A sync-posted arrival** — a path through a leg no claim reported, a person's leg among them — is checked when the snapshot is accepted: an unmet requirement or an invalid inline value is logged `output-invalid`, the station's outputs are not resolved as inputs, and the ticket is listed under Needs you.
