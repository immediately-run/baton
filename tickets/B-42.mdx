**Brief:** the owner, 2026-10-19: "a user's legs should be typescript, mjs or regular non-module
js. Node should perform module resolution (dependencies should be declared in the repo's
package.json)", then "please make the spec amendment, this is important".
**Spec:** `spec/BATON_SPEC.md` §8.4 R-BTN-133, as merged from PR 57 after three adversarial
review rounds, with R-BTN-143 (§8.4, the default-branch check). It amended R-BTN-5, -34, -51, -65,
-72, -105, -119, -121, -131, §5.7 (the test kit) and §6.6 rule 4; §15 S-BTN-109, G-BTN-128. This
ticket builds it. The owner's two rulings in it are settled: install roots are only
the course directory and `.baton/`, never the repository root.

### Requires

None: a checkout and a terminal.

### Why

Today the runner copies each `legs/<leg>.mjs` into a scratch directory (`src/runner/home.ts`
`loadCourse`). A leg can therefore only be `.mjs`, and can import only Node built-ins. A course
written in TypeScript, or one that needs a library, cannot be expressed.

### What to build

1. **The default-branch check is R-BTN-143's** (`src/runner/home.ts` `ensureSha`), run before
   any preparation, so an off-branch commit is never checked out or installed. B-46 builds
   R-BTN-143; if it has not landed, this ticket builds that check exactly as R-BTN-143 states
   (registered branch, `refs/baton/<repository>/default`, one fetch, `released:off-branch`, the
   held-rewrite cache) and B-46 reuses it. *(Changed 2026-10-19 when baton#57 merged with the
   hardening rules R-BTN-139–R-BTN-158: R-BTN-133 first defined its own check, ending
   `stale-board`.)*
2. **Leg trees:**
   - Sparse (non-cone) detached worktrees keyed by (repository, commit, path), stored under
     `<git dir>/baton/trees/`, each with a `.ready` stamp beside it.
   - Write the stop file `<git dir>/baton/package.json`.
   - Pass `-c core.hooksPath=/dev/null -c core.fsmonitor=false` on every git call.
   - Verify a tree on every reuse: stamp, ancestry, and `git status --porcelain
     --ignored=matching --untracked-files=all`. Refuse symlink escapes and submodules.
   - Keep three trees per repository.
3. **Install:**
   - npm only: `npm ci --omit=dev --no-audit --no-fund`, at the course directory and `.baton/`
     (each only when it declares dependencies).
   - Refuse a pnpm or yarn lockfile, a missing lockfile, `workspaces`, and `file:` directories.
   - Dependency cache keyed by digest (lockfile, `package.json`, ABI, platform, arch, npm
     version), made read-only and stamped. Re-check it before each leg; collect it with the last
     tree that links it.
   - Classify failures by npm error: `EUSAGE` is `spec`, `ENOSPC` is `capability`, anything
     else is `transient`.
4. **Preparation:** every step runs as an asynchronous child in its own process group, under
   the fence, stopped by R-BTN-119's sequence and bounded by `--prepare-timeout` (default 15
   minutes). A claim stopped in preparation gets no `close` and no `handoff`.
5. **The wrapper** (`src/runner/legProcess.mjs`):
   - Call form `node legProcess.mjs <call> <script> <ctx.json> <out.json>`, where `<call>` is
     `run`, `close`, `handoff`, `tickets`, `stations` or `rank`, and `out.json` carries `{ok,
     result|ref|url, error?, aborted?}`.
   - Working directory `ctx.checkout` for leg calls, and the whole-commit tree for `tickets`,
     `stations` and `rank`.
   - Clear `NODE_OPTIONS` and `NODE_PATH`.
   - A `module.registerHooks` resolve hook that serves `@immediately-run/baton/leg` and refuses
     anything outside the trees, the digests and `imports` paths. `imports` resolve only for
     `tickets`, `stations` and `rank`.
   - Bound `close` and `handoff` at 2 minutes each, and move both (and `rank.mjs`) out of the
     runner's process.
6. **Extensions:** `mjs`, `js`, `cjs`, `mts`, `ts` and `cts`; refuse two scripts for one leg.
   The runner refuses to start under Node < 22.18; set `engines` to `>=22.18`.
7. **The leg module** `@immediately-run/baton/leg`: `LegError` (identified by brand), `writeMarker`,
   `commentOnPr`, `yieldContext`, `nextFire`, `writeSuccessor`, `NOT_BEFORE_HORIZON_DAYS` and
   `CLI_VERSION`. `build:cli` (PR 58) ships it in `dist/`. The leg's `ctx` later gains `raise`
   (B-55, R-BTN-160) and `resume` (B-59, R-BTN-162); `LegError(type, …)` typing is B-55's.
8. **The `runner:` capability:**
   - Built-in type `runner`, treated as granted in core's rule 4: the `isEligible` list, the
     claim SQL, `fleet_capabilities` and the prerequisites answer. This ticket adds the value
     `leg-trees`; B-70 adds `session` (R-BTN-107) and B-64 `baton-legs` (R-BTN-171), on the same
     code.
   - The runner declares it from its own code, and so does an interactive sidecar. The kit and
     the sync refuse unknown values, and courses may not define the type.
9. **The test kit** (`src/local/testCourse.ts`): installs with the runner's command into its own
   cache and resolves through the same wrapper and hook. It enforces the extension rules and the
   `runner:leg-trees` requirement.
10. **Tests:** S-BTN-109 (`test/integration/`), G-BTN-128. Add cases for every extension, Node
   22.17's refusal, injected stop timers, ancestry, the digest cache's reuse and re-check, and
   the interactive sidecar's declaration.

### Exit criteria

- S-BTN-109 passes on the local project, and `npm test` and `npm run typecheck` are green.
- A course with a `.ts` leg that imports a dependency from `.baton/package.json` runs end to end
  under `baton runner start`, both from a checkout and from `dist/baton.mjs`.
- Carried from review round 3, to settle while building:
  - how `session`-mode runners and check-runners prepare trees (S-6);
  - the rollback limit stays as stated (R3-4).
