**What:** "is this runner live?" is written seven times, with semantics that differ, and not
always on purpose. Separately, the context types mark as optional the services `BatonCore` always
supplies: `src/core/claims.ts` alone has 41 `this.c.x?.` calls, so a dependency dropped from the
constructor silently disables a gate instead of failing the type check.

From the architecture review of 2026-11-19 (`docs/review/architecture-review-2026-11-19.mdx`, on the branch `review/architecture-2026-11-19` until it lands).

### What to build

1. One module holding `isLive(runner, now)` and its SQL fragment. The variants that differ on
   purpose (the dashboard's, the claim gate's) are named functions beside it, each with the rule
   it serves.
2. In each context type, the services `BatonCore` always supplies are required. An optional
   collaborator remains only where a host really may omit it.

**Done when:** no liveness comparison is written inline outside that module, and
`grep -c 'this\.c\.[a-z]*?\.' src/core/claims.ts` is near zero.

### Trust

No new input. This is where a refactor could move a gate: each of the seven sites is compared
with the rule it cites before it is replaced, and a difference is either named or reported as a
bug with its scenario.
