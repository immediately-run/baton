**Brief:** the owner, 2026-11-09 (B-191): "**Tenant screens (admins only)** — `/repositories`
registry, `/instances`, `/resources` with readings, `/capacities`, `/settings`, `/state`,
`/sessions`." The mockup's Capacity cards and Instance view table (`root.txt`) are what two of
these reads serve; its Probes line in Limits is `admin.resource.list`'s `probes`.

**Spec:** [BATON_SPEC §11.4](../spec/BATON_SPEC/11-people.md#sec-11-4) ("Instances and Capacity,
which are tenant-wide, are an administrator's"; instrument keys shown read-only),
[§11.2](../spec/BATON_SPEC/11-people.md#sec-11-2) ([R-BTN-57](../spec/BATON_SPEC/11-people.md#sec-11-2)),
[§6.3](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3) ([R-BTN-76](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3),
[R-BTN-101](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3): resources, instances,
readings, probes), [§6.7](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-7)
([R-BTN-99](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-7): the instance view),
[§6.11](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-11) ([R-BTN-178](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-11):

**Depends on:** B-192 (the front resolves sessions on admitted GETs), B-205 (ETag).

**Used by:** B-214, B-215, B-216.

### What to build

The §14 rows first, then the code. Every read's callers: `admin` (a key) and `{principal:
"session", roles: ["administrator"], scope: "instance"}`; an owner's session is `forbidden`.

1. **`GET /v1/admin/instances`** (`admin.instance.list`): the instance view R-BTN-99 serves
   runners — each instance `{name, resource, serves, repositories, state: {available, until},
   readings: [{source: runner | probe | administrator, credential, kind, available, until,
   valid_for, detail, at, stale}]}` — `detail` the validated object (R-BTN-76), `stale` when
   `valid_for` has passed. From `resources.view`.
2. **`GET /v1/admin/resources`** (`admin.resource.list`): each resource `{name, scope,
   detail_schema, instances: [name]}` and `probes: [{fingerprint, label, added_at}]` (the
   instrument keys, R-BTN-101).
3. **`GET /v1/admin/capacities`** exists (`resources.capacities`): give it its §14 row and the
   id `admin.capacity.list` — each capability with a capacity `{capability, capacity, held,
   holders: [{claim_id, ticket_id, runner_id}]}` (R-BTN-178).
4. **`GET /v1/admin/settings`** (`admin.settings.show`): `{link_hosts, session_hosts,
   check_app_id}` (R-BTN-112, R-BTN-113, §12.7).
5. **`GET /v1/admin/tenant`** (`admin.tenant`): `{live: {runners, repositories, tickets,
   history_rows, claims}, rate: {requests_per_s_5m, burst_5s_max}, envelope: {runners: 50,
   repositories: 20, tickets: 5000, history_rows: 1000000, requests_per_s_5m: 20, burst_5s: 100},
   storage_bytes}` — R-BTN-87's figures, each live one beside its envelope value, "rates as
   5-minute means". The request counter is new (Decision 8a): the core counts verified requests
   per 5-second bucket in the tenant's object (in memory, as the MCP rate counter is; a restart
   empties it), and answers the 5-minute mean and the largest 5-second bucket of the window. The
   mockup's "requests / min 38 / 600" is not drawn: 600 a minute is §2.3's per-credential
   admission limit, not a tenant figure. `frozen` and `sealed` are not reported: R-BTN-88's
   freeze and seal are built by no ticket, and when one builds them it adds the two fields and
   `/state`'s banner (B-215 names the gap).
6. **`GET /v1/admin/sessions`** (`admin.session.list`): the live dashboard sessions — `{id, role,
   key_fingerprint, repositories, bound_at, last_seen_at, client_addr, current}` (`current` the
   caller's own); ended sessions are not listed (they live at most 4 hours, R-BTN-155).
7. **`GET /v1/admin/repositories`** (`admin.repo.list`) gains, per row, `tiers`, `sync_keys:
   [{fingerprint, role}]`, `ci_identity`, `retired_at`, and `?retired=1` to include retired
   repositories — the registry screen's columns (B-214); its §14 row follows. `GET
   /v1/admin/state` is untouched (B-216 settles it).

### What not to do

- No write here, and no session caller on any administrator write (Decision 1a): the tenant
  screens are read-only.
- No secret in any read: `check_app_id` is an id; probes are public keys' fingerprints.
- No screen here: B-214 and B-215.

### Trust

- **The reads** — Baton's rows and administrator configuration; instance names, reading
  `detail`, client addresses and labels are untrusted text or validated blobs (§12.3); answered
  to an administrator's key or session only, the same refusal for an owner's session as for no
  session.

### Invariants

- **Administrators only** (R-BTN-57, R-BTN-155).
- **Readings are statements** (R-BTN-76): returned, never judged beyond `stale`.
- **The envelope is the operator's advice** (R-BTN-87): every figure shown, none refused here.
- **Filter fields only** (R-BTN-33); **both hosts** (R-BTN-55); **one clock** (R-BTN-32): the
  counter reads time through `this.now`.

### Tests

Scenarios numbered at merge, on both hosts, with two instances holding readings from a runner
and a probe (one stale), one capacity half held, two sessions: each read answers the
administrator's key and session and refuses the owner's session; `admin.tenant`'s live counts
equal the rows and its rate reflects a burst of verified requests under the fake clock;
`admin.session.list` marks the caller's own and lists no ended session; `admin.resource.list`
lists the probe key; `admin.repo.list` carries `tiers`, `sync_keys`, `ci_identity` and, with
`?retired=1`, a retired row.

### Exit criteria

- [ ] The five new reads, the capacities row and the registry read's new fields in §14 and the
      registry, built, with tests; the request counter in core.
- [ ] The scenarios pass; `npm test`, `npm run typecheck`, `npm run check:wiki` and
      `npm run check:tickets` are green.
