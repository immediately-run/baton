**Brief:** the owner, 2026-11-09 (B-191): "station/leg graph with queue depths, per-ticket
paths, stats." The mockup's Courses page (`courses.png`: the header "course roadmap-pr v7 ·
workers at 7 · p50 over 7 days", stations as circles with "235 resting", legs with "1 on leg", a
▲ on the blocked leg, and the per-leg table) is the list's card; its "Output implement.result
v2" links to the dropped Schemas view are text. The brief's question 6 is what the screens
answer.

**Spec:** [BATON_SPEC §11.4](../spec/BATON_SPEC/11-people.md#sec-11-4) (the Courses screens,
carrying the retired Courses view), [§6.2](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2)
([R-BTN-126](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2): a blocked leg is a
marked edge, never a station), [§5.4](../spec/BATON_SPEC/05-courses.md#sec-5-4) ([R-BTN-79](../spec/BATON_SPEC/05-courses.md#sec-5-4)),
[§5.2](../spec/BATON_SPEC/05-courses.md#sec-5-2) ([R-BTN-69](../spec/BATON_SPEC/05-courses.md#sec-5-2)),
[§8.5](../spec/BATON_SPEC/08-runners.md#sec-8-5) ([R-BTN-128](../spec/BATON_SPEC/08-runners.md#sec-8-5):
a leg's log opens from its edge, as text), [§5.7](../spec/BATON_SPEC/05-courses.md#sec-5-7) (a
course changes by a commit), [§14](../spec/BATON_SPEC/14-api.md#sec-14) (`courses`,
`course.show`). Context: the brief — course-agnostic; an interactive SVG group carries its
accessible name.

**Depends on:** B-197 (`course.show`), B-208 (the shell; no control from B-207 is needed).

**Used by:** B-203.

### What to build

1. **The layout function**, `src/dashboard/lib/courseLayout.ts`, pure and unit-tested: from a
   course file, stations in columns by longest path from the course's entry station (cycles
   broken at back-edges, which are drawn as arcs under the row), within a column in the file's
   order; each leg a straight edge from its `from` to its `to` column with its label at the
   midpoint; returns coordinates for stations, edges and labels in a unit box the SVG scales.
2. **`/repositories/{r}/courses`** (`src/dashboard/screens/courses/`): one card per course from
   `GET …/courses` and `course.show`'s header fields: id and version, the mockup's header line
   (runners holding grants for it, the window), the graph drawn small by the layout with each
   station's resting count and each edge's "n on leg", and the per-leg `<table>` — from → to,
   output names as text, requires as chips, timeout, retries (`max_runs`), wait, run and fail
   rate from `stats` with a wait over the course's median marked; a `refused` file as a notice
   naming the version kept (R-BTN-69). A card opens the course page.
3. **`/repositories/{r}/courses/{course}`**: the graph large as inline SVG — stations as nodes
   with their resting count; each leg an edge with its state as shape and word first (▲
   blocked, ● running, ○ ready, ↻ backing off) and colour second, its depth against `max_queue`
   (over as a marked edge with "intake closed" as text), never a station for a blocked leg
   (R-BTN-126); every node and edge a focusable `<g>` with `role="button"` and an accessible
   name. Focusing or clicking an edge opens its panel: the leg's fields, its blocked tickets by
   kind and when found, and its window's runs (run, runner, started, ended, end, session link
   under R-BTN-113, transcripts, `log_dir` as text with the `baton leg log <ticket> <leg>`
   line); a station's panel lists its resting tickets. Below: the tickets on the course as a
   `<table>` (ticket linking its page, station, path drawn as the stations and legs run, the
   claim's legs since, waits-for, hand-off as text, blocks, queued leg and source, parent and
   children), loaded by cursor; the off-graph rows; the stats tables. `?since=` as URL query.
   The tables carry everything the drawing does.
4. **Course-agnostic.** Every station, leg, tag and output name is data from the read; the
   screen's source names none (a test greps the fixture's names against the source).
5. **Phone.** The graph scrolls horizontally in its box at 375 px; the tables stack.

### What not to do

- No control: a course changes by a commit (§5.7); a ticket's controls are on its page.
- No log bytes; no stats computed in the browser; no course validation.
- No layout library: the layout function is the repository's.

### Trust

- **Every value** is the reads' text through `Text` (the course file's names as node and edge
  labels, titles, pointers, log directories); session links only as passed. Nothing is written.

### Invariants

- **A blocked leg is a marked edge, never a station** (R-BTN-126); **queue depth is advice**
  (R-BTN-79).
- **Course-agnostic** (the brief); **text, never markup** (§12.3); **log directories as text**
  (R-BTN-128).
- **An owner's session, its repositories** (R-BTN-155).

### Tests

Under `test/ui/` with the layout's own fixtures and B-197's: the layout places a four-station
course in four columns and draws a back-edge as an arc; the SVG marks the blocked edge and draws
no blocked station; the over-`max_queue` edge is marked with its intake text; the edge panel
lists runs with `log_dir` as text; the tables hold what the drawing holds; every `<g>` has an
accessible name; the fixture's station names appear nowhere in the screen's source; a hostile
title is text.

      375 px.

      `npm run check:tickets` are green.
