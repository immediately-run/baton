**Spec:** R-BTN-144 (*What a leg's environment holds*, *Masking*), R-BTN-84 (replay), R-BTN-128
(leg logs), R-BTN-20 (archivers). Source: `docs/review/security-review-2026-11-02.mdx`, finding S1.
PR #165 added every bearer prefix to class 5 (B-169 builds it); this ticket holds the rest of S1.
The review's claims are a reviewer's; they were checked against the spec in PR #165.

### Why

The environment table keeps "git, forge and model-provider credentials, `SSH_AUTH_SOCK`", but
masking class 4 names only "the git and forge tokens the runner holds" and AWS's two variables. A
leg that prints its provider key — the credential an agent most often echoes — writes it in clear
to `leg_log_root` and, through an archiver, to a `transcript_repos` repository. The review's own fix
("the git, forge and model-provider tokens the runner holds") is not implementable as written: the
runner inherits the variables and does not know which one is a provider key, and core and the CLI
name no provider (values 3).

### Decided (the owner)

2026-11-02, choosing among this ticket's options: "I accept your recommendations" — option (a).
The spec states it (R-BTN-144 masking class 7, the environment table, R-BTN-84; S-BTN-98), PR
`claude/baton-spec-review-2fwiga`.

### What to build

1. The runner computes class 7 once at leg start from the environment it gives the leg: every
   variable whose name ends `_KEY`, `_TOKEN` or `_SECRET`, and every name `runner.json`
   `mask_env` lists (a list of names; an unknown name is ignored), each value of 8 bytes or more
   masked as a literal, with the others' classes.
2. An archiver under a runner (`BATON_PARENT` set) masks classes 5, 6 and 7 in transcripts,
   computing class 7 from its own environment.
3. Replay (R-BTN-84) masks its report the same way, when replay is built.
