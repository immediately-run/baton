**Brief:** the owner, 2026-11-09 (B-191): "Every screen = one entity's REST reads."

**Spec:** [BATON_SPEC §11.3](../spec/BATON_SPEC/11-people.md#sec-11-3) ([R-BTN-129](../spec/BATON_SPEC/11-people.md#sec-11-3):
`callers`; a session authorizes as `session` with its role; the one `authorize`),
[§11.4](../spec/BATON_SPEC/11-people.md#sec-11-4) ([R-BTN-155](../spec/BATON_SPEC/11-people.md#sec-11-4):
an owner's session only its repositories; the refusal rule as B-191 amends it),
[§12.1](../spec/BATON_SPEC/12-security.md#sec-12-1) (the session row; [R-BTN-179](../spec/BATON_SPEC/12-security.md#sec-12-1):
the state readable with a key), [§12.4](../spec/BATON_SPEC/12-security.md#sec-12-4) ([R-BTN-16](../spec/BATON_SPEC/12-security.md#sec-12-4):
same-origin JSON, the `Origin` and `Sec-Fetch-Site` checks), [§14](../spec/BATON_SPEC/14-api.md#sec-14)
(the repository reads).

**Depends on:** B-191 (the screens and the session paths are specified), B-25 (the registry,

### What to build

The §12.1 and §14 rows first, then the code.

1. **The front resolves a session on any admitted GET** (`src/core/front.ts`): a request carrying
   the `__Host-baton_session` cookie to a route whose registry entry lists `session` is the
   session's, with R-BTN-16's `Origin`/`Sec-Fetch-Site` checks as on `/v1/ui/*` today; this
   covers `/v1/repositories/*` and the `/v1/owner/{repository}/grants` and `…/policy/log` reads,
   which today demand a signature. A request that carries a signature or a bearer is that key's
   and its cookie is ignored. The list of admitted routes is the registry's (B-25), read by the
   front; no second list.
2. **Session callers** — `{principal: "session", roles: ["administrator", "owner"], scope:
   "repository"}` — on `GET /v1/repositories/{repository}/board`, `…/tickets/{ticket}/blocks`,
   `…/history`, `…/legs/{leg}/runs` (its callers are owner and admin: a session of either
   role), `blocked`, `conditions`, `stats`, `policy`, and `GET /v1/owner/{repository}/grants`,
   `…/policy/log`; `…/prerequisites` already lists a session in §14 and the code follows.
   `authorize` answers an owner's session on the repositories its key still owns, an
   administrator's everywhere.
3. **One refusal** (B-191's rule): on these reads a repository the caller cannot read — unowned,
   ungranted, unregistered or retired — answers `forbidden` for every principal (today an
   unregistered one answers `not-found`, `baton.ts`'s repository routes), so there is no
   existence oracle; an entity id not found in a readable repository stays `not-found`.
4. **§12.1 and R-BTN-16** as B-191 words them: the session row names the reads; R-BTN-16 says a
   session's reads outside `/v1/ui/*` are Baton's to authenticate.

### What not to do

- No new write caller: the confirmed-action list (R-BTN-155) and every write's callers are
  untouched.
- No read built here: `children`, `courses` and `schemas` are B-217's; the ticket, runner,
  course, sync, tenant and attestation reads are their tickets'.
- No `GET /v1/ui/state` change; no ETag or cursor (B-205).

### Trust

- **A session's read** — the cookie is the credential (R-BTN-155), checked on every request
  against its role and repositories; a repository the key cannot read is `forbidden`, the same
  for none.
- **A request with both a key and a cookie** — the key's; the cookie decides nothing, so a page
  cannot borrow a key's reach and a key cannot borrow a session's.

### Invariants

- **One check** (R-BTN-129): `authorize` decides every added caller; the front keeps no list of
  its own.
- **An owner's session reaches only its repositories** (R-BTN-155).
- **Readable with a key** (R-BTN-179): a session read is the same entry, query and JSON a key gets.
- **Same-origin** (R-BTN-16) on every session request; **both hosts** (R-BTN-55).

### Tests

Scenarios numbered at merge, on both hosts:

- an owner's session reads each listed read on its repository and is `forbidden` on another's
  and on an unregistered id; an administrator's reads both; a runner key's answers are unchanged
  except that an unregistered repository is now `forbidden`;
- a request with a cookie and a valid signature is the key's;
- a session request with a foreign `Origin` is refused as `/v1/ui/*` refuses it today;
- `/v1/owner/{r}/grants` answers an owner's session without a signature.

### Exit criteria

- [ ] §12.1's session row, R-BTN-16's paragraph and the §14 callers amended; `spec:index`
      current.
- [ ] The front resolves sessions on admitted GETs from the registry; every read above admits a
      session; the one refusal holds.
- [ ] The scenarios pass; `npm test`, `npm run typecheck`, `npm run check:wiki` and
      `npm run check:tickets` are green.
