**Brief:** the owner, 2026-10-22: "I would like review comments to be saved to the PR
review conversation as comments on GitHub for humans, but also as a file in the PR branch
which is deleted from the branch before it is squash merged, so it doesn't pollute the
main branch. This file would be the only means of communication available between
reviewer and addresser for plain git repos (no forge)."
**Spec:** §5.8 R-BTN-131 (the standard courses' stubs and closes — this is course code,
`src/defaults/pr-close.ts` and the review/address/merge stubs), §7.2 (the review rounds —
"later rounds get one fresh reviewer, who reads the earlier reviews and their replies"),
§2k R-BTN-92 (`forge: git`: no `web_base`, no links — no conversation API exists).

**Since the brief** (the owner, 2026-10-31, in `spec/BATON_SPEC_HISTORY.md`): the rounds left the
PR branch. On it, review commits move the attested head and every repair needed a trusted verifier
("per-ticket side branch is fine"), and a side branch is "very unidiomatic for forges so we should
only do this for plain git (make it a policy setting)". R-BTN-190 is the result.

### The protocol

- **The claim response carries the policy's `leg_state`** (B-145).
- **Under `forge`** (the default on GitHub, GitLab and Gitea): the review close posts the round to
  the PR conversation, the verdict line and the inline findings, as today; the address leg reads it
  from the conversation and answers there. No file is written anywhere.
- **Under `branch`** (the only choice where `forge` is `git`, R-BTN-92):
  - the review close writes the round, the same markdown, to the ticket's leg-state branch
    `baton-legs/<ticket id>` (an orphan branch, B-148) at
    `.baton-legs/<ticket id>/review/<claim nonce>/round.md`, the round number and verdict line
    included;
  - the address leg reads it with `git cat-file`, never a checkout, as quoted data, and answers at
    `.baton-legs/<ticket id>/address/<claim nonce>/reply.md`;
  - a review leg marked `approves: true` and an adjudicate leg read nothing from the branch.
- **The work branch never carries a round** under either value, so nothing is deleted before the
  squash and the merge runner refuses a work branch carrying `.baton-legs` (B-140).

### What this enables, and what it does not change

- On the forges, nothing observable changes for humans: the conversation remains what the close
  posts today, and no file mirrors it.
- On a plain git repository, the leg-state branch is the reviewer-to-addresser channel `create-pr`
  needs to run there at all (the placement's plain-git reading, verdicts from the branch instead of
  review states, is the follow-on ticket).

### Tests

- Unit (the closes' suite): under `forge`, a review close posts the conversation and writes no
  file; under `branch`, it writes the round to `baton-legs/<ticket>` at its own subpath and posts
  nothing; an address close answers beside it; an `approves: true` review reads nothing from the
  branch; the work branch is untouched throughout.
- The kit: a round-trip under `branch` (review, address, merge) runs on the local host with no
  forge token, and the squashed tree contains no `.baton-legs`.

### Exit criteria

- [ ] under `forge` the rounds are the PR conversation, with no file anywhere
- [ ] under `branch` the rounds live on `baton-legs/<ticket>`, the addresser answers there, and no
      counted review or adjudication reads it
- [ ] no round ever reaches the work branch or the default branch
- [ ] the kit runs the round-trip with no forge
