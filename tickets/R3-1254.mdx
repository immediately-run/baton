### Why

baton#10 states four liveness properties but could not check them: Apalache does not support
fairness, and TLC on `small` explored 8,187 distinct states (971 million generated) in 28
minutes without finishing — each `syncRead` picks any barred-tag set per ticket, so a state has
thousands of successors. And the blocks amendment (docs#213, now §6.1–§6.4) adds blocks, decisions, queues and notices, whose
safety and liveness the model does not yet cover.

### What to build

1. **A liveness instance** (`live` in `instances.qnt`): one ticket, two runners, one sync slot,
   the sync's barred tags drawn from two fixed sets, git and owner budgets of 1. TLC checks
   `fencesClear`, `endsResolveWithOwner`, `barsLiftClaimable` and `readyIsClaimed` (as rewritten
   in baton#10's rounds 2–3) to completion; CI runs it if it stays under 10 minutes, else
   nightly. Add **`endsResolveBySync`**: under fairness of the sync cycle and with no owner act,
   every completed end whose evidence landed in git is eventually confirmed (baton#10 3-A-2). From the
   adjudication of 3-A-0: make `fencesClear` exercise `fenceCleared` (today every fence times
   out or is pushed past the horizon, so a mutant breaking only `fenceCleared` passes — add
   fairness of a live fenced runner's heartbeat or a property of its own); state
   `readyIsClaimed` so it survives two tickets (a runner holding the other ticket forever);
   and give `ownerResolve` the owner budget.
2. **Blocks** (R-BTN-75): `blocked_since` as a function of rows and next legs; invariants — a
   ticket with a free next leg is not blocked; a `ticket` or `decision` block is never claimed
   past (gate ghost); an `unblocked` event only follows a `blocked` one.
3. **Decisions and notices** (R-BTN-78, R-BTN-80): a decision posted and answered by syncs;
   couriers claim, crash (lease lapse), mark sent or failed. Safety: no notice for a closed
   decision is marked sent; liveness: under fairness of each courier's claim, every open
   decision's notice is eventually sent to every registered courier.
4. **Queues** (R-BTN-79): depths and full stations over `roadmap-pr`'s course with
   `max_queue` on `fix`; invariant — depth equals the unheld tickets waiting; liveness — the
   review ⇄ fix loop with both bounded never deadlocks (advice only).
5. **Regressions** for every finding docs#213's gate fixed that the model can express.

### Tests

- `npm run model` gains the new invariants and regression runs; the liveness run as above.

### Exit criteria

- [ ] TLC proves the four liveness properties on `live` to completion
- [ ] blocks, decisions, notices and queues modelled, with their invariants holding in simulation and Apalache's depth-5 proof
- [ ] `model/README.md`'s *Checked how* table updated

_2026-10-19 — part 2b, decided at claim (branch `claude/R3-1254-model-capabilities`). Core's
side, mapped first: capability rows (`fleet_capabilities`, `Blocks.recount`), rule 4 on the
ticket's `requires`, resource rows with readings and the fleet answer, and `answer_lost` are
built (R3-1251); a leg's own `requires.capabilities` and `released:blocked` are not (B-10,
B-21). The model:_
- _**Liveness.** Baton records each runner's last heartbeat and a stored live set (core's
  `fleet_live`); an idle runner heartbeats too. A runner is live while its last heartbeat is
  within `TIMEOUT`._
- _**Capability rows** are stored, whole-ticket, and rewritten only where R-BTN-75 says the
  counts change: a heartbeat that changes what a runner declares (its check failing or passing
  again), the alarm noticing a runner stop being live, a force-reap, and a `capability` blocked
  end, which drops the capability from the runner's declared set in its transaction. A leg's own
  list is not modelled until B-10 builds it: it joins the ticket's for that leg, the same check._
- _**Rule 4** at the claim and at each advance: the ticket's `requires` within what the runner
  declares and is granted._
- _**Resources** as one `service` instance per resource, its reading `unavailable` until a
  lapse or `available`; account and runner instances, the administrator's precedence and
  `unknown` are not modelled (each a choice of which reading is in force, with no interleaving
  of its own). A `resource` row is advice: it counts toward `blocked_since` and gates nothing;
  a `resource` blocked end stores its reading and an `end`-sourced need._
- _**`answer_lost`** as R-BTN-77 states it: a row that goes because the live fleet emptied
  clears `blocked_since` silently and is remembered; settled, it logs the owed `unblocked`, or
  is written again silently; any logged transition ends it._
- _**`small`**, the proof's instance, keeps no capability requirements and no needs, so the
  depth-4 proof's cost does not grow; `sim` and the regression runs carry them. A force-reap
  changes no runner's liveness — core marks a runner reaped only when it is already silent past
  its lease, and the alarm's live-set check recounts for that as for any lapse — so it
  recounts nothing in the model either. (B-44, filed for it on the first reading, was
  withdrawn.)_
