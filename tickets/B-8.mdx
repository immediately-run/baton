**Brief:** the owner, 2026-10-16 and 2026-10-17, as specified by B-1 (baton#43).
**Spec:** `spec/BATON_SPEC.md` §2m.4 (R-BTN-117), R-BTN-13, R-BTN-57 and R-BTN-58 as amended, §2m.7a's grants and settings rows.

### Why

§2m is agreed and specified; this ticket builds its part of it.

### What to build

1. `baton owner token create --ttl --max-tier --role worker|courier [--asks]` and the registration route; a credential never exceeds its token and dies with it.
2. API keys in `Authorization` on every call, including the push and stream upgrades; 7 days idle ends one; refused in any other role.
3. `api_keys: false` refuses an API-key worker at its next call.
4. The migration: grant each legacy key what it declared on repositories it used in 30 days, each listed under **Needs you**.

- **Pending grants** *(added 2026-10-18 by BATON_SPEC R-BTN-146)*: the grants this migration writes for `BATON_KEYS` seed keys are written with `accepted_at` set to the migration's time, so no migrated machine stops; a seed key migrated onto two or more repositories lands at span 2, with sync and courier off, and the release notes say so.

### Do not

- Store an API key in clear: keep a hash.

### Tests

- S-BTN-69; G-BTN-94.
- `npm test`, `npm run typecheck` and `npm run check:spec` green.

### Exit criteria

- [ ] the scenarios above pass on both hosts, with their traces replayed through the model where they touch the core
- [ ] merged under the review gate
