**Brief:** the owner, 2026-10-16 and 2026-10-17, as specified by B-1 (baton#43).
**Spec:** `spec/BATON_SPEC.md` §8.2 (R-BTN-117, R-BTN-146), §11.1 (R-BTN-13, R-BTN-159), §11.2
(R-BTN-57, R-BTN-58), §13.2's `registration_tokens`, §14's token, register and settings rows;
`spec/BATON_SPEC_HISTORY.md`, Migrations: the bearer-key migration.

### Requires

None: a checkout and a terminal.

### Why

A cloud session has no key of its own to sign with, and an owner should not hand it one.
Registration tokens let the owner scope what such a session may become; R-BTN-159's API keys
(built, S-BTN-126) give it a credential it can hold.

### What to build

1. **Tokens.** `baton owner token create --repo <id> --role runner [--capabilities …]
   [--max-tier <t>] [--ttl <d>] [--uses <n>]` and `baton owner token revoke`, in a new
   migration adding `registration_tokens`. `runner` is the only role: there is no `courier` role
   and no `--asks` (a forge courier registers through `baton owner courier add`, R-BTN-115).
   `--uses` defaults to 1, at most 100; TTL defaults to 7 days, at most 30. Shown once as
   `brt_<id>_<secret>`, stored as its SHA-256, valid in the minting tenant only.
2. **Registering.** `baton runner register --token <t> --name <name> [--key ssh | --key api]`
   (`POST /v1/register`) creates a runner credential with a grant inside the token's scope,
   never wider and never `human-operator`; registering is acceptance (R-BTN-146). A name bound
   to another live credential is `conflict`; renewing one's own name is a re-key that spends no
   use. Each registration is an `admin` event; more than 10 by one token in 24 hours raises
   `baton.token-burst`. The credential lasts until the token's `grant_ttl` or 7 days without an
   authenticated call; revoking the token revokes every credential it registered.
3. **API-key runners.** Bearers work on the push and stream upgrades as on every other
   `/v1/runner/*` route. The repository setting `api_keys: false` (R-BTN-66, default `true`)
   refuses an API-key runner at its next call, and MCP keys (B-25). An API-key runner credential
   lives at most 90 days.
4. **The migration** (history, "Bearer-key migration"): the bearer tokens and `BATON_KEYS` seed
   keys the code accepts become API-key runner credentials, granted on each repository they
   heartbeated or claimed on in the 30 days before, with the capabilities they declared there
   and `accepted_at` set to the migration's time, so no migrated runner stops. A seed key so
   granted on two or more repositories lands at span 2 with sync off, and the release notes say
   so. Each migrated grant is raised for its owners to confirm or revoke (through today's
   listing if B-57 has not landed). Bearer tokens and `BATON_KEYS` are refused once the
   migration has run.

### Do not

- Store a token or an API key in clear: keep a hash.
- Add a `courier` role, flag or scope: forge couriers have their own credential kind.
