**Brief:** `docs/context/design-brief.mdx`, written in R3-1248's landing for iterating on Baton's web UI with Claude Design: what the dashboard is for, who reads it, what it shows, and the constraints a design must keep.
**Spec:** `spec/BATON_SPEC.md` §14 (the dashboard), as amended by §2m (**Needs you** by severity, the leg stream and **Stop leg**, session links); §10.4 (text, never markup).

### Why

The brief exists, but no ticket takes it through a design to a dashboard that implements it.

### What to do

1. **Operator.** The owner iterates on a design with Claude Design from the brief, then exports or links the result.
2. Turn the agreed design into implementation tickets with `npm run ticket -- new`, citing §14. Each change must keep §10.4: values are set through `textContent`, and the dashboard loads no remote resource.
3. Update the brief with whatever the design settled.

### Do not

- Implement before the owner has agreed a design: the brief is the input, not the design.

### Tests

- The tickets filed cite §14 and the design; `npm run check:wiki` is green.

### Exit criteria

- [ ] a design agreed by the owner, linked from the brief
- [ ] its implementation tickets filed
