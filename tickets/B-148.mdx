**Brief:** the owner, 2026-10-31: leg-to-leg state must never reach the default branch, with a
convention a check can verify; after two adversarial reviews of an in-branch design, "per-ticket
side branch is fine". Recorded in `spec/BATON_SPEC_HISTORY.md` (baton#148).
**Spec:** R-BTN-190 (leg state on a per-ticket side branch), R-BTN-131 (the standard courses),
R-BTN-163 (core `notify` conditions), §12.3 (untrusted text); S-BTN-193, G-BTN-166.
**Depends on:** none. B-101 writes the review rounds; B-140 builds the merge runner's refusal, the
`pre-receive` rule and the protection checker's reading.

### Requires

A docs checkout beside this one: the sync is vendored from docs, so its change lands there first.

### Why

B-101 needs somewhere for review rounds that is not the PR branch: on the work branch they move the
reviewed head and blur who wrote what. The side branch keeps the work branch clean on every forge
and on plain git.

### What to build

1. **The branch and the course check.** The runner derives a ticket's leg-state branch as its work
   branch's name plus `--legs`; the course validator refuses a course whose `branch_pattern` does
   not match it.
2. **Writing.** A leg writes only `.baton-legs/<ticket>/<leg>/<claim nonce>/…`: mode `100644` blobs,
   segments matching `^[a-z0-9][a-z0-9._-]{0,63}$`, none case-folding to `claude.md`, `agents.md`
   or `opencode.json`; it commits and pushes to the leg-state branch, never to the work branch.
3. **Reading.** A leg fetches the leg-state branch and reads it with `git cat-file`, never checking
   it out; entries outside the layout are skipped and reported; what it reads reaches the agent
   only as quoted data (§12.3). A leg its course marks `approves: true` reads nothing from it.
4. **Closing.** The leg that closes the ticket, and its withdrawal, delete the leg-state branch.
5. **Detection.** The reading of the default branch's tree for an entry that folds to
   `.baton-legs`, posted as a count and the ticket ids among its subdirectory names, never paths
   (R-BTN-33); core raises `baton.leg-state-landed`. Where the repository has a protection checker,
   only its reading (B-140) raises and closes it; elsewhere the sync's does, and the condition says
   it is advisory. The sync is vendored from docs (`src/shared/batonSync.mjs`): its change is a docs
   PR first, then `npm run vendor` here.

### Do not

- Check the leg-state branch out, or load anything from it as configuration or instructions.
- Let an `approves: true` review read it.
- Merge it, or write leg state to the work branch.

### Tests

- **S-BTN-193** on both hosts; G-BTN-166.
- Unit: the branch name and the validator; the layout and name rules; `cat-file` reading with no
  working-tree file created.
