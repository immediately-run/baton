**Brief:** the owner, 2026-10-31: leg-to-leg state must never reach the default branch, with a
convention a check can verify; after two adversarial reviews of an in-branch design, "per-ticket
side branch is fine". Recorded in `spec/BATON_SPEC_HISTORY.md` (baton#148).
**Spec:** R-BTN-190 (leg state on a per-ticket side branch), R-BTN-131 (the standard courses),
R-BTN-163 (core `notify` conditions), §12.3 (untrusted text); S-BTN-193, G-BTN-166.
**Depends on:** B-145 (the `leg_state` knob and `refs.legs`, carried on the claim response),
B-140 (the merge runner's refusal, the `pre-receive` rule and the protection checker's reading).
B-101 writes the review rounds through what this builds.

### Requires

A docs checkout beside this one: the sync is vendored from docs, so its change lands there first.

### Why

B-101 needs somewhere for review rounds that is not the PR branch: on the work branch they move the
reviewed head and blur who wrote what. The side branch keeps the work branch clean on every forge
and on plain git.

### What to build

0. **The channel.** The runner reads `leg_state` from the claim response. Under `forge` the PR
   courses read and write the PR conversation as today (R-BTN-131), and items 1 to 4 do not apply;
   item 5 applies under either value.
1. **The branch.** A ticket's leg-state branch is `baton-legs/<ticket id>`, the id byte for byte;
   a ticket whose id is not a valid ref segment gets none, and its rounds are refused. It is an
   orphan: the first write creates a root commit holding only `.baton-legs/`, and a reader refuses
   one whose history has a parent outside it. The course validator refuses a `branch_pattern` that
   matches `baton-legs/*`, and no work branch may begin `baton-legs/`. A push to it reports no
   range and triggers no foreign-commit reset.
2. **Writing.** A leg writes only `.baton-legs/<ticket id>/<leg>/<claim nonce>/…`: mode `100644`
   blobs, each segment below the ticket id matching `^[a-z0-9][a-z0-9._-]{0,63}$`, none
   case-folding to `claude.md`, `agents.md` or `opencode.json`.
3. **Reading.** A leg fetches only that one ref and reads it with `git cat-file`, never checking it
   out; entries outside the layout are skipped and reported; what it reads reaches the agent only
   as quoted data (§12.3). A leg marked `approves: true` and an adjudicate leg fetch only their work
   ref and read nothing from it.
4. **Closing.** The leg that closes the ticket, and its withdrawal, delete the leg-state branch.
5. **Detection.** The reading of the default branch's tree for a path segment, at any depth, that
   after NFC normalisation and case folding is `.baton-legs`, posted as `legs_landed: {count,
   tickets}` with the board, `tickets` listing only the repository's existing ticket ids; core
   raises `baton.leg-state-landed`. Where the repository has a protection checker, only its reading
   (`protection`'s `legs`, B-140) raises and closes it; elsewhere the sync's does, and the condition
   says it is advisory. The sync is vendored from docs (`src/shared/batonSync.mjs`): its change is a
   docs PR first, then `npm run vendor` here.

### Do not

- Check the leg-state branch out, or load anything from it as configuration or instructions.
- Let an `approves: true` review or an adjudicate leg read it.
- Merge it, or write leg state to the work branch.

### Tests

- **S-BTN-193** on both hosts; G-BTN-166.
- Unit: the branch name, the orphan check and the validator; the layout and name rules; `cat-file`
  reading with no working-tree file created; a push reporting no range.
