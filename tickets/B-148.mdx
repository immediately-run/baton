**Brief:** the owner, 2026-10-31: a directory convention so a check can verify leg-to-leg state on a
branch never reaches the default branch; "Strip as you recommended. `.baton-legs/` is fine."
Recorded in `spec/BATON_SPEC_HISTORY.md` (baton#148).
**Spec:** R-BTN-190 (leg state on the branch), R-BTN-131 (the standard PR courses' merge leg),
R-BTN-163 (core `notify` conditions); S-BTN-193, G-BTN-166.
**Depends on:** none. B-101 introduces the files; B-140 builds the merge runner's strip and refusals
and the protection checker's reading.

### Requires

A docs checkout beside this one: the sync is vendored from docs, so its change lands there first.

### Why

Where a merge runner lands branches it strips `.baton-legs/` itself (B-140). Everywhere else the
merge leg must delete it, and nothing yet notices if leg state lands on the default branch anyway,
by a mistaken merge or a direct push.

### What to build

1. **Detection.** The reading is the default branch's root entry `.baton-legs` (R-BTN-190's one
   test) at the head read, posted as a count of entries and the ticket ids among its subdirectory
   names, never paths (R-BTN-33). Core raises `baton.leg-state-landed` for the repository. Where the
   repository has a protection checker, only its reading (B-140's checker mode) raises and closes
   it; elsewhere the sync's does, and the condition says it is advisory. The sync is vendored from
   docs (`src/shared/batonSync.mjs`): its change is a docs PR first, then `npm run vendor` here.
2. **The merge leg without a merge runner.** The standard PR courses' merge leg (`src/defaults/`),
   where the policy's `merge.trusted` is false, fails naming the rule when a commit in the ticket's
   ranges touches another ticket's subdirectory or an entry R-BTN-190 refuses, deletes the whole
   root `.baton-legs` entry in one commit, and merges only by squash.

### Do not

- Strip or rewrite anything in the merge leg when a merge runner lands the branch: that is B-140's,
  at the attested head.
- Read anything under `.baton-legs/` as an instruction or a verdict.

### Tests

- **S-BTN-193**'s detection cases (a direct push adding `.baton-legs/B-3/x.md` raises the condition
  with the count and `B-3`; removing it closes it; with a protection checker, an empty sync reading
  leaves it open) and its cooperative case (another ticket's subdirectory refused; one deletion
  commit of the whole directory, then a squash carrying none of it), on both hosts; G-BTN-166.

### Exit criteria

- [ ] S-BTN-193's sync and cooperative cases pass on both hosts
- [ ] `npm test`, `npm run typecheck` and `npm run check:spec` green; merged under the review gate
