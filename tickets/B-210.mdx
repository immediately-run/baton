**Brief:** the owner, 2026-11-09 (B-191): "A ticket page gathers every read about it: position
(station, path, queued leg), why it can't move (blocks, prerequisites), history with
input/output pointers, children, leg runs with transcripts and log dirs." The mockup's runner
cards' claim block (`workers.txt`) is this page's claim section; its Output name is text.

### What to build

1. **Sections** (`src/dashboard/screens/tickets/TicketPage.tsx`, one component per section
   under it), all declared to the polling layer together, every value through `Text` or
   `View`:
   - **Head**: qualified id, title, course, tier, tags, requires as chips, `web_url` as the one
     outward link (host shown), parent linking its page, the state mark and word.
   - **Position**: station, the path as stations and legs run with run ids, the queued leg and
     its `source` (course, route or decision; R-BTN-83) — from `ticket.show`; beneath it the
     lines `baton ticket route <ticket> <leg>` and `baton ticket adopt <ticket> …` as text
     (Decision 2a).
   - **Claim**: the mockup's block from `ticket.show.claim` — runner linking its page, leg,
     running for, the lease bar (claimed at to lease end, now marked, minutes left), deadline,
     attempt n of `max_runs` and `next_backoff_until`, `session_url` as a link only where the
     read passed it (R-BTN-113), `log_dir` as text with the `baton leg log <ticket> <leg>` line
     (R-BTN-128); then the earlier `attempts` with end reason and detail as text.
   - **Why it cannot move**: `blocks` (kind, ref linking a ticket or naming a capability, since,
     until) and `prerequisites` for the queued leg (`met`, `why`, `since`, `until`, `url` after
     the client's link rule, `found`), as a `<table>`.
   - **Open conditions and scope findings**: condition ids and types linking the Resolve page;
     scope findings (§12.9) with kind, target and ref as text (their acknowledgement is B-222's
     control).
   - **History**: `history` paged by `?before=` ("earlier" loads more), each row's kind, leg,
     run, reached, next leg, and its `inputs` and outputs as pointers: a `git:` or `s3://` URI
     as text with its digest, an `https://` URI as a link only when the client's `links.mjs`
     rule passes it with the repository's `web_base` and `link_hosts` from `repo.list` (§12.3).
   - **Children**: `ticket.children` with station and blocked, linking each.
   - **Leg runs**: for each leg the path names, `legs/{leg}/runs` — run, run id, runner, mode,
     started, ended, end, session link as passed, transcripts as repository paths (text),
     `log_dir` as text.
2. **Phone.** The sections stack at 375 px.

### What not to do

- No control here (B-222); no body; no state computed in the client; no log bytes.

### Trust

- **Every section** draws its read's text through `Text` or `View`; URIs become links only by
  the client's link rule; `session_url` only as the server passed it.

### Invariants

- **Log directories as text** (R-BTN-128); **session links only from `session_hosts`**
  (R-BTN-113); **text, never markup** (§12.3); **positions are Baton's** (R-BTN-39); **an owner's
  session, its repositories**.

### Tests

Under `test/ui/` with fixture reads: every section draws its fixture; `log_dir`, a `git:` URI and
an unlisted `session_url` are text; an `https://` URI under `web_base` is a link; the route and
adopt lines are text; a hostile title is text; the sections stack at 375 px.

### Exit criteria

- [ ] `/tickets/{ticket}` built with every section above, usable on a local Baton at desktop
      and 375 px.
- [ ] The tests pass; `npm test`, `npm run typecheck`, `npm run check:wiki` and
      `npm run check:tickets` are green.
