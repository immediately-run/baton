**Brief:** the Baton project.
**Spec:** `spec/BATON_SPEC.md` §8.1 (the sidecar, per harness: opencode), §9.9 (R-BTN-20: child sessions, the archiver; activity pairing by `callID`), §9.2 (the fence layers), §15 (S-BTN-4, -8; G-BTN-15, -26, -27); the reviewer-spawn denial is docs' `BATON_ROADMAP_PR_COURSE`; the spike (R3-1210)
**Depends on:** R3-1213, R3-1210

### Requires

- none — the fake harness covers both shapes. If the spike found the archiver outside the
  repo, its change is the spike's recorded fallback and not part of this item.

### Why

Most of the fleet runs opencode. The sidecar from R3-1213 is harness-neutral; opencode needs
its plugin, and reviewer child sessions must not register as runners. Tier: critical —
fencing on the main harness.

### What to build

1. A plugin in the shared `.opencode/` config with the R3-1213 hooks' behaviour on its
   session, `tool.execute.before` (deny), after, error and prompt events.
2. `.opencode/agents/review-pr-claude.md` launches `claude -p` with `IR_BATON_PARENT` and
   `IR_BATON_ACTIVITY`; the opencode reviewer spawn passes the same to child sessions.
3. The opencode archiver appends its paths to the spool (from the repo if the spike found it
   there).

### Architecture — the decisions, named

- The plugin calls the same `scripts/hooks/baton-*.mjs` logic through a thin adapter, so the
  two harnesses share one implementation of the matchers and fence checks.
- **Do not:** duplicate the matchers in the plugin; let a child session start a sidecar.

### Tests

- Integration: `S-BTN-4.hung-worker` and `S-BTN-8.no-new-work` with the opencode-shaped fake
  harness; G-BTN-26 (a `claude -p` child with `IR_BATON_PARENT` registers no runner and its
  transcript lands on the parent's `reviewer` activity); G-BTN-15 and G-BTN-27 for opencode.

### Exit criteria

- [ ] `npm run test:baton` passes, including the opencode variants of `S-BTN-4` and `S-BTN-8`
- [ ] `grep -n "IR_BATON_PARENT" .opencode/agents/review-pr-claude.md` matches
- [ ] `npm run verify` green
