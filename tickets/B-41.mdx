**Brief:** the owner, 2026-10-19 (this session): "Can you please verify that we do not have a set
of overlapping primitives for legacy reasons in the course schema?", then "file the ticket with
the spec amendment". The audit found five ways in for a ticket waiting on other tickets, three
for a person and two for `human-operator`.
**Spec:** `spec/BATON_SPEC.md` §6.1 R-BTN-120 / R-BTN-132 (one way in per kind of prerequisite),
§4.6 R-BTN-86 (children; an open child blocks only through a call), §7.6 R-BTN-165 (call legs),
§6.4 R-BTN-116 (person legs), §5.8 R-BTN-131 (the standard courses, `build-app` on calls), §6.6
rules 4 and 6; §1 R-BTN-33 and §4.2 R-BTN-74 (the markdown source's `prs` and `answer` are sync-local
`fields`, never posted; a ticket's `course` is `{}`); history, "Migrations the implementation still carries" (R-BTN-132's window, and
"Course fields the schema review removed" for `build-app`); §15 S-BTN-108, G-BTN-127. The
amendment landed with this ticket; this ticket builds it.
**Depends on:** B-10 (leg `requires.tickets` and `depends_at`), B-7 (person legs, which replace
`waiting_on: owner`), R3-1258 (child tickets in core: `spawned` recorded as a run's children),
B-62 (call legs, which replace the fan-in).

### Requires

None: a checkout, a sibling docs checkout and a terminal.

### Why

Each overlap is a second place to look when a ticket does not move, and some change behaviour:
the parent's `blocked_by` fan-in blocks every leg, so a parent cannot work beside its children
(B-34), and `epic`'s `replan` cannot wait on its own children alone (R-BTN-124). Courses written now
(`build-app`, B-40) copy whichever form is nearest.

### What to build

Ordered by the window's phases (`cross_repo_migration`); each phase is its own PR, and only
phase 4 removes anything.

1. **Phase 0, core.** `ticket_requires` stores `human-operator`, and rule 4 checks it; rule 6
   keeps only the administrator-only grant (R-BTN-58). (`depends_at` and `requires.tickets` are
   B-10's.)
2. **Phase 1, dual-read in core.** A posted `blocked_by` id is read as a whole-ticket `ticket`
   block (`depends_at: {ticket, done: true}`); `operator_only` as `human-operator` in the clause;
   the labels `dependencies`, `children`, `owner` and `policy` from a station function are
   honoured as before. Each logs one `deprecated-field` event per repository and field per day.
   `spawned` writes no provisional row anywhere: an open child blocks its parent only through a
   call (R-BTN-86, G-BTN-76), so a parent's other legs stay ready beside its children.
3. **Phase 2, writers.**
   - `src/defaults/tickets-markdown.ts`: `depends_on` → `depends_at` on the course's
     `start_leg`; no child added to `blocked_by`; `OP` → `human-operator` in `requires`.
   - **`prs` and `answer` stay in the sync** (R-BTN-33, R-BTN-74, adv-1 M4): the markdown
     source stops posting them in the opaque `course` field (today `course: {prs, answer}` in
     `src/defaults/tickets-markdown.ts`) and returns them as the ticket's sync-local `fields`,
     which `src/defaults/cli.ts` hands to the station functions and strips from the board post;
     the posted `course` is `{}`. The readers move with it: `course-pr.ts`'s `prs` (`prRefs` over
     `t.course.prs`) and `courses.ts`'s `answer` read `t.fields`. No old-form read is kept —
     both ends are the CLI's own code and move in one PR.
   - `src/defaults/course-markers.ts` and `course-pr.ts`: no `dependencies` or `children`
     label (core now answers them).
   - The standard courses, each a new version that replays its in-flight tickets (R-BTN-48,
     `baton course test` against the live board):
     - `build-app`'s `file` and `verify` become call legs (B-62) with `"spawns": {"course":
       "*"}` and the completion tables §5.8 gives, replacing `buildAppWaits`' `children` wait;
     - `build-app`'s four approvals, `decision`'s answer and `create-pr`'s `owner`
       adjudication become person legs (B-7), replacing `waiting_on: owner`;
     - `file.md` writes `requires: [human-operator]`, not `tags: [OP]`.
   - docs `.baton/tickets.mjs` (a docs PR): `OP` as `human-operator`; `blocked_by` is already
     empty there, and `dependsOn` becomes `depends_at`.
4. **Phase 3, drain.** Each repository whose snapshot still carries an old form is raised for
   its owners (a `baton.<sub>` notify condition, R-BTN-163, once B-57 lands; today's Needs-you
   path before).
5. **Phase 4, cutover (its own PR, after the drain shows none).** The board-post validator
   refuses `blocked_by`, `operator_only` and the reserved labels, naming the ticket; a new
   migration stops storing `tickets.depends_on`, `tickets.blocked_by` and
   `tickets.operator_only`.

### Do not

- Translate `depends_on` to every leg: in-flight tickets have only ever waited at the start.
- Rename the posted `requires` field, or touch `needs` and `requires.resources` (R-BTN-120's
  "pairs that join": not overlaps).
- Give a non-call leg a wait on children, or add a `children` selector: the validator refuses any
  `select` but `parent` and `posted` (B-10).
- Drop `waiting_on`: forge effects (an author's push, CI) have no kind and get none.
- Edit an old migration: the schema change is a new numbered file.

### Tests

- **S-BTN-108** on both hosts, its trace replayed through the model.
- Unit: the source's translations; a ticket with `prs:` and `answer:` posts `course: {}` and no
  `fields`, while its station function still sees both (`test/unit/tickets-markdown.test.ts`,
  `test/unit/course-pr.test.ts`); a `spawned` end writing no block, the parent's other leg
  ready beside its open children; rule 4 refusing an ungranted `human-operator`; the validator
  refusing each reserved label after cutover.
- S-BTN-104's and S-BTN-107's tests: their `waiting_on: owner|children` assertions become the
  person legs' decision blocks and the call legs' `call` blocks.
- `baton course test` on each standard course's new version against a board with tickets
  mid-course on the old one.
