**Spec:** `spec/BATON_SPEC.md` §9.9 (activities: skill-declared phases), §16.1 R-BTN-28 (shadow reports, `POST /v1/runner/shadow-report`), §16.2 step 2, §15 S-BTN-10; docs' `BATON_ROADMAP_PR_COURSE` (catalog frontmatter, substitution, seats; R-BTN-27; G-BTN-29, -30) and `BATON_DOCS_DEPLOYMENT` §15 (the rows for `claim.sh`, the skills and the agents)
**Depends on:** R3-1205, R3-1211, R3-1213

### Requires

- none.

### Why

Shadow week needs `claim.sh` to report every transition, the skills to mark their phases, the
reviewer agents to declare what they review on and bill, and the gate to take its seats from
the one function that also decides matching. Tier: critical — the review gate's invariant.

### What to build

1. `claim.sh claim` and `set --status` report the transition to `POST /v1/runner/shadow-report`
   after a successful push (best effort; a failure never fails the claim in shadow).
2. `next-roadmap-item` (both copies) and `review-gate` (both copies) call
   `baton-activity.mjs` at the phase boundaries (§9.9).
3. `reviews_on:` and `bills:` frontmatter on every `.opencode/agents/review-pr-*.md` and
   `adjudicator.md`, and `models:` where an agent spends a second model (`review-pr-claude`:
   a second model on another provider account), matching `scripts/data/reviewer-matrix.json`'s
   `agents` (R3-1205).
4. The opencode review gate takes its seats from `node docs/scripts/baton-seats.mjs --authors …
   --accounts <the session's declared accounts>` (required since R3-1205; the sidecar's state
   file holds the declaration) at round one and keeps them for the gate (docs' `BATON_ROADMAP_PR_COURSE`), with the `awaiting-review-capacity`
   release and the blocked-adjudicator packet.

### Architecture — the decisions, named

- `claim.sh` gains one function, `baton_report`, called after each successful push, with a
  5 s timeout and no retry; it uses the sidecar's state file for credentials and does nothing
  without one.
- The skill text keeps the matrix table (generated, R3-1205) for reading, but the gate's
  choice is the CLI's output, recorded in the `reviewer` activity's detail.
- **Do not:** let a shadow report change any exit code of `claim.sh`; edit the matrix by hand
  (run `baton-matrix-table.mjs --write`); bump `skills_version` in this item — it starts at 1
  with these protocol files listed.
