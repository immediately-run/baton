**Brief:** the owner, 2026-10-22, after the B-86 leg held a claim in `implement` for five hours
past the agent's last output: "the runner is responsible for detecting that the agent has
completed its work and wont exit. The baton server has no role in this."
**Spec:** §5.8 R-BTN-131 (the stubs and `agent_command`) as amended by B-84 ("the command's exit
is the agent's completion, which its own contract requires it to mean") — this ticket amends
R-BTN-131 again: an agent's completion is its **exit or its silence**, whichever comes first.
§8.3 R-BTN-72 (the runner: the leg child and its waiting); B-23 (the runner's leg-output
archive) is the same piping, arriving with it. **The amendment is this ticket's first
deliverable.** No §7 condition, no R-BTN-90 deadline: the owner's decision is that this failure
mode is detected and settled entirely in the runner's kit — `baton.stalled` keeps whatever
scope §7's own review leaves it, none of it here.

### What to build

1. **The spec amendment** (R-BTN-131): beside B-84's exit contract, the stub's wait for the
   agent ends at the earlier of the agent's exit or an idle bound on its output — the bound a
   constant of the stub, named like `CLOSE_TIMEOUT_MS` with its reason in the comment.
2. **The stub streams what it now accumulates.** `execFile`'s callback hides the stream; the
   stub spawns the agent with `spawn`, drains and timestamps stdout (the answer protocol reads
   the last line either way), and closes stdin at once as B-84 does. An agent still writing is
   never touched, however long it runs.
3. **Idle past the bound: conclude.** The stub kills the agent (it is the parent; SIGKILL to
   the child alone), takes the received stdout as the agent's output, and proceeds exactly as
   an exit would: the last-line contract for a leg that asks, B-81's forge verify for
   `implement`. The kill is recorded in the leg's result (`agent_concluded_idle`) so the close,
   the marker and the review round can see how the leg ended.
4. **The runner's liveness line** stays as filed here: while a leg runs, each beat logs its
   duration and the age of its last output — the operator watches the wedge form instead of
   silence. `start-runner.sh`'s outside watch (2026-10-22) keeps watching; with 2 and 3 it
   becomes the backstop, not the detector.

### Do not

- Give Baton any part of this: no condition is raised, no deadline taken, nothing posted —
  the server learns the leg ended as it learns every leg, by the claim's end (the owner's
  decision, 2026-10-22).
- Conclude an agent that is still writing: the bound is on silence, never on duration.

### Tests

- Unit: an agent that prints, goes silent past the bound and never exits — the stub concludes,
  its output is the received text, the result records `agent_concluded_idle`, and the forge
  verify runs as after an exit.
- An agent that keeps printing at a slow cadence — never concluded, however long.
- The ask-leg contract over concluded output: the last received line is the answer, or the
  leg fails naming it.
- The B-86 shape replayed end to end: PR open, agent silent, stub concludes, `pr-open`.

### Exit criteria

- [ ] a finished-but-never-exiting agent costs its claim minutes, not hours, with no server
      change at all
- [ ] an agent that is still producing is never killed, whatever its duration
