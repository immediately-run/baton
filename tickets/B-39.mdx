**Brief:** continues R3-1257 (split 2026-10-19). The owner, 2026-10-15: legs that read each other's outputs need those outputs named, typed and found again; failures should name the producer; a past run should be re-runnable.
**Spec:** `spec/BATON_SPEC.md` §2h R-BTN-82 (as amended 2026-10-17 by §2m: outputs are R-BTN-108's envelopes, checked by its one validator), R-BTN-84 (`baton leg replay`), R-BTN-78 (`baton:contract`), R-BTN-69 (a leg's `version`, `inputs`, `outputs`, `replay_safe`), §6.10 (`cannot-finish:contract-input` and `-output`), §6.13 (`ctx.inputs`, `close`), §4 (`leg_outputs`, `leg_run_inputs`, `run_inputs_by_ticket`, `repositories.artifact_buckets`), §10.4 (URIs and markers); §13a S-BTN-48; §16 G-BTN-74.
**Depends on:** B-3. §2m amended R-BTN-82 on 2026-10-17: an output is an envelope naming `id@version`, given by pointer or inline, checked by one shared validator. B-3 builds the envelope and the validator. Building R-BTN-82's original pointer contracts first would build the check twice.

### Requires

- none — every case runs in the integration harness with fixture course files and stub leg scripts, and a local git server for `git:` inputs.

### What to build

1. A course file's leg `version`, `inputs`, `outputs` and `replay_safe`, checked on acceptance (R-BTN-69).
2. URI validation (§10.4: the repository allowlist, `artifact_buckets`, the marker encoding, digests).
3. Inputs resolved at the advance that starts a leg. `input-missing`/`input-version` stored as `waiting` before the leg is offered. A foreign marker's outputs are never resolved.
4. `baton runner start` validates inputs before and outputs after the script, failing the leg `cannot-finish:contract-input` (held, `baton:contract` raised) or `contract-output` (a failed attempt). The closing marker is written only from a validated result. `ctx.inputs` is set.
5. `inputs`/`outputs` history rows (R-BTN-81, built by R3-1257).
6. `baton leg replay [--run n] [--against sha]` with write credentials withheld; `replay_safe: false` refused.
7. `baton course test`'s dataflow and version checks.

### Tests

- Integration, both hosts: S-BTN-48.
- Unit: `contracts.test.ts` (resolution, version checks, URI validation and marker decoding) and the CLI's schema-check and replay tests.
