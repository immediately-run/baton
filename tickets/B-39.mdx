**Brief:** continues R3-1257 (split 2026-10-19). The owner, 2026-10-15: legs that read each other's outputs need those outputs named, typed and found again; failures should name the producer; a past run should be re-runnable.
**Spec:** [BATON_SPEC §5.5](../spec/BATON_SPEC/05-courses.md#sec-5-5) [R-BTN-82](../spec/BATON_SPEC/05-courses.md#sec-5-5) (outputs are [R-BTN-108](../spec/BATON_SPEC/05-courses.md#sec-5-5)'s envelopes, checked by its one validator), [§9.8](../spec/BATON_SPEC/09-claims.md#sec-9-8) [R-BTN-84](../spec/BATON_SPEC/09-claims.md#sec-9-8) (`baton leg replay`), [§7.3](../spec/BATON_SPEC/07-conditions.md#sec-7-3) [R-BTN-163](../spec/BATON_SPEC/07-conditions.md#sec-7-3) (`baton.contract`), [§5.2](../spec/BATON_SPEC/05-courses.md#sec-5-2) [R-BTN-69](../spec/BATON_SPEC/05-courses.md#sec-5-2) (a leg's `version`, `inputs`, `outputs`, `replay_safe`), [§9.7](../spec/BATON_SPEC/09-claims.md#sec-9-7) and [§7.4](../spec/BATON_SPEC/07-conditions.md#sec-7-4) [R-BTN-122](../spec/BATON_SPEC/07-conditions.md#sec-7-4) (`cannot-finish:contract-input` and `-output`), [§8.3](../spec/BATON_SPEC/08-runners.md#sec-8-3) [R-BTN-72](../spec/BATON_SPEC/08-runners.md#sec-8-3) (`ctx.inputs`, `close`), [§13](../spec/BATON_SPEC/13-data-model.md#sec-13) (`leg_outputs`, `leg_run_inputs`, `run_inputs_by_ticket`, `repositories.artifact_buckets`), [§12.3](../spec/BATON_SPEC/12-security.md#sec-12-3) (URIs and markers); [§15](../spec/BATON_SPEC/15-verification.md#sec-15) [S-BTN-48](../spec/BATON_SPEC/15-verification.md#scenarios), [G-BTN-74](../spec/BATON_SPEC/15-verification.md#gates).
**Depends on:** B-3. Under [R-BTN-82](../spec/BATON_SPEC/05-courses.md#sec-5-5) ([§5.5](../spec/BATON_SPEC/05-courses.md#sec-5-5)) an output is an envelope naming `id@version`, given by pointer or inline, checked by one shared validator. B-3 builds the envelope and the validator. Building the earlier pointer-only contracts first would build the check twice.

### Requires

- none — every case runs in the integration harness with fixture course files and stub leg scripts, and a local git server for `git:` inputs.

### What to build

1. A course file's leg `version`, `inputs`, `outputs` and `replay_safe`, checked on acceptance (R-BTN-69).
2. URI validation (R-BTN-82, §12.3: the repository allowlist, `artifact_buckets`, the marker encoding, digests).
3. Inputs resolved at the advance that starts a leg. `input-missing`/`input-version` stored as `waiting` before the leg is offered. A foreign marker's outputs are never resolved.
4. `baton runner start` validates inputs before and outputs after the script, failing the leg `cannot-finish:contract-input` (held `non-retryable:contract-input`, raising `baton.contract`) or `contract-output` (a failed attempt). Landing before B-56, `baton.contract` is raised through R3-1257's Baton-raised decision path, which B-56 converts to the `suspend` core condition. The closing marker is written only from a validated result. `ctx.inputs` is set.
5. `inputs`/`outputs` history rows (R-BTN-81, built by R3-1257).
6. `baton leg replay [--run n] [--against sha]` in R-BTN-144's replay environment (write credentials withheld; the model provider's key only where `replay_env` or `--env` names it), its report masked as a leg's output is (classes 1–7); `replay_safe: false` refused.
7. `baton course test`'s dataflow and version checks.

### Tests

- Integration, both hosts: S-BTN-48.
- Unit: `contracts.test.ts` (resolution, version checks, URI validation and marker decoding) and the CLI's schema-check and replay tests.
