### Requires

- `baton-worker` — exit criteria 1–3: a session registered with Baton (a worker token for its
  host and a running sidecar) on a fleet VM.

### Why

The integration suite proves Baton against a fake clock and a bare repo; this proves the
deployed service, the real mirror and a real fleet worker agree after cutover.

### What to build

A verification run from one fleet VM session, about an hour of wall time (most of it the
15-minute lease timeout), and a note `content/plans/baton/cutover-verify.mdx`.

### Architecture — the decisions, named

- Use a dedicated Verify item as the claimed item, so nothing real is disturbed.
- **Do not:** repair a failure here; file a BUG item in `baton` and leave this item open.

### Tests

None to write.

### Exit criteria

- [ ] **live leg** (`baton-worker`): `claim.sh claim` goes through Baton; the mirror's `roadmap: claim` commit appears within 2 minutes with the claim's time as author date, and `node scripts/check-roadmap-claims.mjs` and `node scripts/factory-state.mjs` read it
- [ ] **live leg** (`baton-worker`): a second session is refused the same item with `not-eligible`
- [ ] **live leg** (`baton-worker`): with the sidecar killed, the claim is reaped at 15 minutes, the item is re-issued, and the old session's `git push` to its item branch is refused
- [ ] `npm run verify` green
