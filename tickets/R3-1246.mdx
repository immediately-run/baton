**Spec:** `docs/content/specs/BATON_SPEC.mdx` §6.13 (R-BTN-72), §6.12 (the leg table, R-BTN-38,

**Depends on:** R3-1245, R3-1234

### Requires

- none — the scripts are tested with a stub harness; R3-1245's scenario runs them for real.

### Why

`baton run` runs each leg through `.baton/courses/roadmap-pr/legs/<leg>.mjs`; docs has none.
Tier: judgement — five small scripts over one convention.

### What to build

1. `legs/implement.mjs`, `review.mjs`, `fix.mjs`, `adjudicate.mjs`, `merge.mjs`: each starts
   the agent session on its leg's section of `next-roadmap-item` (`claude -p` or `opencode
   run`, from the worker's harness), resuming the previous leg's `session` when the advice
   keeps the model and starting fresh when it moves the leg to another.
2. `review.mjs` returns `next: fix | merge | adjudicate` from the round's outcome (open
   findings and the run count), read from the PR the round just reviewed.
3. Each exports `handoff(ctx)`, posting the `baton:handoff` comment with BATON_SPEC R-BTN-44's
   sections, written by the session before it stops.
4. The scripts honour `ctx.signal`: on abort they kill the session they started.

### Architecture — the decisions, named

- **A script is a launcher, not logic**: what a leg does is the skill's text (R3-1234); the
  script picks the harness and the session, and reads one git fact where the graph branches.
- **Do not**: write evidence from the script (the session does); hard-code a model (the
  advice chooses); add a per-course module above the legs.

### Tests

- `scripts/lib/courses/roadmap-pr/legs.test.mjs`: each script with a stub harness — the
  command it runs, session reuse, `review`'s `next` for a clean round, open findings, and the
  third round.
