**Brief:** the owner, 2026-10-22: "credentials are capabilities: an anthropic api key is what
enables a runner to execute an opus review." "Course legs specify a high-level capability like
code-generation-llm, while the runners know they have an API key for OpenCode Go and DeepInfra
and an instance of OpenCode 2 installed in the VM. Baton should never store the credentials,
but it needs to keep track of the ontology of how credentials map."
**Spec:** §5.9, R-BTN-174 (the ontology, its merge, matching, storage, why-not, credentials) and
R-BTN-175 (the language, its validation, bounds, evaluator, narrowing and conformance), with the
rules it amends: R-BTN-121's `derived` types, §6.6 rule 4 and the pipeline, R-BTN-75's
`fleet_capabilities`, and R-BTN-144's `via` credentials. The data model is in §13: `ontologies`,
`runner_derived`. The API is in §14: the claim's and advance's `via`. How the design got here,
and the review that shaped it, are in `BATON_SPEC_HISTORY.md` (Changelog, 2026-10-22; Review
record).

### What to build

1. **`src/core/ontology.ts`** (pure): parse, validate, stratify and evaluate R-BTN-175's
   fragment, with its bounds as counters, and record the first four derivations per atom. It
   is about 300–400 lines.
2. **Accepting a program.** The board post carries the merged program and its digest. Core
   validates it against the repository's courses' `derived` types, stores it in `ontologies`,
   and on refusal raises `baton.ontology-refused`, keeping the previous program.
3. **Storing the derived set.** Recompute `runner_derived` (with `via`) on heartbeat changes,
   grant changes and accepted programs, the last in alarm batches of 50. Rule 4's SQL,
   `isEligible` and `fleet_capabilities` read declared ∪ derived.
4. **Why-not.** R-BTN-174's canonical explanation goes in the blocks index and in `baton leg
   why`.
5. **The leg environment.** The claim and advance answers carry `via`. The runner keeps those
   credentials (R-BTN-144).
6. **Course code.** `src/defaults/ontology.json` (the built-in: model facts, `offers`,
   `usable_with`, the binding idiom), its JSON Schema, the sync's merge by entry id, and `repo
   init` scaffolding. R-BTN-121's `derived` key goes in the course-file validator.
7. **Conformance.** The translator `src/defaults/ontology-asp.ts`, fixtures under
   `test/fixtures/ontology/`, `test/unit/ontology-conformance.test.ts` on `clingo-wasm@0.6.0`
   (an exact devDependency), and the strict-syntax test.
