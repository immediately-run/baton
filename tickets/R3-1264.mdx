**Brief:** the Baton project; filed by R3-1253 (docs#217).
**Spec:** `spec/BATON_SPEC.md` §3.3 R-BTN-73 / R-BTN-95 (routes, events and fields, drops, which want); §3.1 R-BTN-138 and §3.4 R-BTN-140 (repositories and `code_repos` matched by id); §2.3 (admission: Worker-first checks); §12.1 (the forge notification principal); §14 (`POST /v1/forges/{repository}/notify`); §15 S-BTN-56 (the notification cases)
**Depends on:** R3-1263

### Requires

- none — deliveries are signed with test secrets in the harness.

### Why

GitLab, Gitea and App-less GitHub repositories need their reviews and pushes to trigger syncs
too. Tier: judgement — a trigger, verified before anything is read.

### What to build

1. `POST /v1/forges/{repository}/notify`: the verifier from `BATON_FORGE_SECRETS[repository].forge`
   — GitLab `X-Gitlab-Token` (constant time), Gitea `X-Gitea-Signature`, GitHub repository
   webhook `X-Hub-Signature-256` — in the Worker, before the body is parsed.
2. One parser per forge over its accepted events and fields (R-BTN-95), returning only them;
   no pipeline, job or workflow-run events from GitLab or Gitea; the mirror's push dropped by
   its author email; repeated delivery ids dropped (`webhook_deliveries`).
3. **Which want** (R-BTN-95): a delivery to `/v1/forges/{repository}/notify` records a want
   (R3-1263) for `{repository}` only, and only when its project — the parsed id
   (`project.id`, `repository.id`) — is `{repository}`'s own forge id or that of one of its
   `code_repos` entries (R-BTN-140, matched by id once stored; by path for a row registered
   before forge ids, until B-45's backfill). Any other delivery is dropped. Tickets' `repos:`
   play no part.

### Architecture — the decisions, named

- **The parser is the only code that touches a payload**, as `pickDelivery` is for the App.
- **Do not**: compute anything from a payload; accept an unsigned delivery.

### Tests

- Integration: S-BTN-56's notification cases, both hosts.
- `test/unit/forge-notify.test.ts`: each verifier, each parser with a recording payload, an
  unaccepted event, a code repository's delivery through a home repository's route, a delivery
  for a project that is neither the repository nor one of its `code_repos` (dropped), and a
  renamed project still matched by id.
