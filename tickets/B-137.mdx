**Brief:** the adversarial review of the security model (2026-10-27, findings 4 and 18): any
runner's machine key can post the board (R-BTN-102, `machine_sync` default `true`), and any leg
can read its runner's key (R-BTN-14, R-BTN-144). B-127's signature check and B-126's control-change
detection run in the sync, client-side, and R-BTN-139's trust marking runs in the CLI's fact
adapter. A compromised leg can therefore post a board that marks its own verdicts trusted, reports
no control change, and names an older commit as the one runners load. A key can also freeze the
board by holding observation numbers. None of this needs a push.

**Spec:** R-BTN-102, R-BTN-105, R-BTN-62 (observations), R-BTN-139, R-BTN-73 (push deliveries),
R-BTN-97; B-126, B-127; `docs/security-model.mdx` (reach 7, reach 8).
**Depends on:** none.

### What to build

1. **No machine-key posts below the human level**: on every repository with a runner below the
   human level, the policy's `inputs.board` excludes `machine` (the `protected` preset does; R-BTN-93,
   R-BTN-188), changed only by an approver on `approvers.policy`. Existing homes are switched by
   their owners now (`machine_sync: false` until B-145 lands).
2. **What Baton must trust, Baton computes.** Control-path changes (B-126) come from the push
   deliveries' `commits[].added/modified/removed` and `sender.id`, server-side; a missing delivery
   is `pusher-unknown`, fail closed. Signatures (B-127) are verified by Baton over the raw commit
   objects the sync posts, and again by each runner before it loads configuration.
3. **Rate limits per key**: observation numbers and board posts per key per hour, and an owner
   alert when a key holds observations repeatedly. Revoking the key releases its observation.
4. **The security model** names board posts as a reach and the denial of service a key can cause.

### Tests

- A scenario (the next free S-BTN number): a machine key posting a board that drops a control
  change is contradicted by the server's own reading of the delivery and raises a condition; a
  key posting faster than its limit is refused; with `machine` out of `inputs.board` a machine
  key's post is `forbidden`; and **S-BTN-187** (R-BTN-187: a station a trusted leg acts on is not
  reached from a git verdict under `inputs.answers: attestation`).

### Exit criteria

- [ ] `machine` out of `inputs.board` on every VM-runner home; S-BTN-187 and the scenario pass on
  both hosts
