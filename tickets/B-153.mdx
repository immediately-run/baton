**Brief:** the Baton project.
**Spec:** `BATON_SPEC` §8.1 (the sidecar table), §9.2 (the three fence layers, R-BTN-26), §9.9 (activity pairing)
**Evidence:** `content/plans/baton/hook-spike.mdx` in immediately-run/docs (R3-1210's findings note, PR
immediately-run/docs#224) — every claim below is a measured command and output there.

### Requires

- nothing beyond R3-1213/R3-1214's own resources; this item is the spec correction plus the fence's
  implementation guidance those two consume.

### Why

R3-1210 measured both harnesses on a fleet VM and found two spec cells wrong. Building R3-1213
(sidecar/fence) on them would make the fence quietly not fence: on opencode the deny hook never
fires, and on Claude Code a naive layer-1 group kill can kill the harness itself.

### What to build

1. **§8.1, opencode row, "Deny fenced commands".** The cell reads `tool.execute.before`; on the
   fleet's `v2.1.2-neumark.2` that hook does not exist upstream-style, `ctx.tool.hook("execute.before")`
   and `ctx.permission.hook("evaluate")` register but never fire in headless `opencode run`, and
   configured `permission` deny/ask rules do not gate headless runs (`git push --dry-run` executed
   under explicit deny with `--auto`). Amend the cell to the fallback §9.2 layer 2 already names:
   **wrapper scripts early on `PATH`** (`git`, `gh`) for the fenced commands, plus the git `pre-push`
   hook (§9.2 layer 3), with a note to re-measure when the fork grows a working pre-tool hook.
   §6.10's route advice likewise must not assume plugin interception on this harness.
2. **§9.2 layer 1.** "The sidecar terminates every process group the harness started for a tool call
   still running" — on Claude Code a *simple* command runs as a direct child **in the harness's own
   process group** (measured: `tool tail pid=2978757 pgid=2978755` where 2978755 *is* claude; killing
   the group killed claude), while compound commands get `bash -c` in their own session. Amend the
   wording: the sidecar enumerates the harness's descendants belonging to the call and kills those
   pids (or groups verified not to contain the harness). opencode needs no change — every call was
   its own group and session, and the group kill left the server alive (measured).
3. While in §8.1: the opencode "Start / stop" cell's session-end half is `session.execution.*` plus
   the existing 10 s harness-pid poll on this build (`session.idle` never fires in headless runs), and
   the Claude Code "Touch activity" cell must not promise a failure event — a nonzero-exit Bash call
   fires no PostToolUse and no other event (§9.9's claim-end close already tolerates it).

### Architecture — the decisions, named

- The wrapper on `PATH` is installed by the runner (R3-1213) into the leg session's environment, not
  into the VM globally; the pre-push hook is per-checkout (§9.2 layer 3 unchanged).
- The descendant enumeration on Claude Code reuses the sidecar's existing pid poll; it kills pids, and
  a group only after checking the group is not the harness's own.

### Tests

- Wrapper: a leg environment where `git push` resolves to the wrapper refuses with the ticket named,
  exit non-zero, and the refusal line reaches the transcript.
- Enumeration: given a fake harness pid with one own-group child and one shared-group child, the
  sidecar's killer kills both children and not the harness (unit test with a spawned process tree).
