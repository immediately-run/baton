**Brief:** the owner, 2026-11-23: "If possible, I would like to get rid of tiers entirely." The spec half landed in #391 (merged by the owner on 2026-11-23): gate 5 (`above-tier-ceiling`), the repository's `tiers` ladder, the heartbeat's `tier_ceiling` and `tier_ceilings`, the grant's `max_tier`, a ticket's `tier` in the board post and every read, `?tier=`, `ready_by_tier` and re-tier staleness are gone. This ticket builds it in Baton. The history's migration entry *Tier fields from older clients (2026-11-23)* is the plan's order and its end.

**Spec:** [BATON_SPEC §6.6](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-6) (gate 5 retired; [R-BTN-45](../spec/BATON_SPEC/01-what-baton-is.md#sec-1)), [R-BTN-66](../spec/BATON_SPEC/01-what-baton-is.md#sec-1), [R-BTN-35](../spec/BATON_SPEC/01-what-baton-is.md#sec-1) (staleness), [R-BTN-9](../spec/BATON_SPEC/08-runners.md#sec-8-1) (the heartbeat), [R-BTN-58](../spec/BATON_SPEC/11-people.md#sec-11-2) (grants), [R-BTN-74](../spec/BATON_SPEC/04-tickets-syncs-board.md#sec-4-2) (the markdown source), [R-BTN-127](../spec/BATON_SPEC/11-people.md#sec-11-3) (the CLI), §13 and §14; `spec/BATON_SPEC_HISTORY.md`, the 2026-11-23 changelog and migration entries.

**Depends on:** none. The docs-owned decision library (`isEligible`'s rule 5, `TIERS`, `fitsTier`) is retired by its own docs ticket; until it is vendored, stop calling it here rather than editing `src/vendor/`.

**Used by:** none.

### What to build

In this order: the server first, since an old server counts an untiered ticket as the top tier and refuses it to a capped grant.

1. **Server.**
   - Remove gate 5 from `src/core/gates.ts`, and `above-tier-ceiling` from the failed-rule order in `src/core/claims.ts`.
   - Remove the re-tier release in `staleBoard` (`claims.ts`).
   - Remove tier from the reads: the ticket's `tier`, the tickets list's `?tier=`, the board's and admin state's `ready_by_tier`, the runners read's `tier_ceilings`, the grants read's `max_tier`, and the repository reads' `tiers`.
   - Remove `tiers` from admin repository registration and change, and `max_tier` from grants.
2. **Transition.**
   - Accept and ignore, never validate: a board post's ticket `tier`, a heartbeat's `tier_ceiling` and `tier_ceilings`, a grant's `max_tier`, a registration's or change's `tiers`, and `?tier=`. A refused heartbeat gets a live runner reaped.
   - Each logs one `deprecated-field` event per credential and field per day, as `retiredBoardFields` (`src/core/board.ts`) does.
   - Refuse them `invalid-params` after 30 days with none.
3. **Migration.** A new numbered file in `src/migrations/` drops every tier column: the repository's `tiers`, the grant's `max_tier`, the runner's `tier_ceiling` and `tier_ceilings`, the ticket's `tier` and `tier_position`, and `ready_tickets.tier_position`. Rebuild what indexes them.
4. **CLI, runner and sources.**
   - Remove `--tier` (`src/runner/main.ts`, `sidecar.ts`), `--max-tier` and `--tiers`, and `--tier` from `ticket new`.
   - Stop `.baton/tickets.mjs` and `src/defaults/tickets-markdown.ts` posting `tier`.
   - Remove `tier` from `src/vendor/ticketPr.mjs`'s control fields, via its docs source and `npm run vendor`.
   - Remove the re-tier release from the trace checker (`scripts/check-traces.mjs`).
   - Fix `scripts/start-runner.sh`'s grant line (`--max-tier judgement`).
5. **Dashboard.** Remove `ByTier` (`BoardScreen.tsx`), the tickets screen's tier filter and the runner page's tier ceiling.
6. **Model and docs.** Update the Quint model's rules 4–7 (`model/baton.qnt`), the README and `docs/security-model.mdx`'s tier text.

### Trust

**No new input.** Every input this touches is removed or ignored:
- **A ticket's `tier`:** any pusher writes it, and now nothing reads it.
- **A runner's ceilings:** the runner declares them.
- **The grant's `max_tier`:** an owner's key set it.

**One loosening, which the owner accepted in #391:** removing `max_tier` widens every grant that set one below the top. Such a key may take every ticket its capabilities fit. Bering's keys were granted `--max-tier judgement` by the runbook. An owner who relied on the cap re-scopes the key by capability (§6.6 rule 4) before the deploy. Say so in the PR, and in the deploy's note.

### Invariants

- **[R-BTN-33](../spec/BATON_SPEC/01-what-baton-is.md#sec-1), filter fields only.** Nothing new is stored, and the migration only drops columns.
- **Migrations are append-only.** The drop is a new file.
- **A heartbeat is never refused for a retired field (§8).** The fields are ignored, never validated, so a runner on an old CLI is not reaped.
- **Gate numbers are stable (§6.6).** 5 stays unused, as 6 and 12 do.
- **G-BTN-40.** The SQL matches the decision library, so the SQL's rule 5 goes with the library's.

### Tests

- Update the scenarios the spec amended: S-BTN-24, S-BTN-39, S-BTN-69, S-BTN-260, S-BTN-296 and G-BTN-66. Drop tier fixtures elsewhere.
- **New: old fields are ignored.**
  - A heartbeat carrying `tier_ceiling: "nonsense"` is answered, not refused.
  - A post carrying `tier: "normal"` leaves the ticket claimable.
  - A grant with `max_tier` is accepted.
  - Each logs `deprecated-field` once a day.

### Exit criteria

- [ ] No `tier`, `max_tier`, `tier_ceiling`, `tiers` or `ready_by_tier` is read or written outside the transition's ignore path.
- [ ] A ticket that a `judgement`-capped grant refused before is claimed by that runner.
- [ ] `npm test` and `npm run typecheck` pass.
