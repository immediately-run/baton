**Brief:** the owner, 2026-10-16 and 2026-10-17, as specified by B-1 (baton#43).
**Spec:** `spec/BATON_SPEC.md` §2m.5 (R-BTN-118, R-BTN-119), R-BTN-33 and R-BTN-91 as amended, §11's stream rows.

### Why

§2m is agreed and specified; this ticket builds its part of it.

### What to build

1. Viewer upgrade: same `Origin`, a known running claim, `stream` not false, a session that may view it; else `forbidden`, ringing nothing.
2. Runner upgrade: only the claim's holder, after `watch`; a second connection replaces the first.
3. The channel enforces 8 KB frames and 64 KB/s, counting drops in `gap`; nothing stored, logged or exported.
4. **Stop leg** on the dashboard sends the release message; the runner stops the group within 30 s and ends `released:requested`.
5. **Tenancy** *(added 2026-10-18 by BATON_SPEC §3b, R-BTN-132)*: a stream's Durable Object is named through B-36's helper, `idFromName('baton/stream/<claim id>')`, never by the claim id alone, since claim ids repeat across tenants.

6. **Hardening** *(added 2026-10-18 by BATON_SPEC §10.7, R-BTN-142)*: each leg starts with `IR_BATON_LEG=<claim id>.<leg>.<run>`; stopping it also signals every visible process carrying exactly that tag (start time checked against pid reuse), in a systemd scope where available, all gone within 30 seconds; S-BTN-115.

### Do not

- Write a frame to storage or logs.

### Tests

- S-BTN-70, S-BTN-71; G-BTN-95, G-BTN-96.
- `npm test`, `npm run typecheck` and `npm run check:spec` green.
