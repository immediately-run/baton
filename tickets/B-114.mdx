**Brief:** the owner, 2026-10-26: ticket repositories should be plain `render: safe` wikis with
no components of their own, whose board still renders — from components Baton supplies, like a
plugin. The components belong to the **viewer**, not the content, which keeps the platform's
rule that a repository cannot choose the code that renders it; Baton owns the ticket format, so
it ships the viewer, as its one immediately.run program beside its CLI.
Expedited: a ticket that changes the ticketing system itself is finished first.
**Spec:** `immediately-run/docs` `PLATFORM_LAYERING_SPEC` §1.1 (M3 library mode),
`SPACES_UI_SPEC` §6 (a marker may name an app; `opens: self`), `BOOT_SCAFFOLDING_SPEC` §4.1 as
amended by R3-1292; R-BTN-74 (the markdown ticket format the components read); R-BTN-31.
**Depends on:** none in this repository.
**Waits on:** docs R3-1290 (`extendComponents`, the safe renderer drawing with a shell's map,
`setForkContentRoot`), R3-1292 (`immediately.run.entry` and `immediately.run.dependencies`) and
R3-1294 (Grove as an `open-declared` opener), each merged and released — written here rather
than in `depends_on` until B-113 lets a dependency name another repository's ticket.
**Used by:** fieldhouse FLDH-36 (its tickets wiki switches to this viewer), and the same switch
in docs and hq.

### What to build

1. **`viewer/`**, the shell:
   - `viewer/platform.tsx` — `setForkContentRoot('/app/tickets/')`, then
     `boot({ mdxComponents: COMPONENTS, children: <App /> })` (the thin-shell pattern, Grove's
     `examples/thin-shell/src/main.tsx`);
   - `viewer/App.tsx` — default-exports a component rendering `<GroveApp />`, and nothing else
     (the Fast Refresh rule: a file that exports a component exports only components);
   - `viewer/components.ts` — `COMPONENTS = extendComponents(GROVE_MDX, { RoadmapBoard,
     RoadmapMeta, NextAvailable, Dependencies, ProjectIndex, ProjectItems, ProjectMembers,
     ProjectMeta, StatusBadge, TopicIndex })`, the ten names every ticket marker registers today.
2. **The components move, they are not copied**: `tickets/components/*` (the ten components,
   their helpers `InlineProse`, `ItemCard`, `QueueChips`, `roadmapData.ts`, `roadmapLib.ts`,
   `useProjectId.ts`, `useRoadmapRows.ts`, and `roadmap.css`) move to `viewer/components/` with
   `git mv`, so their history follows. `tickets/immediately.run.json` loses its `components` key.
3. **`package.json`'s `immediately.run` block** gains
   `"entry": "viewer/platform.tsx"`, `"opens": [{ "app": "self", "version": "^1" }]`, and
   `"dependencies"` naming `@immediately-run/grove` (pinned by commit, `github:` form) and the
   React the shell needs. npm's own `dependencies`, `bin` and `files` are unchanged: the published
   CLI gains no dependency.
4. **Baton's own tickets** render through the viewer as its fork: `tickets/home.mdx` declares
   `render: safe`, and opening this repository shows the board.

### Architecture — the decisions, named

- **The viewer is Baton's only program, not a second entry point.** Multiple entry points per
  repository (`AGENT_AUTHORING_ARCHITECTURE` §5) are not built; one `immediately.run.entry`
  suffices, and becomes the entry map's default when that lands.
- **Baton's own tickets are a fork, never a dispatch.** A marker in this repository naming
  `github:immediately-run/baton` would be self-dispatch, which the platform refuses; the shell's
  `setForkContentRoot` serves `tickets/` instead. `docs/`, Baton's second corpus, keeps its own
  marker and stock Grove.
- **Components stay app code.** They run in the viewer's frame with the viewer's authority, which
  is exactly why they may render safe content: the corpus contributes data only.
- **Do not:** leave a copy of any component in `tickets/`; add Grove or React to npm's
  `dependencies` (the CLI would install them); mark stock Grove's components or the manifest;
  name a mutable branch in the viewer's Grove dependency (pin a commit, LIBRARY_MOUNTS §6).

### Tests

- Scenarios: none run yet — the viewer changes no Baton core behaviour (R-BTN-50); the board it
  renders is checked by the ticket repositories' switch-overs.
- `viewer/components.test.ts` (vitest): `COMPONENTS` carries all ten names and still resolves
  `Callout` to Grove's stock component; input: the REAL `tickets/immediately.run.json` from
  before the move (its `components` keys, saved as a fixture) — the list the viewer must cover.
- `npm run check:package`: the packed tarball contains no `viewer/` and its `dependencies` are
  unchanged.
