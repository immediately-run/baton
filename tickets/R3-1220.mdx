### Requires

- `cloudflare-admin` — exit criterion 1: the Workers Paid plan.
- `human-operator` — exit criteria 4–6: the drain, the cutover act with its confirm code, the
  adoptions and the deployment-log row.

### Why

Cutover is one-way (R-BTN-28), and §16.1 lists its preconditions: the paid plan (a quota
outage would stop all claiming, R-BTN-18, R-BTN-2), docs' owner bars and required bars set in
Baton (R-BTN-67), the checked model and its trace check green (R-BTN-68), the load test passing
at the envelope (R-BTN-87), every registered forge repository's immutable ids stored
(R-BTN-138), and the legs live with their scenarios green (§15). Only the owner can take the
plan, set the bars, drain the fleet and confirm the act. *(2026-10-14: the owner withdrew the
push rule on the Baton workflows — whoever can push is a legitimate user, R-BTN-66.)*

### What to build

The owner, in one sitting:

1. **Preconditions.**
   - Cloudflare: move the account to Workers Paid.
   - Baton: `baton owner settings docs --required-bar '*' --course roadmap-pr --except
     implement,review,adjudicate --tag-prefix family:`, and any provider suspensions in force as
     owner bars on every course (`baton owner bar docs --course '*' …`); bars are per course.
   - Check the rest are green: R3-1243's model and R3-1244's trace check (`model-report` on
     `main`), R3-1258's load test against staging, `baton repo identify` showing docs' forge
     ids (B-45), and §15's scenarios for the legs docs runs.
2. **Drain** (§16.1 step 1): stop every fleet session; confirm the dashboard's **Runners**
   view is empty.
3. **The act** (§16.1, R-BTN-155): `POST /v1/ui/cutover {repository: "docs", confirm: true}`
   from the dashboard answers `202 {confirm_code}`; perform it with `baton admin confirm
   <code>`. Baton imports each legacy claim (§16.1 step 2) and sets the flag.
4. **Adoption** (§16.1 step 3): as each session returns, its runner requests its claim
   (`POST /v1/runner/adopt`); confirm each on the dashboard
   (`POST /v1/ui/adoptions/{claim}/confirm`, then `baton admin confirm`). Unadopted legacy
   claims are reaped at their `reap_after`.
5. Restart the fleet from pulled checkouts.
6. Add the measurement-source row to the deployment's log (docs' `BATON_DOCS_DEPLOYMENT`).

### Architecture — the decisions, named

- Order matters: the preconditions first, then the drain, then the act.
- **Do not:** cut over with a runner alive, or before any §16.1 precondition holds.

### Exit criteria

- [ ] the Cloudflare account shows Workers Paid
- [ ] `baton owner settings docs` lists the two required bars
- [ ] the model report, the staging load test, docs' stored forge ids and the legs' scenarios
      are green on the cutover day (§16.1's preconditions)
- [ ] **live leg** (`human-operator`): the act confirmed with `baton admin confirm`; the
      dashboard shows `mode: cut-over`
- [ ] **live leg** (`human-operator`): every legacy claim either adopted or shown with its
      `reap_after`
- [ ] the deployment's log has the measurement-source row dated the cutover day
- [ ] `npm run verify` green
