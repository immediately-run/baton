**Brief:** the owner, 2026-10-27, on hardening against a compromised runner. The security model
(`docs/security-model.mdx`, hardening option 6, mitigation G): detection closes nothing but makes
a compromise visible within one sync, at small cost.

**Spec:** R-BTN-73 (GitHub App deliveries and the fields Baton reads, `pusher` among them),
§7.1 (the board post), R-BTN-80 and R-BTN-103 (notices), R-BTN-85 (events), R-BTN-139
(trusted identities); `docs/security-model.mdx`.
**Depends on:** none.

### What to build

1. **Control inputs**, a fixed list per repository: `.baton/**`, goal files, `.github/workflows/**`,
   agent configuration (`.claude/**` (hooks, settings, skills, memory), every `CLAUDE.md` and `AGENTS.md`, and plugin manifests, which privileged
   interactive sessions load or execute: security model, OWASP ASI05 and ASI06), dependency
   manifests and lockfiles (ASI04), and ticket frontmatter fields `EXPEDITE`, `tier`, `requires` and `depends_on`. Owners may
   add paths in their settings (R-BTN-66).
2. **The check.** When an accepted board post's head changes a control input, Baton looks up the
   pushers of the commits since the last accepted head, from the forge's push deliveries (R-BTN-73;
   the commit author is not trusted, anyone sets it). A change whose pusher is not an owner's
   recorded forge identity raises a `control-changed` event and a notice under Needs you, naming
   the paths, the commits and the pusher.
3. **Owners' identities**: each owner records the forge user ids that are theirs
   (`baton owner identity add`), the same kind of id `trusted_identities` holds.
4. **No gate.** The post is accepted as today; this is detection only. Hardening option 7
   (owner-signed control inputs) is the gate.
5. **Forges without push events** (a plain git remote) record `pusher-unknown` and raise the
   notice for every control change.
6. **Provenance on every ticket** (the owner, 2026-10-27; security model reach 3, option 9). For
   each ticket the sync records who last changed its body and its brief: the pusher of that
   commit, from the same push deliveries, and its signing key if any (B-127). Baton serves it with
   the ticket (`last_written_by: {pusher, signer?, commit, at}`) in the board, the recommendations
   and the dashboard. `baton ticket show` prints it first, so a privileged session sees "last
   written by `immediately-run-worker`" before it reads the body. Provenance is information,
   not a gate. **Hand-off documents and agent memory carry it too** (OWASP ASI06): a hand-off
   (R-BTN-44) is served with the claim and runner that wrote it, and a memory file with its
   last pusher, so the next reader knows whose words steer it.

### Tests

- A scenario: a ticket body last pushed by the worker identity is served with that pusher, and one
  an owner signed with the signer; a later push by the worker replaces both.
- A scenario (the next free S-BTN number): a non-owner's push changing `.baton/baton.json` raises
  one notice naming the path and the pusher; an owner's push raises none; a ticket's `EXPEDITE`
  set by a non-owner raises one; a forged commit author with a non-owner pusher still raises it.
