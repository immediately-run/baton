### Requires

- none — dispatch adapters are faked in the harness.

### Why

A sync must happen without Baton holding a forge credential: Baton records a want and any
runner pulls it; dispatch becomes an optional push. Tier: critical — a lost want leaves a
ticket's station stale, and the clearing rule rides R-BTN-62's numbers.

### What to build

1. Sync wants: every place that dispatches a sync today records `sync_wanted_at` (earliest)
   and `sync_wanted_after` (`board_head.last_handed_out`, 0 before any) in its transaction; an
   accepted or held post numbered above it clears both; not exported, cleared on import.
2. The mirror's want: events of kinds the mirror writes above `mirror_acked_seq`.
3. `GET /v1/sync/wanted` (per role, no state change but the nonce) and `POST /v1/sync/want`.
4. Dispatch adapters behind one port: the GitHub App (today's `dispatchWorkflow`), GitLab
   pipeline triggers, Gitea workflow dispatch; secrets from `BATON_FORGE_SECRETS`
   (`--forge-secrets` locally), whose entries also carry `forge` and `gitlab_issuer`; one retry
   at most; the unblocked trigger through the same adapters, restricted to the repository's
   own target.
5. Needs you: a want older than 30 minutes, a mirror 30 minutes behind, a configured adapter
   with no secret; the seal's mirror rule ("has a mirror").

### Architecture — the decisions, named

- **A want is state; a dispatch is a hint**: nothing depends on a dispatch arriving.
- **Do not**: store a forge credential in SQLite or export one; retry a dispatch twice.

### Tests

- Integration: S-BTN-56's mid-run want and failed dispatch, both hosts.
- Unit: the clearing rule against R-BTN-62's counter (before any number, a held post, an
  import), the mirror's want, each adapter's request shape.

### Exit criteria

- [ ] S-BTN-56's want and dispatch cases pass on both hosts
- [ ] no code path sends a dispatch without first recording the want
- [ ] `npm run typecheck` green
