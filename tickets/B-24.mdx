**Brief:** the owner, 2026-10-17: "I would like a single registry of actions that an authenticated user can take, depending on what permissions they are granted. It shouldn't matter if they are invoking this through Baton's REST API or the CLI or an MCP integration for an agent." The owner's three answers:
- keep today's roles and scopes;
- serve a remote MCP endpoint from Baton;
- put every route in the registry, with the MCP surface filtered.

**Spec:** `spec/BATON_SPEC.md` new §2m.6e: R-BTN-129 (the action registry) and R-BTN-130 (Baton's MCP endpoint).

### Why

Who may do what is spread across §10.1, §11, R-BTN-127's table and §14, and every surface checks it separately. There is no MCP surface for agents.

### What to do

1. Add §2m.6e:

   - R-BTN-130: the stateless MCP endpoint, owner-minted MCP keys, what MCP never reaches, tools, content as data, and bounds.
2. Add dated notes on R-BTN-57, -58, -117, -127, §10.1, §11 and §14. Add S-BTN-100 to S-BTN-102 and G-BTN-120 and G-BTN-121, a Decisions entry, an open question on OAuth, and a CHANGELOG row.
