**Brief:** the owner, 2026-10-31, in a design session on Fieldhouse's courses, on being shown that
the marker courses cannot run under the strong policy: "This seems like a pretty serious issue.
Please address this now."

**Spec:** `spec/BATON_SPEC.md` §5 R-BTN-131 (*The marker courses*: each leg commits its work to the
default branch, and `close` pushes the ticket); §12.8 R-BTN-188 (`refs.default_branch`,
`merge.trusted`, `tickets.created`, `leg_state`, `refs.legs`), R-BTN-180 (*Nothing requires a runner
the refs exclude to write the default branch*; the proposal route; the refusal of a policy whose
writes could never land), R-BTN-189 (`no-runner-lands`), R-BTN-190 (the leg-state branch),
R-BTN-171 (the outbox), B-120's course history.

**Depends on:** nothing to start. Item 2 lands with B-145 (it extends that ticket's validator) and
reads a fixed default where the policy store does not exist yet. Item 4 needs B-120 (course history
in Baton), B-148 (the leg-state branch mechanics), B-64 (the outbox) and B-140 (the proposal merge),
and builds on whichever has landed.

### Why

The five marker courses cannot run on a home whose default branch is protected, and nothing in the
spec or the tickets says so.

- **The code.** Every marker leg's `close` commits the ticket on the default branch and pushes it
  (`src/defaults/ticket-state.ts`, `PUSH_TRIES`), retrying only a refusal because the branch moved.
  Each leg also commits its own work there under its `## <leg>` heading; `build-app` writes
  `product/<ticket>/`; `bug-report`, `draft-ticket` and `spec-to-tickets` file new ticket files.
- **The spec.** Under `merge.trusted`, "no course commits to the default branch" (R-BTN-188's knob
  table, R-BTN-180). R-BTN-180 routes what a runner's action *creates* (a handler ticket, a call
  leg's children, a promoted question, a supersession's replacement) through proposals, and says
  claims, status and course history are Baton's. It gives no route for a marker leg's record, its
  machine state written to the ticket's frontmatter, `build-app`'s documents, or the tickets these
  courses file with their own legs.
- **The ticket that held it.** B-130 item 4: "No course writes main directly. Marker courses that
  commit their record to the ticket file on main (B-100) move their record to Baton (B-120's
  direction) or to the PR branch (B-101)", with the exit criterion "the standard courses file
  tickets by PR; no course commits to a default branch". B-130 was superseded on 2026-10-31 by the
  repository policy (B-145); its closing note maps every other item and ends "Nothing here remains
  to build". This ticket takes item 4 back.
- **Who it hits.** Under the `protected` and `protected-signed` presets every marker leg fails at
  its close, once the rulesets `baton repo protect` prints are applied. FLDH-42 applies them to
  `fieldhouse`, `docs` and `baton`, and docs runs `bug-report`, `draft-ticket` and `decision`;
  `immediately-run/hq` will run the same. Until this lands, the failure arrives at the first close,
  after the leg's model spend, rather than when the policy is set.

### What to build

1. **The spec amendment first** (its own PR, R-BTN-31's scenario with it): R-BTN-131's marker
   courses paragraph and R-BTN-180's *Nothing requires a runner …* list state where each of the
   four writes below goes when `refs.default_branch` excludes `runner`, and S-BTN-194 is added
   (*Tests*, below). Decide in the amendment, recording the choice in §16:
   - **One path or two.** Proposed: two, by the policy. Where `refs.default_branch` admits
     `runner` (`cooperative`, `plain-git`), the marker courses keep writing the default branch as
     today, since Baton serves the simple end; where it excludes `runner`, items 3 and 4 apply. The
     alternative, one path everywhere, puts an approval in front of every agent-filed ticket on a
     single-user repository.
   - **The leg-state branch for marker records.** R-BTN-190 scopes the branch to rounds passed
     between legs and to `leg_state: branch`. A marker course has no PR conversation, so under a
     protected default branch it uses the branch whatever `leg_state` says. Proposed: R-BTN-190
     names marker records as a second kind of leg state, under the same layout and read rules.
   - **Approvals per output.** Proposed: one proposal per output a human must accept. A
     `spec-to-tickets` run is one proposal holding all its children (one `std:approval@1` covers
     the set, matching `check`'s whole-set judgment). A `build-app` stage's document is the
     proposal whose approval *is* the stage approval, replacing `answer: <stage>` there.
2. **Refuse it before it runs** (with B-145):
   - Each course file declares where its legs write: a field the amendment names, proposed
     `record: default-branch | leg-state`. The standard marker courses declare `default-branch` until
     item 4 lands. The PR courses, which write only their branch, declare `leg-state`.
   - B-145's validator refuses a policy version whose `refs.default_branch` excludes `runner` while
     the repository's registry lists a `default-branch` course (`unlandable-course`, naming each
     course). The sync's registry post is refused the same way, naming the course and the policy
     version, so a course added after the policy is caught too. This is the same class as
     R-BTN-180's existing refusal of a policy whose writes could never land.
3. **A refused close ends the claim with its own reason.** A push the forge refuses for protection
   (not because the branch moved) is never retried. It ends the claim with an end reason the
   amendment names, proposed `released:cannot-finish:policy`, naming the ref and the forge's
   message, and raises a `notify` condition once per repository. Today it surfaces as a generic
   failed close.
4. **The marker courses under a protected default branch:**
   - **Machine state** (`station`, `next_leg`, the claim nonce) is Baton's course history (B-120).
     The close writes nothing to the ticket's frontmatter, and the station function reads the
     history.
   - **Each leg's record** (today the `## <leg>` section) goes to the leg-state branch at
     `.baton-legs/<ticket>/<leg>/<claim nonce>/record.md`. The next leg reads it as quoted data
     through `git cat-file` (R-BTN-190), and no gate, merge or trusted leg reads it.
   - **Outputs** are proposals on `baton/proposed/<ticket>`. These are the new ticket that
     `bug-report`'s `file` and `draft-ticket`'s `check` write, `spec-to-tickets`' children,
     `build-app`'s stage documents and plan tickets, and `decision`'s packet. They are written by a
     trusted-runner deliverer from the leg's typed output through the CLI's templates (R-BTN-171),
     and landed by the proposal merge with a `std:approval@1` (R-BTN-180).
   - **A change to an existing ticket** (`bug-report`'s fold, a decision packet in its own ticket)
     is a ticket change under `paths.tickets` and is proposed the same way.
   - **`decision`'s answer.** Under `inputs.answers: attestation`, the owner's answer is an
     attestation, not `answer:` in git, and `carry-out` reads it from Baton.
5. **Migration.** A home whose policy tightens while marker tickets are in flight replays each one's
   frontmatter state into course history once (B-120's `baton owner ticket adopt`), then stops
   reading the frontmatter. A ticket mid-course resumes at its station with no leg re-run.
6. **The docs.** `docs/standard-courses.mdx`: *How each course finds where a ticket is* and
   *`build-app`, step by step* gain the protected-branch behaviour. `docs/security-model.mdx` lists
   the marker courses among what `no-runner-lands` changes.

### Tests

S-BTN-194, as the amendment states it, covering at least:

- Under `protected`, setting a policy on a repository whose registry lists `bug-report` is refused
  `unlandable-course` naming `bug-report`. A sync that adds `draft-ticket` under that policy is
  refused naming it. Under `cooperative` both are accepted, and the course writes the default
  branch as today.
- A close whose push the forge refuses for protection is not retried, and ends
  `released:cannot-finish:policy` naming the ref. A close refused because the branch moved is
  retried as today.
- Under `protected` with item 4 built, each of the five courses runs from its first leg to its end
  station, and the default branch's history shows no commit by a runner. `research`'s record is
  read by `draft` from the leg-state branch and by no other leg. `check`'s ticket arrives as one
  proposal, is not claimable before its approval, and lands by the proposal merge.
  `spec-to-tickets`' children land as one proposal under one approval.
- A forged `record.md` planted on the leg-state branch by another domain reaches the next leg only
  as quoted data and changes no station.
- A ticket in flight at `draft` when the policy tightens resumes at `draft` from course history
  with its frontmatter state unread.

### Do not

- Push the default branch from any runner leg where `refs.default_branch` excludes `runner`,
  including a "status-only" frontmatter write.
- Let a gate, a merge or a trusted leg read the leg-state branch.
- Let a proposal merge cover a path its entries do not name.
- Retry a protection refusal, or report it as a moved branch.
- Copy the marker courses into Fieldhouse or any other home as hardened variants: Baton's standard
  courses must run under Baton's own strongest preset.
