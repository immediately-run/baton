**Brief:** the owner, 2026-10-31, in a design session on Fieldhouse's courses, on being shown that
the marker courses cannot run under the strong policy: "This seems like a pretty serious issue.
Please address this now."

**Spec:** `spec/BATON_SPEC.md` §5 R-BTN-131 (*The marker courses*: each leg commits its work to the
default branch, and `close` pushes the ticket); §12.8 R-BTN-188 (`refs.default_branch`,
`merge.trusted`, `tickets.created`, `leg_state`, `refs.legs`), R-BTN-180 (*Nothing requires a runner
the refs exclude to write the default branch*; the proposal route; the refusal of a policy whose
writes could never land), R-BTN-189 (`no-runner-lands`), R-BTN-190 (the leg-state branch),
R-BTN-183 (the ticket merge), R-BTN-192 (the fact reader), B-120's course history.

### Why

The five marker courses cannot run on a home whose default branch is protected, nor can `create-spec`'s two interactive legs,, and nothing in the
spec or the tickets says so.

- **The code.** Every marker leg's `close` commits the ticket on the default branch and pushes it
  (`src/defaults/ticket-state.ts`, `PUSH_TRIES`), retrying only a refusal because the branch moved.
  Each leg also commits its own work there under its `## <leg>` heading; `build-app` writes
  `product/<ticket>/`; `bug-report`, `draft-ticket` and `spec-to-tickets` file new ticket files.
  `create-spec`'s interactive legs `converse` and `address` push their frontmatter the same way
  (`prClose`).
- **The spec.** Under `merge.trusted`, "no course commits to the default branch" (R-BTN-188's knob
  table, R-BTN-180). R-BTN-180 routes what a runner's action *creates* (a handler ticket, a call
  leg's children, a promoted question, a supersession's replacement) through proposals, and says
  claims, status and course history are Baton's. It gives no route for a marker leg's record, its
  machine state written to the ticket's frontmatter, `build-app`'s documents, or the tickets these
  courses file with their own legs.
- **The ticket that held it.** B-130 item 4: "No course writes main directly. Marker courses that
  commit their record to the ticket file on main (B-100) move their record to Baton (B-120's
  direction) or to the PR branch (B-101)", with the exit criterion "the standard courses file
  tickets by PR; no course commits to a default branch". B-130 was superseded on 2026-10-31 by the
  repository policy (B-145); its closing note maps every other item and ends "Nothing here remains
  to build". This ticket takes item 4 back.
- **Who it hits.** Under the `protected` and `protected-signed` presets every marker leg fails at
  its close, once the rulesets `baton repo protect` prints are applied. FLDH-42 applies them to
  `fieldhouse`, `docs` and `baton`, and docs runs `bug-report`, `draft-ticket` and `decision`;
  `immediately-run/hq` will run the same. Until this lands, the failure arrives at the first close,
  after the leg's model spend, rather than when the policy is set.

### What to build

The rules are in the spec, amended with this ticket (R-BTN-69's `records` and `outputs`,
R-BTN-131's *Under a protected default branch*, R-BTN-180's `unlandable-course` refusal and
refused-write rule, R-BTN-183's *A ticket merge*, R-BTN-192's *Ticket merges*, `std:approval@1`'s
`answer`, the `released:cannot-finish:policy` end, S-BTN-194). Build them:

1. **Course-file fields.** The course validator accepts `records` (`default-branch` | `policy`,
   absent meaning `default-branch`) and `outputs` (path patterns with `{ticket}`, refusing a
   control path or one R-BTN-184's floor protects). The standard courses declare `default-branch`
   until item 4 lands, then `policy`; `build-app` declares `outputs: ["product/{ticket}/**"]`.
   `create-pr` and `review-pr` declare `policy` now.
2. **Refuse it before it runs** (with B-145). The policy validator refuses `unlandable-course`,
   naming each course. The sync's registry post refuses each such course as an invalid course file:
   the previous file stays in force, and `baton.course-refused` names the policy version.
3. **A refused close ends the claim with its own reason.** The close tells a protection refusal
   from a moved branch, and never retries the first. The end is `released:cannot-finish:policy`
   naming the ref, the ticket held `non-retryable:policy`, and `baton.unlandable` is raised once
   per repository.
4. **The protected route** (needs B-120, B-140, B-148), for the five marker courses:
   - **One work branch per ticket.** The close pushes the ticket's work branch, not the default
     branch, and the first pushing leg opens the PR; each leg's instructions stay the same, with
     the branch in place of the default branch. `decision`'s `prepare` writes no `answer:`.
   - **The approval gate.** Readiness waits on `owner` until a `std:approval@1` covers the head,
     at each stage R-BTN-131 lists, and until `pr-merged` after the last. `decision`'s approval
     carries `answer: {leg, option}`, applied as the person leg's answer. A `build-app` stage's
     approval is its person leg's answer; `plan` writes the children beside `PLAN.md`, and
     `file` returns the landed children as `spawned`.
   - **Refining and rejecting.** The owner's commits on the branch are the person leg's range,
     attested by the fact reader's `pr-pushed`; `changes` re-queues the writing leg; a cancel
     closes the PR unmerged.
   - **The ticket merge** in the merge runner (B-140): the owner's approval in place of
     `merge.reviews` and `merge.checks`, every changed path in the ticket folder or `outputs`,
     R-BTN-183's other rules, and `id-taken`. Baton lists waiting tickets in the fact-legs list;
     the merge runner attests each merge as `pr-merged`, and Baton applies the deferred end.
   - **After the merge**, a leg's record goes where `leg_state` says.
5. **Migration.** A home whose policy tightens while marker tickets are in flight replays each
   one's frontmatter state into course history once (B-120's `baton owner ticket adopt`), then
   stops reading the frontmatter. A ticket mid-course resumes at its station with no leg re-run.
6. **The docs.** In `docs/standard-courses.mdx`, *How each course finds where a ticket is* and
   *`build-app`, step by step* gain the protected route. `docs/security-model.mdx` lists the
   standard courses among what `no-runner-lands` changes.

### Tests

S-BTN-194, every case in its row.

### Do not

- Push the default branch from any runner leg where `refs.default_branch` excludes `runner`,
  including a "status-only" frontmatter write (the owner, 2026-11-01: no agent-filed change
  lands without their approval).
- Let a gate, a merge or a trusted leg read the leg-state branch.
- Let a ticket merge cover a path outside the ticket folder and `outputs`, or land a head no
  approval covers.
- Reach a course's end before its ticket merge lands.
- Retry a protection refusal, or report it as a moved branch.
- Copy the marker courses into Fieldhouse or any other home as hardened variants: Baton's standard
  courses must run under Baton's own strongest preset.
