**Brief:** the owner, 2026-10-31, in a design session on Fieldhouse's courses, on being shown that
the marker courses cannot run under the strong policy: "This seems like a pretty serious issue.
Please address this now."

**Spec:** `spec/BATON_SPEC.md` §5 R-BTN-131 (*The marker courses*, the course table, `spec-to-tickets`,
`build-app`), R-BTN-165 (children a merged PR landed), R-BTN-180, R-BTN-192 (`pr-merged`);
S-BTN-104, S-BTN-107, S-BTN-194.

**Depends on:** B-120 (course history in Baton, fact legs), B-140 (the fact reader, which
attests `pr-merged` under `protected`), B-7 (person legs: `decision`'s `answer`, `build-app`'s
`ship-anyway`) and B-62 (call legs: `file`, `fix`). Under `cooperative` the sync attests
`pr-merged`, so items 1–5 can be built and tested before B-140.

### Why

The five marker courses cannot run on a home whose default branch is protected.

- **The code.** Every marker leg's `close` commits the ticket on the default branch and pushes it
  (`src/defaults/ticket-state.ts`, `PUSH_TRIES`), retrying only a refusal because the branch moved.
  Each leg also commits its own work there under its `## <leg>` heading; `build-app` writes
  `product/<ticket>/`; `bug-report`, `draft-ticket` and `spec-to-tickets` file new ticket files.
- **The spec.** Under `merge.trusted`, "no course commits to the default branch" (R-BTN-188,
  R-BTN-180). R-BTN-180 routes what a runner's action *creates* through proposals, but gives no
  route for a marker leg's record, `build-app`'s documents, or the tickets these courses file.
  `create-spec`'s `converse` and `address` no longer write frontmatter (B-120 moves their state to
  course history), so they need nothing here.
- **The ticket that held it.** B-130 item 4: "No course writes main directly …", with the exit
  criterion "the standard courses file tickets by PR; no course commits to a default branch".
  B-130 was superseded on 2026-10-31 without it. This ticket takes item 4 back.
- **Who it hits.** Under the `protected` and `protected-signed` presets every marker leg fails at
  its close once the rulesets `baton repo protect` prints are applied. FLDH-42 applies them to
  `fieldhouse`, `docs` and `baton`; docs runs `bug-report`, `draft-ticket` and `decision`.

### What the owner has decided

- **2026-10-31:** the marker courses must run under Baton's strongest preset; no hardened
  copies in other homes.
- **2026-11-01:** "The marker courses no longer need to commit to the main branch now that ticket
  history and claims are owned exclusively by Baton. We can always commit to a PR branch instead
  of the main branch." The owner then chose:
  - **every policy:** one route;
  - **answer, then merge:** `decision` takes two acts;
  - **each approval is a merge:** `build-app` has a PR per stage, and the plan's PR carries its
    children.

  The two earlier drafts (proposals, then a ticket merge) are withdrawn. Their history entries,
  dated 2026-10-31 and 2026-11-01 in `spec/BATON_SPEC_HISTORY.md`, record why.

### What to build

1. **The marker branch.** Each marker leg's `close` commits on the ticket's current marker branch
   (`baton/m/<id>/<n>`): the one the last writing leg reported, or a new one cut from the default
   branch, or from a closed PR's head after a route. The close then opens the PR and reports
   `{branch, head}` with the position. It refuses paths outside the ticket folder and the course's
   `outputs`, and never pushes or merges the default branch (`src/defaults/ticket-state.ts`).
   The courses' `branch_pattern` is `baton/m/{ticket}/*`, and R-BTN-25 continues only the current
   branch.
2. **The course files** (`src/defaults/courses.ts`), as R-BTN-131's table gives them: every fact
   leg with `arrives: {fact: pr-merged}`; the self-edges with `max_runs`; `decision`'s `answer`,
   `settled` and re-ask paths; `build-app`'s stage PRs, `verify`'s three outcomes, `ship-anyway`
   and `fix`'s `unfixed`; and `outputs` (`build-app`: `product/{ticket}/**`). A writing leg's
   `next` naming itself is refused.
3. **What a leg reads and when a merge counts.**
   - The runner reads the ticket at the marker head (R-BTN-5), and the station functions read
     there too.
   - The fact reader and the sync count only a merge of the current marker branch containing
     its reported head, made by no claim, or on `forge: git` a first-parent merge commit.
   - `fact-legs` carries the branch and head, and keeps a ticket closed `done` until its arrival
     applies.
   - `baton.marker-unreported` is raised for unreported commits.
4. **Call legs over a merge's children** (R-BTN-165): the set is read from the applied merge,
   `child-closed` is refused, the null outcome taken on an empty set, the completion evaluated at
   the end, and the children `waiting` on `parent` until bound.
5. **Leg instructions.**
   - Every marker leg's `.md` commits to the marker branch, never the default branch, and only
     the last writing leg sets `status: done`.
   - `build-app`'s *The conversation* refines the PR and ends with the owner's merge, not
     `answer:`. `plan` writes the children, and `verify` writes `VERIFY.md` and its fix tickets.
   - `decision`'s `prepare` asks through Baton, not `answer: open`, and reports `carried` when
     the question is settled. `carry-out` reads its claim's input `answer` and reports `asked`
     to re-ask.
   - New ids skip the open marker branches' heads.
6. **Migration.** Before the new course files land, place every live marker ticket whose
   position the new file lacks with `baton owner ticket adopt`, so that R-BTN-64's course test
   passes. The map, tested on a fixture per row:
   - `decision`: at `asked` with `carry-out` queued, to `answered` if an `answer:` was given,
     else to `asked` with `answer` queued.
   - `build-app`: at `defined`, `designed`, `architected` or `planned`, with the next drafting
     leg or `file` queued:
     - to the next `*-accepted` station if the git `answer:` approved that stage;
     - else to the drafting station with its `accept-*` leg queued, which waits for a PR the
       next run of the drafting leg opens.
   - `draft-ticket` at `drafted` with `check` queued: unchanged.
   - Any ticket a leg left with records on the default branch keeps them, and its next leg
     opens the first marker branch.
7. **The docs.** In `docs/standard-courses.mdx`, *How each course finds where a ticket is* and
   *`build-app`, step by step*. In `docs/security-model.mdx`, the marker courses among what a
   human's merge by hand lands.

### Tests

S-BTN-104, S-BTN-107 and S-BTN-194, every case in their rows, and each row of item 6's map.

### Do not

- Push the default branch from any marker leg, under any policy.
- Treat an answer, a comment or a verdict as a stage's approval: only a merge is.
- Take a call leg's children from its script or from tickets outside the applied merge.
- Copy the marker courses into Fieldhouse or any other home as hardened variants.
