**Brief:** the owner, 2026-10-16 and 2026-10-17, in one design discussion (the session's summary of the agreed points, then "go"): the runner organizes a ticket's legs and sessions report to it; cloud sessions as runners; one envelope and named schemas for leg outputs and readings; station entry requirements; standard output formats as a library; a course's signature; declarative views; session links; check courses with the merge check delivered to GitHub by a trusted courier; registration tokens with API keys as a fallback to SSH; a running leg's output streamed over wss; stopping a leg from the dashboard; a leg's prerequisites in one place, with tickets `at` or `reached` a station; capability types declared in each course file.
**Spec:** `spec/BATON_SPEC.md` — new §2m; dated notes on R-BTN-13, -33, -37, -58, -69, -72, -75, -76, -78, -80, -82, -91, -101, §7.2 rule 4, §10.1, §11 and §14.
