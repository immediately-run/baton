**Brief:** the owner, 2026-10-16 and 2026-10-17, in one design discussion (the session's summary of the agreed points, then "go"): the runner organizes a ticket's legs and sessions report to it; cloud sessions as runners; one envelope and named schemas for leg outputs and readings; station entry requirements; standard output formats as a library; a course's signature; declarative views; session links; check courses with the merge check delivered to GitHub by a trusted courier; registration tokens with API keys as a fallback to SSH; a running leg's output streamed over wss; stopping a leg from the dashboard; a leg's prerequisites in one place, with tickets `at` or `reached` a station; capability types declared in each course file. Later the same day: retries per leg, Temporal-style, with a backoff as a prerequisite; a comparison with Gas Town; and from it, handing off when the context fills, a planning leg shipped as a course, and severity on decisions — with asking a predecessor session mentioned, not built.
