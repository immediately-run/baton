### Why

The owner, 2026-11-26: "it should be possible for a user to see why a particular leg was chosen in the dashboard or using the CLI", and "where no [leg] can commence, it should be clear when the next action of the ticket may be determined, or that the ticket needs human attention because the next leg cannot be calculated."

### What to build

1. **`baton ticket why <ticket>`**: the latest verdict, its `because` lines, its `until` and triggers or its `host`, the course version and the posting key.
2. **`--replay`**: rebuild the `ctx` from Baton's record at the verdict's record position, while that record is retained (R-BTN-88), run the selector through the local CLI's executor, and say whether the verdict matches; a record no longer retained says so.
3. **The dashboard:** the ticket view shows the verdict and why; the board shows each ticket's verdict kind — queued, waiting (until when, on what), awaiting selection (with its age), needs attention. Text only (`textContent`); `because` urls as links after §12.3's link rule.
4. **Needs you** lists the two selection conditions, each linking its verdict.

### Trust

- **What is shown:** course-written text (`reason`) and links (`url`), both untrusted: text through `textContent`, links only after the link rule.
- **Replay** runs repository code: only through the local executor, never in the CLI's process.

### Invariants

- **Text, never markup** (§10.4, CLAUDE.md): no `innerHTML`.
- **Replay never writes**: it compares and prints; it posts no verdict.

### Tests

- `ticket why` prints a `run`, a `wait` and an `attention` verdict.
- `--replay` reproduces a verdict whose record is retained; a verdict posted with a changed outcome does not reproduce, and a gate still refuses the merge it would have queued.
- Dashboard: a `because` reason containing markup renders as text.

New S-BTN scenarios for these, numbered with `node cli/baton.mjs tickets next scenario`.

### Exit criteria

- [ ] `baton ticket why` and the dashboard show every live ticket's verdict and why.
- [ ] `--replay` reproduces any verdict whose record is still retained.
- [ ] The scenarios pass; `npm test`, `npm run typecheck` and `npm run check:spec` green; merged under the review gate.
