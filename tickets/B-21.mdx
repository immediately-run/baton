**Brief:** the owner, 2026-10-17: a prerequisite may fail during a leg, as well as before it starts. That is a coloured edge in the course graph, not a new station. B-20 specified it (baton#44).
**Spec:** [BATON_SPEC §6.2](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2) ([R-BTN-126](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2), [R-BTN-75](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2), [R-BTN-77](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-2)), [§6.3](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3) ([R-BTN-76](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3), [R-BTN-101](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-3)),
[§6.1](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-1) [R-BTN-120](../spec/BATON_SPEC/06-prerequisites-blocks-advice.md#sec-6-1), [§7.4](../spec/BATON_SPEC/07-conditions.md#sec-7-4) [R-BTN-122](../spec/BATON_SPEC/07-conditions.md#sec-7-4) (`max_blocked`, a constant), [§7.3](../spec/BATON_SPEC/07-conditions.md#sec-7-3) [R-BTN-163](../spec/BATON_SPEC/07-conditions.md#sec-7-3) (`baton.retries`),

Migrations: `provider-exhausted`.

### Why

R-BTN-126 is specified. This ticket builds it.

### What to build

Baton's half of R-BTN-126 as amended 2026-11-15 (a leg's block is a request the runner
confirms). The runner's half — running the capability's check after the leg stops, the bound
account readings, `runner.json` `instance`, countering — is B-245, which requires this ticket.

1. **The end.** `POST /v1/runner/end` takes `released:blocked` with `prerequisite: {kind, ref}`,
   plus `commit` for a `ticket` end and, for a `resource` end, an optional
   `reading: {instance, available: false, until?, valid_for?, detail?}` that is the runner's own
   check's reading (R-BTN-121), never the leg's. Validate each kind as R-BTN-126's **Invalid**
   bullet says: a bad kind or `ref`, a capability the `capability` bullet does not admit, or a
   `ticket` end without `commit` records a counted `released:cannot-finish:transient` in the
   same transaction and answers `invalid-prerequisite`. A reading failing its envelope, bounds
   or one-a-minute limit, or naming an instance not serving `ref` or not reportable, is dropped
   and logged `reading-refused`; the end stands. Route `released:blocked` before `checkEnd`'s
   owner-bar branch (Status, 2026-10-19). The `capability` kind is already accepted
   (`src/core/validate.ts:628`, B-104's branch): extend that path, do not add a second.
2. **Resource.** Store the reading as the runner's (R-BTN-76), add the `end`-sourced need to
   `leg_needs`, stamp `found_at`, then write the `resource` row against R-BTN-76's counts, all
   in one transaction — the leg blocks once every usable instance of `ref` is `unavailable`, for
   every runner alike. The need and its row go when the leg next ends other than `blocked` on
   that resource, or after 7 days; posts never remove it.
3. **Capability.** Remove the capability from the runner's declared set and update
   `fleet_capabilities` in the end's transaction, so rule 4 refuses this runner at once. Baton
   never checks the statement; the runner confirmed it before ending (B-245). The runner
   declares it again when its check passes (R-BTN-121), or, for a name its executor `provides`,
   when the executor states it again (R-BTN-107). Re-evaluate the runner's derived sets in the
   same transaction (R-BTN-174) if B-104's derivations have landed.
4. **Ticket, condition and call.** A `ticket` end writes a provisional row carrying its
   `commit` (R-BTN-75): it refuses a claim and an advance into the leg and stays out of
   `blocked_since`; the first accepted snapshot whose head contains the commit replaces it, and
   one unconfirmed within an hour is dropped and logged `prerequisite-unconfirmed`. `condition`
   and `call` ends follow R-BTN-162 and R-BTN-165 (B-59, B-62). There is no `decision` kind
   (R-BTN-78 retired).
5. **Bounds.** `max_blocked` is the constant **5** per (ticket, leg) in 24 hours (R-BTN-122), not
   a setting. Count from `claims.blocked_kind` and `blocked_ref`, `call` ends excepted
   (G-BTN-115). The sixth holds the ticket `blocked-exhausted` and raises `baton.retries` listing
   each end's prerequisite; a runner with more than 20 blocked ends across tickets in 24 hours
   raises `baton.blocked-ends`. A valid blocked end is not a failed attempt, not a run for
   `max_runs` (R-BTN-69), and starts no backoff.
6. **The wire and the channel.** The runner's `LegError(type, message, {prerequisite,
   instance?, commit?})` and the local channel's `baton leg release --blocked --kind <kind>
   --ref <ref> [--instance <i>] [--commit <sha>]` (R-BTN-106) carry the leg's request to the
   runner. Build the CLI command and the channel message; what the runner does with the request
   is B-245. A request is never retried in the claim.
7. **Views.** The **Courses** view, a ticket's path and `baton leg why` draw each leg as an edge
   in one state — `ready`, `running`, `blocked` (each prerequisite's kind, `since`, `until`,
   `found`), `backing-off`, `not-queued` — in colour and a text label, from the blocks index and
   `leg_needs`; never as a station.
8. **Migration.** `ticket_blocks.provisional` and `found`, `leg_needs.source`, `added_at` and
   `found_at`, `claims.blocked_kind` and `blocked_ref` with their index, and the
   `blocked-exhausted` hold reason — skipping any an earlier migration added.

### Do not

- Add a station for a blocked leg anywhere.
- Retry an error that names a prerequisite.
