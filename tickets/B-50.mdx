**Spec:** BATON_SPEC §15 R-BTN-68 (hosted runners run no Quint; a PR carries `npm run
model:pr`'s report; `npm run model:full` runs weekly on `main` as this series), §6.5 R-BTN-89's
recurring jobs ("one child ticket per run", `writeSuccessor`, the `series` course), §4.6
R-BTN-86, §7.5 R-BTN-167 (an interrupting `start` timer), §7.1 R-BTN-160 (`error.capability`).
**Depends on:** R3-1259 (the series) and B-60 (the interrupting `start` timer).
**Brief:** the owner, 2026-10-20: "3 hours is absurdly long. We can run that maybe once a week not
for every pr", then "Please create the recurring 'Weekly model check' as a baton ticket within
the baton repo. It should be run on any baton runner connected to the baton repo."

### Requires

R3-1259: `not_before`, `nextFire`, `writeSuccessor` and the default `series` course. Until it
lands, Baton cannot run a recurring job, and the weekly check is run by hand on the owner's
machine (`npm run model:full` on `main`). Baton must also be syncing this repository (`.baton/`
from `baton repo init`, the sync workflow, the registration); that is the `create-pr` gap run's
work, not a ticket.

### Why

Since baton#68, nothing on a hosted runner runs Quint, and a PR's report (`model:pr`) checks the
regression runs, 200 model-drawn traces and the scenario traces. The simulation (10,000 samples
and the witnesses), 1,000 model-drawn traces and Apalache's proof to depth 4 take about three
hours, so they run once a week on `main`. That run must not depend on anyone remembering it: it
is a Baton series, and any runner granted on baton takes it.

### What to build

1. **The job's course**, `.baton/courses/model-check/`: one leg `check`, from `scheduled` to
   `done`.
   - **No agent.** The leg's `run` executes `npm ci` and `npm run model:full` in the leg's
     checkout of the run's commit (`main`'s head when the leg starts) and keeps its stdout, the
     Markdown report. It never calls `agent_command`.
   - **Any runner.** The course requires no capability, so every runner granted on baton is
     eligible (rule 7). `model:verify` needs Java: when `java` is not on the PATH, the leg
     downloads a pinned Temurin JRE tarball into the runner's cache, outside the checkout, and
     puts it on the PATH for the step. A runner that cannot fetch it throws
     `LegError('error.capability', …)` naming the missing JRE, ending
     `cannot-finish:capability` (a floor type, never retried, R-BTN-122). Before B-55 types
     `LegError`, the leg ends `cannot-finish:capability` directly.
   - **Time.** `"timers": [{"after_s": 18000, "from": "start", "interrupting": true}]` (five
     hours, R-BTN-167, built by B-60) for a run of about three hours on 4 CPUs. The course file
     carries no `max_duration` (retired: read as such a timer during the window, refused after B-67). The leg reports progress on each
     step, so the lease holds.
   - **The report.** Before its closing commit, the leg appends the report under `### Report` to
     the run's own ticket file, so every week's report stays in git, archived with the run. When
     the report does not pass, the leg also files a B-ticket with `npm run ticket -- new`, titled
     `Weekly model check <date> failed: <checks>`, with the report as its body, and the run
     still closes `done`. A failed check is a finding for a person, not a failed attempt to
     retry.
   - **The successor.** The leg calls `writeSuccessor(ctx, {schedule: {cron: '0 2 * * 1', tz:
     'UTC'}})`: Mondays at 02:00 UTC, the next run `model-check-<n+1>` on `main` before the
     closing commit, `depends_on` this run (R-BTN-89).
2. **The series and its first run.**
   - `tickets/model-check.mdx` on the `series` course, titled `Weekly model check`.
   - `tickets/model-check-1.mdx` on `model-check`, with `parent: model-check`, `run: 1`, and
     `not_before` at the first Monday 02:00 UTC after this ticket merges.
   - Both carry the ticket source's fields only (R-BTN-33). Stopping the series is a git act:
     withdraw the pending run, then retire the series.

### Tests

- `baton course test . model-check` passes, including the timer's validation. The test kit drives a run to `done`, and
  the leg script exports `run`, `handoff` and `close`.
- A unit test for the leg with `npm run model:full` stubbed:
  - a passing report is appended to the run's file, and no B-ticket is filed;
  - a failing report files one B-ticket and the run still closes `done`;
  - the successor is `model-check-<n+1>` with the next Monday's `not_before`, and a retried leg
    writes no second one;
  - no `java` and no network fails the leg `cannot-finish:capability`, naming the JRE.
- S-BTN-51 (R3-1259) already covers the series mechanics.

### Exit criteria

- `model-check-1` runs on a granted runner at its `not_before`, appends a passing report for
  `main`'s head, writes `model-check-2` for the next Monday, and closes `done`.
- `npm test` and `npm run check:wiki` are green.
