**Spec:** R-BTN-47 (registered repositories: "only an administrator registers, changes or
retires a repository"), §12.2 (`admin.repo.retire` destructive), §14 (`POST
/v1/admin/repositories` with `{id, retire: true, confirm: true}`), R-BTN-155 (*Sessions*),
R-BTN-130 (an MCP key's end), `BATON_MCP_OAUTH_SPEC` (grants and tokens), R-BTN-93 (sync keys),
R-BTN-171 (the outbox). Source: `docs/review/security-review-2026-11-02.mdx`, finding U1, widened
on checking: no rule states retirement's effect on anything.

### Why

A session loses a repository "as soon as its key stops owning it"; an MCP key ends "when the
credential that minted it is removed or revoked". Retirement is neither, so as written an
owner's session, an MCP key and an OAuth grant on a retired repository keep their reach, and
nothing says whether its sync keys still post, its grants still claim, a held claim keeps its
lease, or a queued `withdraw` or `forge-check` is still offered. The code today sets
`repositories.retired_at` and filters reads by it (`src/core/admin.ts`, `src/core/claims.ts`);
each surface's behaviour is whatever its query happens to do.

### Spec (written 2026-11-03)

The spec half is written: R-BTN-47's *Retirement* (final; sessions, MCP keys and OAuth grants,
sync and mirror keys, runner grants and check-runners, active claims `released:retired`, queued
and claimed outbox entries, owners and history kept; later calls `not-found`, the id never
registered again), R-BTN-155 and R-BTN-130 citing it, the end-reason row and S-BTN-198, in PR
`claude/baton-spec-review-2fwiga` at the owner's request ("Please ensure all tickets required to
implement the spec are ready to be picked up for implementation").

### What to build

1. `admin.repo.retire` runs R-BTN-47's six steps in the one transaction that sets `retired_at`
   (`src/core/admin.ts`): the session reach, the MCP key and OAuth grant revocations with their
   tokens, the sync and mirror key, runner grant and check-runner revocations, a `release` with
   reason `retired` to each active claim (fenced as R-BTN-19 says when unacknowledged), and the
   outbox entries `dropped`, each logged.
2. Every route naming a retired repository answers `not-found` (today several filter by
   `retired_at`; make it one check), forge notifications for it are refused, and registering a
   retired id is `conflict` (today a known id takes the change path).
3. The export keeps a retired repository's owners, events, history and closed tickets.
4. `released:retired` in the end-reason vocabulary.
