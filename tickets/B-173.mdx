**Spec:** R-BTN-47 (registered repositories: "only an administrator registers, changes or
retires a repository"), §12.2 (`admin.repo.retire` destructive), §14 (`POST
/v1/admin/repositories` with `{id, retire: true, confirm: true}`), R-BTN-155 (*Sessions*),
R-BTN-130 (an MCP key's end), `BATON_MCP_OAUTH_SPEC` (grants and tokens), R-BTN-93 (sync keys),
R-BTN-171 (the outbox). Source: `docs/review/security-review-2026-11-02.mdx`, finding U1, widened
on checking: no rule states retirement's effect on anything.

### Why

A session loses a repository "as soon as its key stops owning it"; an MCP key ends "when the
credential that minted it is removed or revoked". Retirement is neither, so as written an
owner's session, an MCP key and an OAuth grant on a retired repository keep their reach, and
nothing says whether its sync keys still post, its grants still claim, a held claim keeps its
lease, or a queued `withdraw` or `forge-check` is still offered. The code today sets
`repositories.retired_at` and filters reads by it (`src/core/admin.ts`, `src/core/claims.ts`);
each surface's behaviour is whatever its query happens to do.

### Spec (written 2026-11-03)

The spec half is written: R-BTN-47's *Retirement* (final, six steps in one transaction, the
tombstone export and the seed), R-BTN-19, R-BTN-3's heartbeat, R-BTN-88's seal, §2.3's event
prune, R-BTN-140's consent, R-BTN-155, R-BTN-130, R-BTN-171's *Dropping*, `BATON_MCP_OAUTH_SPEC`
§5, §7 and §9, and S-BTN-198, in PR `claude/baton-spec-review-2fwiga` at the owner's request
("Please ensure all tickets required to implement the spec are ready to be picked up for
implementation"), after one round of fresh review.

### What to build

1. `admin.repo.retire` runs R-BTN-47's six steps in the one transaction that sets `retired_at`
   (`src/core/admin.ts`): session reach; MCP keys, OAuth grants with their tokens, pending OAuth
   requests and codes; sync and mirror keys, registration tokens, runner grants and
   check-runners; each active claim reaped as a force-reap (fence-pending where its runner is
   alive); `queued`, `claimed` and `delivered` outbox entries `dropped`, each logged; sync wants,
   trailing dispatches and the unblocked trigger deleted.
2. A heartbeat declaring a retired repository's course drops that course instead of being
   refused, so the old holder reports `fenced`; a deliverer's later mark is ignored.
3. Every other route naming a retired repository answers `not-found` (one check, not each
   query's filter); its forge notifications and CI identity are refused; registering a retired
   id is `conflict` (today a known id takes the change path); the OAuth token exchange refuses a
   code for a retired repository `invalid_grant`.
4. The seal and the event prune count only live repositories' mirrors; the export carries a
   retired repository as its tombstoned registry row alone; the seed skips and logs an entry
   naming a retired id.
5. `code_repos` consent is judged for a retired repository as for a live one.
