**Brief:** the owner, 2026-10-26, verbatim: "blindly accepting git updates as tickets status in
Baton is *NOT* desired as this allows an agent with write access to the home repo's
tickets/ directory to overwrite ticket course traversal history in baton. Git is authorative in
everything *except* the ticket's course history (the specific station -> leg pairs traveled so
far in the history encountered). A baton CLI command (or MCP of course) will force the baton
server to override it's own ticket history with the contents of the ticket file in git."

The case that prompted it: legs completed outside the runner, in an interactive session or
during stale-PR cleanup. They should be a deliberate act of a key holder, never a side effect of
whoever can push.

**Clarified:** the owner, 2026-10-31, in a design session: Baton is the sole authority on
ticket history; tickets in git may get per-leg amendments, but git need not hold a ticket's
full history. On adopt: "this is a useful fallback if baton is down". The four mechanism
choices below were the owner's answers the same day.

### The choices (the owner, 2026-10-31)

1. **Git facts move a ticket only on declared legs:** person legs and legs declaring
   `arrives: facts`, by an edge from Baton's station. Anything else is `position-disagrees`
   and moves nothing.
2. **The sync reads Baton's positions** in its observation and hands them to `stations(ctx)`;
   station functions compute readiness at that station only.
3. **Regression detection is retired:** `regressed_since`, `git.regressed`, the runner's abort,
   `baton.regressed`, path-extension checks, `position-replaced`, `route-overridden`,
   `path-rewritten` and the `marker`/`inferred` next sources.
4. **Confirmation checks evidence, not position:** an end's position stands at once; the end is
   confirmed by the first snapshot after it that shows its named evidence.

### Why

Every accepted snapshot overwrites `ticket_stations` today, so anyone who can push to the home
repository can rewrite where a ticket is and how it got there: ticket frontmatter and closes,
markers, PR comments. Leases, retries, holds and run counts key off that traversal, so the
write is a way around them (reset a path to escape `max_runs` or a retry hold).

### What to build

1. **Core.** Positions written only by advances and ends, Baton's settlements and overrides,
   fact arrivals and adopt (R-BTN-39); a new ticket at `start` on its first snapshot. A
   snapshot updates readiness and bars only, discarding readiness whose `at` is not Baton's
   station. `position-disagrees` replaces the retired discrepancy subs, raised under Needs you.
   Retire the regression machinery listed above, in core, the runner and the heartbeat.
2. **The observation's `positions`**, read by the station functions (their readiness, arrivals and implied station are the sync's attestations, built below);
   `StationCtx.positions` in `src/defaults/courses.ts`.
3. **The standard courses' station functions** compute readiness at the given station from
   their facts. `create-spec`'s `converse` and `address`, and the marker courses' closes, write
   no machine state; `create-pr`'s and `review-pr`'s human-made outcomes that should still move
   a ticket get `arrives: facts` legs where the course needs them (decide per course, in the PR).
4. **Adopt:** the route, `baton owner ticket adopt` with `--at` and `--next`, the
   `nothing-implied` refusal, releasing and fencing an active claim first, `history-adopted`,
   the attempt-window reset; MCP's `ticket.adopt` with R-BTN-130.
5. **Confirmation** by evidence (R-BTN-10), and `baton.unconfirmed` for evidence never shown.
6. **Migration.** At the release that ships this, each live ticket's course history starts from
   the newest of: its `ticket_stations` row, the last arrival in its `claim_legs`, and an
   unconfirmed end's pair; no git read. `next_source` `marker` maps to `holder` and `inferred` to
   `course`; every `regressed_since` is cleared. A ticket whose position is still wrong is the
   owner's to adopt.
7. **The model** (`model/baton.qnt`): snapshots no longer move positions; adopt as an action;
   disagreement as a no-op plus a discrepancy; `model:pr`'s report.

### What to build: the inbound path (folded in from B-151 in review round one)

1. **Writers.** `sync` for the board post's credential (sync key, CI identity, machine key) and
   `courier` for a courier key, in the attestation writer enum and the policy's `attestations`
   entries.
2. **The board post.** `attestations: [{type, ticket, ref?, value}]` validated per type and
   stored in the post's transaction, superseding the previous run's of the same type and
   subject; refused with the post. `stations` and `markers` are retired from the post; bars,
   decisions and `not_before` move into `tickets[]`.
3. **The holder's arrival.** An `advance`, end or suspension records its pair as the holder's
   `std:arrival@1` (writer `runner`, signed by the request), the same type as the sync's fact
   arrival; every preset admits `runner` for it on the claim's own leg, and nothing else of the
   sync's types (R-BTN-83, R-BTN-191).
4. **Readers.** Readiness (R-BTN-70), fact arrivals and implied stations (R-BTN-39), outputs
   (R-BTN-82), markers (R-BTN-46) and evidence (R-BTN-10) read from the newest accepted run's
   attestations; a person leg settles from a `std:decision@1` by an admitted writer (R-BTN-116).
5. **Couriers.** `POST /v1/courier/entries/{repository}/{id}` with `delivered` records a
   `std:effect@1` by `courier`; confirmation stays the sync's later attestation of the effect.
6. **The CLI's sync** emits the attestations from each station function's result.
7. **The model:** one inbound path, and no judgement over two runs' attestations.
