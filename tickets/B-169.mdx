**Spec:** `spec/BATON_SPEC.md` as PR #165 left it: R-BTN-144 (*Masking*, class 5), R-BTN-114
(*Conclusions are the owners'*), R-BTN-73 / R-BTN-95 (*Routes*) and §2.3 (*Admission*), R-BTN-16
(*Cookies*, *Headers*), R-BTN-155, R-BTN-131 and R-BTN-180 (*the request command*). History: the
changelog entry "the security review's corrections". Source:
`docs/review/security-review-2026-11-02.mdx`, findings S1, S2, S4, C2, C5 and U3. No owner
ruling: each change aligns two rules or closes a gap in the direction the spec already took.

### What to build

1. **Masking.** The runner's class-5 pattern matches `brt_`, `bak_`, `bmcp_`, `bps_`, `bds_`,
   `bmo_`, `bmr_` and `bor_`, each followed by `[A-Za-z0-9_-]*`; the archiver's transcript
   masking uses the same pattern (one shared definition, not two lists).
2. **The checks map.** `PUT /v1/owner/{repository}/settings` refuses a `checks` course map that
   does not name exactly one end station `success`, exactly one `failure` and at most one
   `neutral` (`invalid-params`, naming the course). Any change to `checks`, and any key added to
   `check_runners`, is a loosening: it needs an approver on `approvers.policy` (R-BTN-186), and a
   delegated key is refused as before.
3. **Notification body caps.** `POST /v1/github/webhook` and `POST /v1/forges/{repository}/notify`
   refuse a body over 25 MB `too-large` on `Content-Length`, or once 25 MB have been read
   (chunked bodies), before any MAC is computed. Both stay outside the per-IP rule.
4. **Headers.** Every response to a request a credential or a dashboard session authorizes
   carries `Cache-Control: no-store` (one place in `src/core/http.ts`, not per route).
5. **The pending cookie** is `__Host-baton_pending` wherever B-46's sign-in builds it.
6. **The request's PR fallback.** `baton ticket request` asks Baton nothing. When the forge
   refuses its push to the default branch as protected (not a moved head, which is retried as
   now), it pushes the same commit to `request/<ID>` and opens a PR from it through the
   CLI's forge adapter for the home's forge (R-BTN-92), printing the URL; on a `git` forge, or
   with no forge credential, it prints the branch and exits non-zero.

### Tests

S-BTN-42 (the 26 MB bodies), S-BTN-68 (the two maps; the human-only `approvers.policy` cases),
S-BTN-98 (`bmr_` and `bps_` masked) and S-BTN-124 (`no-store` on a session read) as §15 now
states them; S-BTN-175 gains a protected default branch (a PR opened, nothing pushed to `main`).
Green in `npm test` on both hosts.
