**Brief:** the same run (finding 9; the lessons page): the leg stubs run
`execFile("sh", ["-c", agent_command + ' "$@"', …])`, and that environment hangs
`opencode run` (v2.1.2, macOS, the bun binary) deterministically — zero output, idle event
loop, forever, burning the claim until reap. Direct `spawn` from node works; the same
command through `sh -c` hangs; `sh -c '… < /dev/null'` works. Ruled out: stdin pipes
(`stdio: "ignore"` still hung), signal dispositions (`trap '' PIPE` completes), trust
prompts, the background service (`--standalone` also hung). Root cause unexplained.
**Spec:** §2f (R-BTN-74), §5.8 (R-BTN-131: the stubs).

### Why

A leg must not depend on its agent CLI tolerating the stub's spawn environment. One real
harness already fails it silently; the workaround lives in this repository's `baton.json`
and the lessons page, not in the product.

### What to build

1. The stubs spawn the agent without a shell: `agent_command` parsed as `sh -c` words are
   today (a shell string is the documented interface — keep accepting it) but executed as
   `execFile(command, args)` after one `sh -c`-compatible word split (quotes; no
   substitutions), so no shell process stands between the stub and the agent.
2. The stdio contract is explicit: stdin is never an open pipe — `ignore` or a closed fd —
   and stdout/stderr are captured pipes; written into the leg's `.md` header (Baton's
   contract for `agent_command` authors).
3. The hang itself reproduced in a test where it can be (a spawn through `sh -c` of a
   command that reads stdin blocks — assert the stub's stdin is not readable), and the
   reproduction documented in the PR for the platform where the original hangs.

### Tests

- Unit: the stub's child stdin is not an open pipe; a command string with quoted arguments
  splits as `sh` would (shared helper with its own table).

### Exit criteria

- [ ] no shell between the stub and the agent; stdin never an open pipe
- [ ] the opencode invocation works without the manual redirection
