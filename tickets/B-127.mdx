**Brief:** the owner, 2026-10-27, on hardening against a compromised runner. The security model
(`docs/security-model.mdx`, hardening option 7, mitigation C) recommends it as the one mitigation
that works on every forge and visibility, the public `baton` repository included: a push alone
can no longer change what every runner executes or how work is scheduled.

**This is a change to Baton, not in Baton.** It narrows R-BTN-66 ("the rest stays in git, where
agents may improve it: course files…"): an agent's change to a control input becomes a proposal
an owner signs.

**Spec:** R-BTN-66, R-BTN-13 (SSHSIG), R-BTN-98, R-BTN-133 and R-BTN-134 (what a runner loads and
from where), R-BTN-12 (expedite), §7.1 (the board post); B-122 (goals); `docs/security-model.mdx`.
**Depends on:** none.

### What to build

1. **Control inputs**: `.baton/**` (`agent_command`, `agent_wrapper`, course sources, overrides,
   `rank.mjs`, `sync.mjs`), goal files, the `EXPEDITE` tag, and agent configuration (`.claude/**` (hooks, settings, skills, memory), every `CLAUDE.md` and `AGENTS.md`, and plugin manifests): a pushed session hook runs with the owner's credentials in their
   next interactive session (security model, OWASP ASI05). Baton cannot stop Claude Code
   loading an unsigned file, and a check kept in the same repository can be rewritten by the
   push it guards. For these paths the deliverable is a verifier the owner installs outside the
   repository (user-level settings, or the environment's setup script) that refuses to open a
   privileged session on a checkout whose agent configuration was last changed in a commit no
   owner key signed, plus the notice. **Not ticket `tier`**
   (decided, the owner, 2026-10-27). A tier routes work by quality, not privilege: a runner
   granted a higher tier also takes every lower one, so a changed tier sends a ticket to no
   runner whose credentials it could not already reach through its body (security model,
   reach 3). Revisit if tiers ever map to different credential sets; barred tags, Baton
   state, are the tool for keeping work off a runner.
2. **Signed by an owner.** A control input counts only at a commit carrying a valid SSH signature
   (git's `gpg.format ssh`, the SSHSIG format R-BTN-13 already verifies) by an owner key of that
   repository, for the commit that last changed it. Baton checks this in the sync (CLI side, with
   the owner keys from Baton) and records the signing key with the board post.
3. **Otherwise, the last signed version.** An unsigned change keeps the last signed version in
   force, and raises an `unsigned-control` notice naming the paths and commits. A repository with
   no signed version yet keeps today's behaviour until its owners opt in (`require_signed_control`,
   an R-BTN-66 setting, default off), so adoption is per repository.
4. **Runners load the same.** A runner loads `agent_command`, overrides and `rank.mjs` only from
   the signed commit the board post names, extending the verified tree it already checks
   (R-BTN-133, R-BTN-134).
5. **Goals from their first version.** If B-122 has not landed, goals are control inputs from the
   start; if it has, they join item 1.
6. **Tooling.** `baton owner sign` (or plain `git commit -S`) and a doc on configuring git with an
   owner key.
7. **Verifiable owner statements** (the owner, 2026-10-27; security model reach 3, option 10). A
   ticket's `**Brief:** the owner …` line, and any line quoting the owner as authority, counts as
   the owner's only in a commit signed by an owner key. The sync marks each ticket's brief
   `signed` or `unsigned` with its provenance (B-126). The standing CLAUDE.md rule tells agents
   that an unsigned owner quote is a claim, not the owner. This applies whether or not
   `require_signed_control` is on: it marks, it does not refuse.

### Tests

- A scenario: a brief added in an owner-signed commit is `signed`; the same text pushed unsigned
  by the worker is `unsigned`; editing a signed brief in an unsigned commit makes it `unsigned`.
- A scenario (the next free S-BTN number): with `require_signed_control` on, an unsigned change to
  `agent_command` leaves the runner running the signed one and raises the notice; an owner-signed
  change takes effect; a commit signed by a non-owner key, or a forged signature, counts as
  unsigned; an `EXPEDITE` added unsigned does not expedite.
