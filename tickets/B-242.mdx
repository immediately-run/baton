**What:** an unchanged dashboard poll should cost ~nothing.

- A `state_version` counter bumped inside `store.transaction` on any write; `/v1/ui/state` serves it as an ETag and answers 304 to a matching `If-None-Match`.
- Clock-dependent fields (alive, stalled, reap_at, the time windows) must still refresh: include a coarse time bucket in the ETag, or have the UI recompute them.
- The UI polls only while visible (`document.visibilityState`), and backs off when unchanged.

**Target:** an unchanged poll ≈ a handful of constant rows — the version row, the session
lookup, the request's upkeep — never the state.

**Why:** on 2026-11-14 production exceeded Cloudflare's free-tier Durable Objects limit of
5,000,000 `rows_read`/day at 21:41Z; every runner call returned 500 until the 00:00Z reset.
Measured on a production-sized local state (180 tickets, 600 claims, ~3k events) with
workerd's `SqlStorageCursor.rowsRead`: `GET /v1/ui/state` ≈ 14.4k rows per 10 s poll
(≈ 3·events + 2–5k), recommendations ≈ 3.7k, claim ≈ 3.8–4k, alarm ≈ 0.8–1.3k per minute,
`POST /v1/sync/board` 4–5k rows over ~2.5k statements. This ticket is one of B-235–B-243,
the owner's 2026-11-15 plan to bound what each read costs.

**Done when:** the named calls' rows_read, measured the same way in a test (cloudflare host),
is at or below the target, `EXPLAIN QUERY PLAN` shows the intended index where one is named,
and behaviour is unchanged (the existing scenarios pass).

### Trust

Input: the `If-None-Match` request header on `GET /v1/ui/state`. Anyone allowed to read the state may send it; it is only compared with the current version, and a mismatch serves the full state as today.

### Invariants

- The dashboard never shows stale clock-dependent state (alive, stalled, reap_at): the ETag carries a coarse time bucket.

## Status

_filed 2026-11-15._

_2026-11-15: the UI half — the dashboard polls only while visible and backs off from 10 to 60 seconds while the answers are unchanged (test/unit/dashboard-poll.test.ts). The `state_version` ETag waits on B-237's counter._

_2026-11-16: the remaining half serves V1's `GET /v1/ui/state`, which V2's cutover retires
(B-203, B-216). The same mechanism — an ETag from `state_version`, the caller and a clock bucket,
compared before the read runs — is B-205's for every V2 read; build it here as a helper B-205
reuses (`src/core/stateVersion.ts`), not as code private to `/v1/ui/state`._

_2026-11-18: the ETag half built — `stateEtag`/`ifNoneMatch` in `src/core/stateVersion.ts`
(SHA-256 over the version, the caller, the route and a one-minute clock bucket,
`CLOCK_BUCKET_MS`), served by `GET /v1/ui/state` after the principal and before the read runs
(S-BTN-235, test/integration/B-242.ui-state-etag.test.ts). Measured on the cloudflare host over
the production-sized state (180 tickets, 600 claims, ~3k events): the unchanged poll reads 3 rows
(the version row, the session lookup, the request's alarm upkeep) where the full read reads ~8.2k;
a write or a new bucket serves the full state again. §14's `/v1/ui/state` row and S-BTN-235 state
it; the history entry names the decisions (the bucket's minute, `*` matching nothing)._

_2026-11-18, round 2 (the first review): the bucket is five minutes, not one — §11.4 doubles a
screen's poll interval while unchanged to at most 60 s, and a bucket at the cap lands every
backed-off poll in a fresh bucket, a full read each time, so the bucket sits above the cap
(`CLOCK_BUCKET_MS`'s comment says it stays there). With it: the Target line above restated as one
criterion with S-BTN-235's handful; `If-None-Match: *` pinned by a test; the rows_read guard
pinned on both sides and the second poll bounded, not equated (a background alarm may read in one
window); §14's row names the route among the ETag's inputs; and the lease floor's citation
corrected — §8's R-BTN-9, not §6.8._
