**Brief:** continues B-3 (split 2026-10-20). The owner, 2026-10-16 and 2026-10-17, as specified by B-1 (baton#43).
**Spec:** `spec/BATON_SPEC.md` §5.1 R-BTN-134 (`schemas/<name>@<n>.json` in the course directory); §5.5 R-BTN-108 (the static refinement check `baton course test` runs), R-BTN-109's last bullet (every `entry` schema posted; every arriving leg's contract can meet it), R-BTN-111 (a course's signature, `spawns` with `lifetime`); §5.7 (the test kit); §14 (`GET …/stats`); §15 S-BTN-65's kit half, S-BTN-80's signatures.
**Depends on:** B-3, which ships the validator (`src/shared/schema.mjs`: `refinementGaps`, `checkSchemaSet`), the `std:` library and the schemas a sync posts.

### Requires

- none.

### What to build

1. **One schema reader at the new location.** `courseSchemas` in `src/defaults/cli.ts` reads `<course dir>/schemas/<name>@<n>.json` (R-BTN-134, R-BTN-108): `.baton/courses/<course>/schemas/` for a repository's own course, the source's directory for a sourced one (whichever of this ticket and B-43 lands second wires the sourced case). The sync's post and the kit use the same function; nothing reads `.baton/schemas/<course>/` afterwards.
2. **The kit's refinement report.** `baton course test` (`src/local/testCourse.ts`) runs `checkSchemaSet` over the course's schemas and, for each schema with an `x-baton-base`, `refinementGaps` against its base, and reports every gap with its keyword (S-BTN-65: a refinement dropping `head_sha` from `required` is reported, naming `required`).
3. **Entry against contracts.** The kit checks every `entry` schema is posted or `std:`, and that every leg arriving at a station declares outputs that can meet its requirements.
4. **Signatures and spawns (R-BTN-111).** The kit prints each course's signature (its `start` entry as input, each `end` station's entry as output); `GET /v1/repositories/{repository}/stats` carries it per course. A leg's `spawns: {course: <id> | [<id>…] | "*", provides, lifetime?}` is accepted in the course file (`lifetime` `parent` or `station`) and checked by the kit against each named course's input; `"*"` checks against every course the repository lists other than its own.

### Do not

- Check a call leg's completion stations against the called courses' end outputs: that is B-62's (R-BTN-165), on this ticket's signature code.
- List conditions in the signature: B-55 adds them (R-BTN-160).
- Act on `lifetime`: supersession is B-65's (R-BTN-168); this ticket only accepts and validates the field.

### Tests

- S-BTN-65's kit half and S-BTN-80's signatures half (both signatures printed; naming `abandoned` as not producing `result` is its completion case, B-62's), through `baton course test` on fixture courses whose schemas sit in `schemas/` of the course directory.
- A unit case in which the sync's post and the kit read the same schemas from the same path.
- `npm test`, `npm run typecheck` and `npm run check:spec` green.

### Exit criteria

- [ ] the scenarios above pass
- [ ] merged under the review gate
