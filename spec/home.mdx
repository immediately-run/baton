<Lede>Baton's specification, the repository's `spec/` folder. A rule has one home, in the file
of the section that owns it; tickets and the documentation link to that section rather than
restate it.</Lede>

## Files

- [The index](BATON_SPEC.md): each section's file, its subsections and the rule ids each
  defines, and every rule, scenario and gate id with its file. Generated by
  `npm run spec:index`; start here, then open only the section you need.
- The sections: `spec/BATON_SPEC/`, one file per section — [the front](BATON_SPEC/00-front.md)
  (status, companions, contents), sections 1 to 16, the load-bearing assumptions, the Decisions
  and the open questions. Joined in name order, they are the whole spec.
- [The history](BATON_SPEC_HISTORY.md): dated amendments, retired ids, the map from old section
  numbers and the decisions in full.
- [MCP OAuth](BATON_MCP_OAUTH_SPEC.md): the companion spec for MCP clients that cannot send a
  bearer.

How to read and amend the spec, and how a ticket cites it, is in the documentation wiki:
[reading and writing the spec](../docs/context/spec-writing.mdx).
