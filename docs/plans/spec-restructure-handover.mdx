## How the parts were written

- **Anchor-based splicing, never retyping.** A small Python helper (`once(old, new)` for an
  exact-once replacement, `region(start, end, new)` to replace between two unique line prefixes,
  `line(prefix, new)` for a table row, `after(prefix, new)` to insert one) applied every edit from
  a script, and the script aborted before saving on any anchor miss, so a miss never left a
  half-applied file. Large sections (§12.8, §7.8, §11.3) were rewritten as whole regions from new
  text; everything else by `once`. Print the exact lines before writing an anchor; wrapped lines
  and a phrase that appears twice are the usual misses. Grep the whole spec for a phrase you
  rename (`` `baton attest` `` survived part 3's first pass wrapped across a line).
- **The impact list** came from `npm run spec:impact -- <ids> --term <words>` with the terms
  backticked where a bare word matches prose ("baton run" matches "Baton runs"); each entry was
  read by hand and marked changed or still true in the PR body. Reviewers caught marks that were
  wrong in every part; expect the same.
- **Reviewers** were fresh agents given: the diffs against `origin/main` as patch files (spec;
  docs, README and the companion spec; tickets), the marked impact list in the PR body, the
  earlier rounds' reviews and history records, the tickets with the rulings, and a reading order;
  asked for anchored findings with severity (blocking, major, minor), the smallest fix, and a list
  of earlier findings confirmed closed. Round one's two reviewers were given different angles (the
  whole text; the guarantees, actors and the review's journeys); rounds two and three re-checked
  the previous round's fixes line by line before looking afresh.
- **Each round** became one commit ("review round N closed"), a history record under the part's
  entry (findings, then "Fixed:"), a PR-body section, and refreshed patch files for the next
  reviewer. The owner's answer became one more record and a note on each ticket it settled.
- **CI.** The cloud container fails five test files for lack of `ssh-keygen` and `ssh-agent`
  (`sign`, `cli`, `defaults-cli`, `runner-main`, `S-BTN-156.sync-key`); CI runs them green and
  nothing in the restructure touches them. GitHub is reached through the GitHub MCP tools; `gh` is
  for search only. The `test` job takes about five minutes a push; merge at the head it passed on.
