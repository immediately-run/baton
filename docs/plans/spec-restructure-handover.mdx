## How the parts were written

- **Anchor-based splicing, never retyping.** A small Python helper (`Spec.once(old, new)` for an
  exact-once replacement, `region(start, end, new)` to replace between two unique line prefixes,
  `line(prefix, new)` for a table row) applied every edit from a script, and the script aborted
  before saving on any anchor miss, so a miss never left a half-applied file. Large sections (§12.8,
  §7.8) were rewritten as whole regions from new text; everything else by `once`. Fetch the exact
  lines before writing an anchor; wrapped lines are the usual miss.
- **The impact list** came from `node scripts/spec-tools.mjs impact <ids> --term <words>`, then a
  script compared each unit's text at HEAD with the same unit on `origin/main` (by kind and id or
  label) and marked it changed or still true; the still-true marks were then read by hand, since
  reviewers caught several that were wrong.
- **Reviewers** were fresh agents given: the diffs against `origin/main` as patch files (spec; docs
  and scripts; tickets), the marked impact list, the earlier rounds' reviews, the history records,
  the tickets with the rulings, and a reading order; asked for anchored findings with severity
  (blocking, major, minor), the smallest fix, and a list of earlier findings confirmed closed. Round
  one's two reviewers were given different angles (the whole text; the guarantees, actors and
  journeys). Reviewers hit the account's rate limit twice; a stopped agent resumes from its saved
  state with a message, which the owner asked for by "Retry now".
- **CI.** The cloud container fails five test files for lack of `ssh-keygen` and `ssh-agent`
  (`sign`, `cli`, `defaults-cli`, `runner-main`, `S-BTN-156.sync-key`); CI runs them green. GitHub
  is reached through the GitHub MCP tools; `gh` is for search only.
- **Each round** became one commit ("review round N closed"), a history record under the part's
  entry (findings, then "Fixed:"), a PR-body section, and refreshed diffs for the next reviewer.
