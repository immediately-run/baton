## What #171 put in place (now on main)

- **R-BTN-193 — git is never a lock or a counter.** The owner: "I want the spec to be very clear
  that this is not how Baton is meant to be used. And it is merely a legacy to be phased out as
  soon as possible." The git-lock ticket commands and every next-free scan are named legacy where
  they are specified; nothing new may use git that way.
- **Stale-rule guard at claim** (R-BTN-74): `claim` refuses a ticket citing a rule a dated history
  entry's bold title (or its `Rules changed:` line) names after the ticket was filed or last
  re-read it, until `--rules-reread <exact ids>`. From 2026-11-04 every new history entry must name
  the rules it changes (`check:spec`).
- **Trust and Invariants** on every new ticket: `check.sections_since: 2026-11-03` and
  `check.sections_from_id: B-176` in `.baton/baton.json`; `tickets new` refuses an unfilled one
  (`--trust`, `--invariants`). Exempt: project pages, request tickets, handler (`handles:`) and call
  (`called_by:`) children.
- **Babysit skill:** merge main when it changes `spec/` or `src/migrations/`, at least daily; a
  ruling's PR rewrites or strikes the ticket clause it contradicts; new numbers are the next free at
  merge until B-176.
