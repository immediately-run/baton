<Lede>These are core's words. A word not on this page — pull request, review, model, provider —
belongs to a course, and Baton passes it through unread.</Lede>

**Repository.** A git repository registered with Baton. Its `.baton/` folder describes its
courses; its sync tells Baton where every ticket is.

**Home, code repository.** Every ticket lives in one repository, its **home**, which holds its
board, its courses and its owners. The repositories a ticket's work changes are its **code
repositories**: the home's owners list them in `code_repos`
(a home that lists none reaches them by name where its policy's `repos.unlisted` allows,
R-BTN-140), and they hold no tickets of their own. What a home covers is its owners' choice; Baton has no word for it.

**Ticket.** A unit of work, filed in its repository's ticket source. Baton knows its id, course
and requirements, never its body.

**Ticket source, reader, writer.** The repository's code that reads its tickets from their store
and posts them in each sync — the **reader** — and may write to that store: a new ticket, a
withdrawal — the **writer**. The default is the
markdown source, the store a git folder (R-BTN-74). A writer that Baton drives, and one that
shows a station's status or adds a note, is [proposed, not built](../../spec/proposals/tickets-and-sources.md).

**Launcher.** A process outside Baton that starts runner sessions for the work Baton lists as
waiting, handing each a ticket it may prefer; Baton reserves nothing for it (R-BTN-201).

**Course.** The state machine a ticket follows: **stations** it rests at and **legs** it runs
between them. Defined in `course.json`; changed by a commit.

**Station.** A place a ticket rests between legs (`filed`, `reviewed`, `merged`). An **end
station** finishes the ticket.

**Leg.** One edge of the course (`implement`, `review`, `merge`). A leg is **ready** or
**waiting** on something named.

**Fact leg.** A leg no runner runs, for a hand act done outside Baton (`merged-by-hand`): it
arrives when the sync attests its forge fact, along the edge the course file gives it (R-BTN-203).

**Reconcile leg, outside-work evidence.** **Outside-work evidence** (`std:evidence@1`; not a leg's
evidence, R-BTN-8) is a sign the sync found that a ticket may have moved outside Baton in a way no
fact leg takes (a PR merged early, a commit naming it). A course's
**reconcile leg** (`reconciles: {to: …}`) is the runner leg Baton queues to weigh it; its
outcomes are the station it left and each station of its `reconciles.to` (R-BTN-39, R-BTN-203).

**Path.** The legs a ticket has run and the stations they reached, as Baton recorded them: its
**course history**, which git never writes.

**Runner.** An agent session on a machine, identified by its key. It declares capabilities,
tags and the courses it can run.

**Capability.** A name a runner declares (`key:anthropic`, `capability:code-generation-llm`) and
a leg requires; Baton matches the two by name and derives nothing. What the keys and tools a
runner holds amount to is the runner's own statement, and which model and key a leg uses is the
course's choice, in its ranking code and instructions (R-BTN-174, §6.10).

**Executor, provides.** The module a CLI runner starts every leg and runs every call into
repository code through — `builtin` (child processes, the default), the home's own, or one pinned
on the host — chosen by the runner's host, never by a repository; it names the capabilities it
**provides**, which Baton matches by name like any declared capability and never judges
(R-BTN-107).

**Executor data.** The JSON object a course or home may give a leg for its executor, which Baton
passes through and never reads or stores (R-BTN-107).

**Capacity, seat.** A capability with a capacity has that many seats: a claim holds one, fixed when
its leg starts, for each such capability rule 4 matched for that leg (the ticket's requirements and
the leg's), and a claim past capacity is refused (R-BTN-178). Not the tenant's capacity envelope
(R-BTN-87), which no claim is refused by.

**Claim.** A runner's lease on one ticket. It runs one or more legs and ends **done**,
**suspended** at a station, or **released**.

**Lease, heartbeat, reap, fence.** A claim lives while its runner heartbeats. A silent runner
is **reaped** at its lease; a **fence** stops a revived runner from writing.

**Gate.** A rule Baton enforces for safety: one holder, capabilities and their capacity, grants, barred
tags. Everything else is **advice**.

**Tag, barred tag.** Short strings a course gives runners (`family:glm`). A leg can bar tags,
so some runners may not run it.

**Owner bar, required bar.** Limits a repository's owners set in Baton, which no push changes:
tags barred across courses, and bars every leg must carry. Under `cooperative` they, like every
position and count Baton owns, are a **coordination record** for runners that cooperate — a
pusher can re-file a ticket or edit its course and Baton does not try to notice; under
`protected` the forge and the trusted runners make the same state a boundary (R-BTN-66).

**Sync, snapshot, observation.** The repository's sync reads git and posts a **snapshot**.
Each carries an **observation** number, so a stale reading never overrules a newer one.

**Confirmation.** A completion counts once a later snapshot shows its evidence; its position
stands from the moment Baton records it.

**Adopt.** An owner's signed command that sets a ticket's position, for legs done outside Baton
([proposed, not built](../../spec/proposals/ticket-adopt.md)).

**Hand-off.** The document a suspended or released claim leaves for the next claimant.

**Hold, expedite.** An operator's overrides: stop a ticket being offered, or put it first.

**Block.** Why a leg cannot start — another ticket, a missing capability, an outside resource,
a backoff, an open condition.

**Ticket state.** The one word the dashboard draws a ticket under: `unconfirmed`, `running`,
`waiting-person`, `held`, `blocked`, `backing-off`, `suspended`, `ready` or `closed`, in that
precedence, every other that applies listed beside it as a reason; the Tickets screen's tabs —
Ready, Running, Blocked, Unconfirmed, Closed today — group them (§11.4).

**Person leg, question.** The one way a course waits on a person: a leg no runner runs, which
arrives when a person answers it with a `std:decision@1`. Its question — the id, the link, the
options — is what the ticket source posts for it, and Needs you (the debugger's list; the
dashboard's Conditions screen) holds it until it is answered or expires (R-BTN-116).

**Autonomous leg, interaction request.** An autonomous leg never asks for a person and fails
when it would need one. Any other leg may raise an **interaction request** (`interact`): a
condition carrying its run's session link, which a delivery runner sends to a person, who joins
the session in its harness's own UI; what they say there never passes through Baton
(R-BTN-195).

**Condition, leg event.** A condition is what a running leg tells Baton (it needs a person, it
hit an error, it has something to report), or what Baton raises of its own; a binding chooses the
course that handles a leg's condition (R-BTN-160, R-BTN-161). A **leg event** goes the other way: what Baton tells a running leg, that its ticket changed
(`ticket.changed`) or why it is being stopped (`release`). The leg alone handles it
(R-BTN-198; [proposed, not built](../../spec/proposals/conditions.md)).

**Cancel leg.** The ordinary leg a course names to undo its work outside git when a ticket is
cancelled; Baton alone queues it, and the ticket is withdrawn when it ends (R-BTN-168;
[proposed, not built](../../spec/proposals/conditions.md)).

**Administrator, owner, grant.** Administrators run the instance; each repository's owners
grant runner keys access to it.

**Action, registry.** Everything a credential can ask Baton to do is one action in one registry,
named `<noun>.<verb>`, with the principals that may call it; the API, the CLI, the dashboard and
MCP are generated from it and checked by one `authorize`. The CLI is `baton <noun> <verb>`, and
its help comes from the registry (R-BTN-127, R-BTN-129).

**Session.** A dashboard sign-in of an administrator's or owner's key, opened by its link or a
code its holder confirms, or by an email Cloudflare Access verified that `ACCESS_IDENTITIES`
binds to the key; one principal, carrying its key's role, an owner's reaching only the
repositories the key still owns (R-BTN-155).

**Screen.** One entity's page of the dashboard — sign in, pick a repository, one entity per
screen — named `root`, `tenant/<segment>` or `repository/<segment>[/{param}]`; what it draws is
that entity's REST reads, and its controls the registry actions whose `ui.view` names it
(R-BTN-129, §11.4).

**Overview strip.** The line every repository screen carries — running now · ready · needs you —
linking to Board, Tickets and Conditions, with the repository's mode where it is not cut over
(§11.4).

**Delegated key.** An MCP key: a bearer an owner's tool holds, acting as an owner of one
repository for the actions listed when it was minted. It may tighten (hold, bar, stop,
cancel) and undo its own tightenings, never loosen another's, route, adopt, resolve, answer a person's leg or
touch credentials or the policy (R-BTN-186, R-BTN-130). No delegated key can be minted yet:
MCP is [proposed, not built](../../spec/proposals/people-and-dashboard.md).

**Policy, preset, guarantee, floor.** A repository's policy is the one versioned document of
every rule about authority and trust — who lands what, who approves what, whose
attestations count — held in Baton, never in git. A preset (`cooperative`, `protected`,
`protected-hardware`) is a set of values an owner applies and then tunes. A guarantee is a named
condition over the policy; `floors` is the knob listing the guarantees Baton refuses to let any
change break (§12.8). Baton's own server is trusted: a compromised Baton is recovered, not
resisted, so nothing is signed for a verifier outside it.

**Run id.** The opaque id Baton mints for every leg run at its start (`r_` and a ULID), carried
by the history, the resume record and leg logs (R-BTN-63).

**Pusher.** A forge author whose words count — a verdict, a marker, an approval — because the
forge reports they can push the PR's base, or the owners list them in `pushers`. The one sense in
which a forge author is trusted; "trusted" otherwise names a leg property and the runner that runs such a leg (R-BTN-139, R-BTN-182).

**Attestation, reading.** Everything Baton is told about the world: a typed statement it records —
a review, a check run, a human's approval or answer, a runner's report of where its leg reached,
a fact the sync read from git, a deliverer's delivery (the outbox is proposed, not built), a provider's remaining funds — about a ticket
or commit, or about a resource instance (a **reading**). Attestations differ only in who wrote
them. A leg's course says which attestations it requires and whether a missing one blocks the leg
or only steers advice; the repository's policy says whose count.

**Command.** A request to change Baton's own state — a claim, an advance or end, a heartbeat, an
owner's or administrator's action. Baton accepts or refuses it by its gates; it is not evidence. A
command may carry an attestation: an advance moves the lease and reports where the leg reached.

**Outbox, deliverer** ([proposed, not built](../../spec/proposals/conditions.md)). Every git write, check run and ticket-store write Baton intends — a
ticket's withdrawal, a merge check, the status a ticket store shows — is an outbox entry; a deliverer, a runner whose host holds the credential the effect
needs, delivers it, and Baton confirms it by reading it
back. Baton itself holds no credential that writes git, posts a check or writes a ticket store; a workflow dispatch is
its own call, made with the App key it holds (R-BTN-94, R-BTN-171).

**Reply.** Baton's answer to a command or a read: a claim response, a recommendation, a policy
read. The fourth noun: Baton **learns** through attestations, **is asked** through commands,
**acts** through deliverers and its own dispatches, and **answers** in replies.

**Trusted runner.** A runner whose host holds the credential a leg marked `trusted` needs and
whose grant names that leg's capability; the merge runner is the first
([proposed, not built](../../spec/proposals/security.md)). Runners are trusted and legs are not
([BATON_SPEC §12.8](../../spec/BATON_SPEC/12-security.md#sec-12-8)).

**Protected path.** A path whose changes a trusted runner never merges alone: a computed floor
(`.baton/`, workflows, agent configuration, tickets) plus the owners' own; control paths land
only by a human ([proposed, not built](../../spec/proposals/security.md)).

**Human-only key.** A key used for nothing else and kept out of every agent's reach; only it
satisfies a human gate.
