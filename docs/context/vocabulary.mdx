<Lede>These are core's words. A word not on this page — pull request, review, model, provider —
belongs to a course, and Baton passes it through unread.</Lede>

**Repository.** A git repository registered with Baton. Its `.baton/` folder describes its
courses; its sync tells Baton where every ticket is.

**Home, code repository.** Every ticket lives in one repository, its **home**, which holds its
board, its courses and its owners. The repositories a ticket's work changes are its **code
repositories**: the home's owners list them in `code_repos`, and they hold no tickets of their
own. What a home covers is its owners' choice; Baton has no word for it.

**Ticket.** A unit of work, filed in git. Baton knows its id, course, tier and requirements,
never its body.

**Course.** The state machine a ticket follows: **stations** it rests at and **legs** it runs
between them. Defined in `course.json`; changed by a commit.

**Station.** A place a ticket rests between legs (`filed`, `reviewed`, `merged`). An **end
station** finishes the ticket.

**Leg.** One edge of the course (`implement`, `review`, `merge`). A leg is **ready** or
**waiting** on something named.

**Path.** The legs a ticket has run and the stations they reached, as Baton recorded them: its
**course history**, which git never writes.

**Worker.** An agent session on a machine, identified by its key. It declares capabilities,
a tier ceiling, tags and the courses it can run.

**Capability.** A name a worker declares (`key:anthropic`, `capability:code-generation-llm`) and
a leg requires; Baton matches the two by name and derives nothing. What the keys and tools a
worker holds amount to is the worker's own statement, and which model and key a leg uses is the
course's choice, in its ranking code and instructions (R-BTN-174, §6.10).

**Capacity, seat.** A capability with a capacity has that many seats: a claim holds one, fixed when
its leg starts, for each such capability rule 4 matched for that leg (the ticket's requirements and
the leg's), and a claim past capacity is refused (R-BTN-178). Not the tenant's capacity envelope
(R-BTN-87), which no claim is refused by.

**Claim.** A worker's lease on one ticket. It runs one or more legs and ends **done**,
**suspended** at a station, or **released**.

**Lease, heartbeat, reap, fence.** A claim lives while its worker heartbeats. A silent worker
is **reaped** at its lease; a **fence** stops a revived worker from writing.

**Gate.** A rule Baton enforces for safety: one holder, capabilities and their capacity, tier, grants, barred
tags. Everything else is **advice**.

**Tag, barred tag.** Short strings a course gives workers (`family:glm`). A leg can bar tags,
so some workers may not run it.

**Owner bar, required bar.** Limits a repository's owners set in Baton, which no push changes:
tags barred across courses, and bars every leg must carry. Under `cooperative` they, like every
position and count Baton owns, are a **coordination record** for workers that cooperate — a
pusher can re-file a ticket or edit its course and Baton does not try to notice; under
`protected` the forge and the trusted runners make the same state a boundary (R-BTN-66).

**Sync, snapshot, observation.** The repository's sync reads git and posts a **snapshot**.
Each carries an **observation** number, so a stale reading never overrules a newer one.

**Confirmation.** A completion counts once a later snapshot shows its evidence; its position
stands from the moment Baton records it.

**Adopt.** An owner's signed command that sets a ticket's position, for legs done outside Baton.

**Hand-off.** The document a suspended or released claim leaves for the next claimant.

**Hold, expedite.** An operator's overrides: stop a ticket being offered, or put it first.

**Block.** Why a leg cannot start — another ticket, a missing capability, an outside resource,
a backoff, an open condition.

**Person leg, question.** The one way a course waits on a person: a leg no runner runs, which
arrives when a person answers it with a `std:decision@1`. Its question — the id, the link, the
options — is what the ticket source posts for it, and Needs you lists it until it is answered or
expires (R-BTN-116).

**Cancel leg.** The ordinary leg a course names to undo its work outside git when a ticket is
cancelled; Baton alone queues it, and the ticket is withdrawn when it ends (R-BTN-168).

**Administrator, owner, grant.** Administrators run the instance; each repository's owners
grant worker keys access to it.

**Action, registry.** Everything a credential can ask Baton to do is one action in one registry,
named `<noun>.<verb>`, with the principals that may call it; the API, the CLI, the dashboard and
MCP are generated from it and checked by one `authorize`. The CLI is `baton <noun> <verb>`, and
its help comes from the registry (R-BTN-127, R-BTN-129).

**Session.** A dashboard sign-in, minted by an administrator's or owner's key through a code the
key holder confirms; one principal, carrying its key's role, an owner's reaching only the
repositories the key still owns (R-BTN-155).

**Delegated key.** An MCP key: a bearer an owner's tool holds, acting as an owner of one
repository for the actions listed when it was minted. It may tighten (hold, bar, stop,
cancel) and undo its own tightenings, never loosen another's, route, adopt, resolve, answer a person's leg or
touch credentials or the policy (R-BTN-186, R-BTN-130).

**Policy, preset, guarantee, floor.** A repository's policy is the one versioned document of
every rule about authority and trust — who lands on which refs, who approves what, whose
attestations count — held in Baton, never in git. A preset (`cooperative`, `protected`,
`protected-hardware`) is a set of values an owner applies and then tunes. A guarantee is a named
condition over the policy; `floors` is the knob listing the guarantees Baton refuses to let any
change break (§12.8). Baton's own server is trusted: a compromised Baton is recovered, not
resisted, so nothing is signed for a verifier outside it.

**Role, domain.** What a grant says about its runner's trust: its role (`runner`, or
`trusted-runner` for the legs marked `trusted`) and its domain, a label for the host or VM it runs
in, both set by the policy's `approvers.roles` approver. Two reviews count as independent when
their domains differ; Baton compares the labels and verifies nothing about them (R-BTN-180).

**Pusher.** A forge author whose words count — a verdict, a marker, an approval — because the
forge reports they can push the PR's base, or the owners list them in `pushers`. The one sense in
which a forge author is trusted; "trusted" otherwise names the runner role (R-BTN-139).

**Attestation, reading.** Everything Baton is told about the world: a typed statement it records —
a review, a check run, a human's approval or answer, a runner's report of where its leg reached,
a fact the sync read from git, a deliverer's delivery, a provider's remaining funds — about a ticket
or commit, or about a resource instance (a **reading**). Attestations differ only in who wrote
them. A leg's course says which attestations it requires and whether a missing one blocks the leg
or only steers advice; the repository's policy says whose count.

**Command.** A request to change Baton's own state — a claim, an advance or end, a heartbeat, an
owner's or administrator's action. Baton accepts or refuses it by its gates; it is not evidence. A
command may carry an attestation: an advance moves the lease and reports where the leg reached.

**Outbox, deliverer.** Every git write and check run Baton intends — a ticket's withdrawal, a
merge check — is an outbox entry; a deliverer, a runner whose host holds the credential the effect
needs and whose grant role the policy admits, delivers it, and Baton confirms it by reading it
back. Baton itself holds no credential that writes git or posts a check; a workflow dispatch is
its own call, made with the App key it holds (R-BTN-94, R-BTN-171).

**Reply.** Baton's answer to a command or a read: a claim response, a recommendation, a policy
read. The fourth noun: Baton **learns** through attestations, **is asked** through commands,
**acts** through deliverers and its own dispatches, and **answers** in replies.

**Trusted runner.** A runner that claims only legs marked `trusted`, runs no repository code, and
acts on attestations alone; the merge runner is the first.

**Protected path.** A path whose changes a trusted runner never merges alone: a computed floor
(`.baton/`, workflows, agent configuration, tickets) plus the owners' own; control paths land
only by a human.

**Control input.** A path or ticket field a push can use to steer what Baton or a privileged
session executes: the fixed list of R-BTN-194 (`.baton/`, goals, workflows, agent
configuration, dependency manifests) plus the owners' `control_paths`, and a live ticket's
`EXPEDITE`, `tier`, `requires` and `depends_on`. A change by a pusher outside the owners'
`pushers` is noticed — one event under Needs you — never gated.

**Human-only key.** A key used for nothing else and kept out of every agent's reach; only it
satisfies a human gate.
