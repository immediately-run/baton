think the code base has been updated to reflect the new, simpler specs. Please perform a
thorough review of how the current code base implements the spec. Identify areas where the code

Read at `main` `5758cdb` (2026-11-24). Eight reviewers each read one span of
`spec/BATON_SPEC/` whole and the code that implements it; one of them rebuilt the schema by
applying every migration to an in-memory SQLite and diffed it against §13 column by column. A
mechanical cross-reference of every `R-BTN-n` the code cites against the spec index and the
history's *Retired requirements* table was run beside them. The eight area reports, with every
finding at `file:line`, are the [appendix pages](code-vs-spec-2026-11-24/index.md); this page
is their merge. Findings marked **verified** were re-checked by hand against both the rule text
and the code; the rest are the reviewers' claims, each of which the reviewer marked confirmed or
likely.

All 220 open tickets (`available`, `in-progress`, `in-review`, `deferred`; no ticket carries a
literal `waiting` status) were read for overlap. Nothing here is new work where an open ticket
already owns the change: such findings are listed as *covered*, and where the ticket's plan is
wrong or incomplete, as a *correction to* that ticket.

## Summary

PR #299 removed text, not code. Of the fifteen follow-up tickets it filed (B-288 to B-302), one
is done (B-292, in Fieldhouse); the other fourteen are `available`, as are B-322 (tiers, retired
2026-11-23) and B-263 (signed control, retired 2026-11-19). So almost everything the spec retired
since 2026-11-19 is still built and still served. That part is expected and ticketed.

What the tickets do not cover falls in six groups:

1. **Five security-relevant gaps** no ticket names (*Security first*, below).
2. **Retired concepts outside the removal tickets' file lists**: about thirty places, mostly
   reads, stats, the dashboard and compatibility shims whose reason has gone.
3. **Complexity with no owner**: second implementations of one rule (the candidate query, rule
   4, the schema validator, the conditions store, the repository read), dead code paths and
   one-valued wire fields.
4. **Anchors.** About 100 citations of retired ids; 174 places where a `§n` beside an id
   disagrees with the section that id lives in; 177 citations of sections that no longer exist;
   about twenty ids cited for something the rule does not say; seven built rules no code cites;
   and missing citations on load-bearing functions in every area.
5. **Corrections to open tickets**: B-288's plan, if followed, deletes the live sync
   dispatcher; B-302's would mark §4 built while R-BTN-203 is not; B-285 is `done` with its
   courier removal undone; fourteen open tickets still prescribe designs the simplification
   removed.
6. **The spec stating as built what is not**, in sections PR #299 did not reach.
